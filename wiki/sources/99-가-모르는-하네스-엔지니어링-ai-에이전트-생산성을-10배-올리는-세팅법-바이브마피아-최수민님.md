## Summary

이 글의 핵심은 [[HarnessEngineering]]을 통해 [[AI에이전트]]가 계획된 기준에 따라 자율 개발과 코드 리뷰까지 수행하게 하고, 사람은 [[기획 구체화]]와 암묵지 전달에 집중하는 방식으로 생산성을 크게 높이는 것이다. 

특히 개발 초기 단계가 불명확한 상태일수록 오토메이션 오탐이 커지므로, 구현 가능한 만큼만 잘 정제된 문서와 구조화된 스크립트를 갖추는 것이 중요하다는 점을 강조한다. 또한 [[ClaudeCode]] 연동 기반의 오케스트레이션, 태스크-페이즈 분해, 멀티세션 실행 구조를 제안하며 PR 생성·리뷰 자동화를 통해 반복 작업 소모를 줄인다.

## Key Claims

- [[HarnessEngineering]]은 [[AI에이전트]]의 자율성을 높이되, 판단 기준은 사람이 정한 문서 기반 규칙으로 고정해 오작동 위험을 줄이는 시스템 설계 방식이다.
- [[기획 구체화]]가 충분하지 않으면 구현 단계에서 의도와 다른 결과가 나오기 쉬워서, AI 활용 이전에 핵심 요구사항을 구체화하는 과정이 생산성의 첫 단추다.
- [[SubAgent]], [[Phase]], [[Task]] 단위로 작업을 쪼개고, 각 페이즈를 독립 실행 가능하게 만들면 메인 세션의 컨텍스트 오염을 줄이면서 반복 실행 신뢰도를 높일 수 있다.
- 문서 기반 스크립트(오케스트레이션/스킬)는 회복(retry), 작업 재시작, 상태 추적을 내장해 장애 대응 속도와 일관성을 높인다.
- 하네스형 워크플로우에서 구현 완료 직후 바로 코드 작성 자체보다 [[docs_diff]] 생성이 우선되어야 하며, 변경 줄 단위 추적이 구현 정합성의 기준점이 된다.
- [[PR]] 자동 생성/자동 리뷰 루프는 작업 완료 속도를 높이지만, 최종적으로는 사람이 판단해야 할 항목(왜 필요한지, 방향성 적절성, 비정형 의도)을 별도로 남겨야 한다.
- [[CodeRabbit]] 같은 리뷰 도구를 결합해 AI가 작성한 코드 개선 포인트를 반영하되, 인적 판단이 필요한 사안은 사람이 확인하는 하이브리드 리뷰 체계를 유지해야 한다.
- 제품화 단계에서 특히 중요한 것은 컨텍스트 리소스(토큰/상태) 절약이며, 메인 에이전트는 상위 전략과 사용자 의도 수렴에만 집중하고 반복 구현은 하위 세션으로 분리해야 한다.
- [[RAG]]와 유사한 방식으로, 과거 설계 근거/ADR을 축약해 요약한 평가기준을 작업별로 제공하면 코드 리뷰 정확도와 일관성이 높아진다.
- [[AX]] 전환을 위해서는 복잡한 RAG보다도, 조직 데이터의 구조화(파일시스템·문서화·작업 이력)와 에이전트 실행 문맥 정렬이 우선 순위가 높다.

## Key Quotes

> "사람이 구체화한 기획을 AI가 틀림없이 구현하도록 돕는 것이 하네스의 핵심이다." 

> "구현은 AI가 잘해도, 무엇을 만들지의 결정과 암묵지는 사람의 역할이다."

> "PR은 풀 자동화에서 필수는 아니지만 인간 검토자가 가장 잘 보는 보고·대화 채널이 된다."

## Connections

- [[HarnessEngineering]] — 소스의 핵심 방법론. 설계-구현-리뷰 자동화 전체를 관통한다.
- [[AI에이전트]] — 하네스의 대상. 특히 구현·검증·리뷰 단계의 반복 자동화.
- [[ClaudeCode]] — 오케스트레이션 호출이 쉬운 협업 환경으로 언급됨.
- [[Task]] / [[TaskPhase]] — 작업 분해 단위. 메인-서브 세션 협업의 핵심 구조.
- [[docs_diff]] — 변경 추적의 정합성 확보를 위한 문서 기반 증거 자료.
- [[PR]] / [[CodeReview]] — 구현 완료 후 검증, 보고, 승인 흐름을 잇는 최종 인터페이스.
- [[CodeRabbit]] — 리뷰 보조 에이전트로의 활용 사례.
- [[ADR]] / [[설계 의도 문서]] — 설계 기준을 압축해 하위 세션 품질을 높이는 재사용 자산.
- [[RAG]] — 문맥 검색 기반 대안으로 언급되어, [[문서 기반 에이전트]] 접근과 비교되는 방식으로 해석됨.
- [[AX]] — 기업 단위 자동화 전환 시, 데이터 정비와 인간 의도 전달의 중요성이 강조되는 조직 전략.

## Contradictions

- 기존 [[VibeCoding]]류 글에서 강조된 "개발 자동화 자체가 목적"인 관점과 다르게, 이 소스는 "기획 구체화와 문맥 정합성 확보"를 선행 조건으로 두어 하네스의 품질 기준을 더 엄격히 설정한다. 이 차이는 상충이 아니라 우선순위 정렬 차이로 본다.
