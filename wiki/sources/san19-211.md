## Summary
이 문서는 [[ONNX]]를 프레임워크 간 모델 상호운용 표준으로 정의하고, [[ONNXRuntime]]가 이를 고성능 실행으로 연결하는 방식의 핵심 구조를 설명한다. 모델은 표준화된 그래프 표현(연산자·타입·메타데이터 기반)으로 정리되고, [[ONNXRuntime]]에서 그래프 최적화와 실행 공급자 기반 파티셔닝을 통해 하드웨어 가속기별로 분할 실행된다.

또한 [[Microsoft]]가 [[ONNX]] 생태계를 실제 운영 서비스(Bing, Office 365, AzureML 등)에서 대규모 트래픽으로 사용하는 운영 사례와 성능 개선 수치를 제시하며, [[ONNXRuntime]]의 경량 학습/추론 API(C#, Python)를 통해 추론 및 재학습 루프까지 포함하는 실용적 플랫폼임을 보인다.

## Key Claims
- [[ONNX]]는 [[PyTorch]], [[TensorFlow]], [[Caffe2]], [[Keras]] 등에서 학습된 모델을 상호 교환 가능한 개방형 형식으로 통합하는 ML 표준이다.
- [[ONNX]] 모델은 연산자 노드 기반의 비순환 계산 그래프(acyclic dataflow graph)로 구성되며, 버전 정보·메타데이터·입출력·노드 목록을 포함한다.
- [[ONNXRuntime]]은 그래프 최적화(드롭아웃 제거, 노드 융합, 상수 폴딩), 그래프 파티셔닝(실행 공급자별 분할), 실행 공급자 인터페이스를 통해 성능을 개선한다.
- 그래프 파티셔닝은 `GraphPartitioner`가 노드별로 적합한 실행 공급자(CPU, CUDA, TensorRT, nGraph, etc.)를 탐욕적(greedy) 방식으로 할당해 [[HeterogeneousInference]] 성능을 높인다.
- [[ONNX Runtime API]]는 Python/ C#에서 간단한 `InferenceSession` 사용 흐름을 제공하며, 추론뿐 아니라 경량 학습 런타임(약 3MB, ONNX Runtime 합쳐 약 5MB)까지 지원한다.
- [[Microsoft]]의 실서비스 적용에서는 Bing QnA 모델에서 최대 2.8배, Semantic Search 이미지 임베딩에서 1.8배 성능 향상이 보고되었다.
- ONNX 모델 획득 경로는 기존 모델 변환, [[ONNXZoo]], [[Azure Custom Vision]], 그리고 ONNX 학습 런타임 기반 직접 학습이 존재한다.

## Key Quotes
> "ONNX는 AI 모델의 상호 운용성을 높이는 개방형 표준 형식이다."

> "ONNX Runtime은 그래프 최적화, 그래프 파티셔닝, 실행 공급자(Execution Provider)를 통해 모델을 효율적으로 실행한다."

> "Graph Partitioner는 변경 가능한 그래프 노드를 각 실행 공급자의 기능에 따라 할당한다."

> "사용자는 선호 실행 공급자 목록을 지정하고, ONNX Runtime은 순서대로 각 노드의 실행 가능성을 검사해 할당한다."
