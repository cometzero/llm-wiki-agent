## 1. ONNX(Open Neural Network Exchange) 소개 [2]

ONNX는 다양한 AI 프레임워크에서 학습된 모델을 표준화된 형식으로 교환하고 여러 하드웨어에서 고성능으로 실행할 수 있도록 돕는 개방형 ML 모델 형식이다.

### 1.1. ONNX란 무엇인가? [6]

ONNX는 AI 모델의 상호 운용성을 높이는 개방형 표준 형식이다. [6]

개방형 ML 모델 형식으로, 다양한 AI 프레임워크(PyTorch, TensorFlow, Chainer, Caffe2 등)에서 학습된 모델을 표준화된 형태로 교환할 수 있다. [8]

다양한 하드웨어(CPU, GPU, FPGA, NPU 등)에서 모델을 효율적으로 실행할 수 있도록 지원한다. [8]

ONNX는 주요 기술 기업들의 협력을 통해 개발되고 있다. [15]

Microsoft, Facebook, Amazon, IBM, Intel, NVIDIA 등 다수의 글로벌 기업들이 ONNX 프로젝트에 참여하고 있다. [15]

이는 ONNX가 AI 생태계 전반에 걸쳐 폭넓게 채택되고 있음을 보여준다. [15]

ONNX의 핵심 설계 원칙은 유연성, 표준화, 효율성이다. [19]

유연성: 전통적인 딥러닝(DNN) 및 머신러닝(ML) 모델을 지원하며, 빠르게 발전하는 기술에 맞춰 유연하게 확장할 수 있다. [19]

표준화: 실제 사용 사례를 기반으로 잘 정의된 연산자 목록을 표준화하여 일관성을 유지한다. [20]

효율성: 모델의 직렬화 및 교차 플랫폼 표현을 위한 간결하고 효율적인 형식을 제공한다. [19]

### 1.2. ONNX 파일 구조 및 연산자 [22]

ONNX 파일은 모델의 버전 정보, 메타데이터, 그래프 구조를 포함한다. [22]

ONNX 파일은 버전 정보, 메타데이터, 입력 및 출력, 노드 목록, 그래프 이름 등으로 구성된다. [26]

모델의 계산 흐름은 비순환 데이터 흐름 계산 그래프(Acyclic dataflow computation graph) 형태로 표현된다. [26]

각 노드는 연산자(Operator)와 해당 연산자의 매개변수(Parameters)를 정의한다. [28]

ONNX는 다양한 데이터 타입과 연산자를 지원하여 복잡한 모델을 표현할 수 있다. [31]

데이터 타입: 정수(int8, int16, int32, int64), 부동 소수점(float16, float, double), 불리언(bool), 문자열(string) 등 다양한 텐서(Tensor) 데이터 타입을 지원한다. [31]

비텐서 타입: 시퀀스(Sequence)와 맵(Map) 같은 비텐서 타입도 지원한다. [33]

연산자: Relu와 같은 기본적인 연산자는 입력 텐서를 받아 요소별로 활성화 함수를 적용하여 출력 텐서를 생성한다. [36]

현재 ai.onnx 도메인에 124개, ai.onnx.ml 도메인에 18개의 연산자가 정의되어 있다. [38]

이미지 분류, 추천 시스템, 자연어 처리 등 다양한 AI 분야를 지원한다. [39]

ONNX는 기존 연산자를 조합하여 복합 함수를 만들 수 있다. [44]

복합 함수(Compound Functions)는 기존의 기본 연산자들을 조합하여 구축할 수 있다. [44]

런타임/프레임워크/도구는 이러한 복합 함수에 대해 최적화된 구현을 제공하거나, 기본 연산자를 사용하여 폴백(fallback)할 수 있다. [44]

## 2. Microsoft의 ONNX 활용 사례 및 ONNX Runtime [46]

Microsoft는 ONNX를 통해 다양한 AI 모델을 효율적으로 배포하고 성능을 최적화하고 있다.

### 2.1. Microsoft의 ONNX 활용 [50]

Microsoft는 내부 및 외부 고객을 위해 ONNX를 광범위하게 사용한다. [50]

Microsoft의 다양한 팀과 고객들은 여러 프레임워크(PyTorch, Keras, Caffe 등)로 학습된 모델을 사용한다. [50]

이러한 모델들은 CPU, GPU, FPGA 등 다양한 하드웨어에 배포된다. [51]

Microsoft의 주요 제품 및 플랫폼에서 ONNX가 활용된다. [52]

제품: Bing, Office 365, ML.NET, Microsoft Cognitive Services, AzureML, WinML, Skype, Power BI 등. [52]

규모: 매일 수십억 건의 요청을 처리하며, ONNX Runtime을 통해 성능 향상을 경험하고 있다. [53]

ONNX Runtime은 Microsoft 서비스에서 상당한 성능 향상을 제공한다. [57]

Bing QnA 및 Segment QnA: 답변 생성 모델에서 ONNX Runtime을 사용하여 최대 2.8배의 성능 향상을 달성했다. [57]

Bing Semantic Search Image Embedding Model: 이미지 콘텐츠 이해를 위한 임베딩 모델에서 ONNX Runtime을 사용하여 1.8배의 성능 향상을 보였다. [62]

Figure 1: Bing QnA 및 Segment QnA 모델의 ONNX Runtime 성능 향상 [57]

Figure 2: Bing Semantic Search Image Embedding Model의 ONNX Runtime 성능 향상 [62]

### 2.2. ONNX Runtime의 특징 [71]

ONNX Runtime은 고성능, 교차 플랫폼, 경량 및 모듈식, 확장성을 특징으로 한다. [71]

고성능: ONNX 모델을 위한 고성능 런타임이다. [74]

교차 플랫폼: Windows, Mac, Linux 등 다양한 운영체제와 CPU, GPU(Nvidia, Intel), 엣지 디바이스(ARM) 등 여러 하드웨어에서 작동한다. [75]

경량 및 모듈식: 가볍고 모듈화된 구조를 가지고 있다. [71]

확장성: 플러그인 가능한 아키텍처를 통해 하드웨어 가속기 및 최적화 도구를 쉽게 추가할 수 있다. [74]

ONNX-ML 사양(v1.2 ~ v1.5)을 지원하며, C, C#, Python API를 제공한다. [74]

## 3. ONNX Runtime 아키텍처 및 기능 [76]

ONNX Runtime은 그래프 최적화, 파티셔닝, 실행 공급자 등을 통해 AI 모델의 효율적인 실행을 지원한다.

### 3.1. ONNX Runtime 아키텍처 [76]

ONNX Runtime은 그래프 최적화, 그래프 파티셔닝, 실행 공급자(Execution Provider)를 통해 모델을 효율적으로 실행한다. [76]

그래프 최적화: 노드 제거(dropout, identity 등), 노드 융합, 상수 폴딩(constant folding) 등을 통해 그래프를 최적화한다. [76]

그래프 파티셔닝: 그래프를 실행 공급자의 기능에 따라 여러 서브그래프로 분할한다. [77]

실행 공급자: CPU, CUDA, nGraph, TensorRT 등 다양한 하드웨어 가속기를 위한 플러그인 인터페이스를 제공한다. [79]

Figure 3: ONNX Runtime 아키텍처 [76]

ONNX Runtime은 모델의 인메모리 객체 매핑과 읽기/쓰기 API를 제공한다. [81]

IR(Intermediate Representation): ONNX 모델 파일 형식을 인메모리 객체로 매핑하여 그래프를 읽고 쓸 수 있는 API를 제공한다. [81]

GraphViewer: 그래프의 읽기 전용 뷰를 제공하여 계산 그래프를 검사하는 데 사용된다. [82]

IExecutionProvider: 하드웨어 가속기와의 인터페이스를 정의한다. [83]

### 3.2. 그래프 최적화 및 파티셔닝 [85]

그래프 최적화는 특정 패턴을 찾아 서브그래프를 재작성하고 규칙을 적용한다. [85]

GraphTransformer: 특정 패턴을 가진 노드를 찾아 서브그래프를 재작성하고 규칙을 적용하는 인터페이스이다. [85]

RewriteRule: 그래프 변환을 적용하는 인터페이스이다. [87]

최적화 레벨:

레벨 0: 그래프 파티셔닝 후 적용되는 변환(예: 캐스트 삽입, 메모리 복사 삽입). [88]

레벨 1: 특정 실행 공급자에 국한되지 않는 일반적인 변환(예: 드롭아웃 제거). [89]

레벨 2: 실행 공급자별 변환. [89]

Figure 4: ONNX Runtime 그래프 최적화 [85]

그래프 파티셔닝은 그래프 노드를 최적의 실행 공급자에 할당하여 이기종 환경에서 성능을 극대화한다. [91]

GraphPartitioner: 변경 가능한 그래프 노드를 각 실행 공급자의 기능에 따라 할당한다. [91]

"탐욕적(greedy)" 노드 할당 메커니즘을 사용한다. [92]

사용자는 선호하는 실행 공급자 목록을 지정할 수 있으며, ONNX Runtime은 목록 순서대로 각 공급자의 노드 실행 가능 여부를 확인하고 할당한다. [92]

향후 계획: 프로파일링 기반 파티셔닝 및 ML 기반 파티셔닝을 도입할 예정이다. [93]

Figure 5: ONNX Runtime 그래프 파티셔닝 [91]

### 3.3. 실행 공급자 및 API 예시 [96]

실행 공급자는 하드웨어 가속기와의 인터페이스를 제공하며, 두 가지 유형으로 나뉜다. [96]

커널 기반 실행 공급자: ONNX 연산자의 실행을 정의하며, CPUExecutionProvider, CudaExecutionProvider, MKLDNNExecutionProvider 등이 있다. [96]

런타임 기반 실행 공급자: ONNX 연산자 단위가 아닌 전체 또는 부분 그래프 실행을 담당하며, TensorRTExecutionProvider, nGraphExecutionProvider 등이 있다. [99]

Figure 6: ONNX Runtime 실행 공급자 [96]

ONNX Runtime은 Python 및 C# 등 다양한 언어로 간단한 API를 제공한다. [102]

Python에서는 onnxruntime.InferenceSession을 사용하여 모델을 로드하고 추론을 실행할 수 있다. [102]

C#에서도 유사한 방식으로 InferenceSession을 통해 모델을 로드하고 실행한다. [102]

Figure 7: ONNX Runtime API 예시 [102]

### 3.4. 코드 생성 및 학습 기능 [105]

ONNX Runtime은 TVM/Halide 기반의 코드 생성 기능을 활용하여 성능을 최적화한다. [105]

NupharEP와 FpgaEP는 TVM/Halide를 기반으로 코드 생성 기능을 사용한다. [105]

ONNX 그래프를 커널 코드로 변환하고, 컴파일러를 통해 최적화된 코드를 생성한다. [106]

Figure 8: ONNX Runtime 코드 생성 [105]

ONNX Runtime은 경량 학습 런타임을 제공하여 다양한 프레임워크와 하드웨어를 지원한다. [108]

ONNX Training Runtime은 빠르고 경량화된 학습 런타임으로, 추론과 학습 기능을 모두 제공한다. [108]

학습 런타임의 바이너리 크기는 약 3MB이며, ONNX RT와 합쳐 약 5MB이다. [109]

강화 학습, 재학습, 양자화된 추론 등 다양한 학습 시나리오를 지원한다. [108]

TensorFlow, PyTorch 등 여러 프론트엔드 학습 프레임워크와 GPU 등 다양한 가속기 백엔드를 지원하는 통합 소프트웨어 스택을 제공한다. [109]

Figure 9: ONNX Runtime 학습 기능 [108]

## 4. ONNX 모델 생성 방법 [120]

ONNX 모델은 기존 모델 변환, ONNX Zoo 활용, Azure Custom Vision 서비스 이용 등 다양한 방법으로 얻을 수 있다.

### 4.1. ONNX 모델을 얻는 4가지 방법 [124]

ONNX 모델을 얻는 주요 방법은 기존 모델 변환, ONNX Zoo 활용, Azure Custom Vision 서비스 이용, 직접 학습이다. [124]

기존 모델 변환: TensorFlow, Keras, PyTorch 등 다른 프레임워크로 학습된 모델을 ONNX 형식으로 변환한다. [126]

ONNX Zoo: 미리 학습된 ONNX 모델 컬렉션을 활용한다. [124]

Azure Custom Vision 서비스: 클라우드 기반의 AI 서비스에서 ONNX 모델을 생성하고 다운로드한다. [124]

직접 학습: ONNX Runtime의 학습 기능을 사용하여 모델을 학습하고 ONNX 형식으로 저장한다. [126]

Figure 10: ONNX 모델을 얻는 4가지 방법 [124]

### 4.2. ONNX Zoo 및 Azure Custom Vision 서비스 [128]

ONNX Zoo는 이미지 분류 모델을 포함한 다양한 사전 학습된 ONNX 모델을 제공한다. [128]

이미지 분류 모델: 입력 이미지를 받아 미리 정의된 클래스 중 하나로 객체를 분류하는 모델 컬렉션이다. [128]

예시 모델: MobileNet, ResNet(18, 34, 50, 101, 152), VGG, SqueezeNet 등 다양한 CNN 모델을 제공한다. [129]

각 모델은 설명, 참조 논문, ONNX Opset 버전, 파일 크기, Top-1 및 Top-5 정확도 등의 정보를 포함한다. [129]

Figure 11: ONNX Zoo 이미지 분류 모델 목록 [128]

Azure Custom Vision 서비스는 사용자 정의 이미지 분류 모델을 ONNX 형식으로 쉽게 생성하고 내보낼 수 있다. [134]

사용자는 이미지를 업로드하고 태그를 추가하여 모델을 학습시킨다. [134]

학습된 모델의 성능을 확인한 후, ONNX 형식으로 다운로드할 수 있다. [134]

### 4.3. 기존 모델을 ONNX로 변환하는 방법 [137]

다양한 AI 프레임워크의 모델을 ONNX로 변환할 수 있는 도구가 제공된다. [137]

TensorFlow: onnx/tensorflow-onnx (tf2onnx) [137]

Keras: onnx/keras-onnx [137]

Scikit-learn, LightGBM, LibSVM, XGBoost, SparkML, CoreML: onnx/onnxmltools [137]

PyTorch, CNTK: 네이티브 ONNX 내보내기 기능을 제공한다. [138]

각 프레임워크별로 모델을 ONNX로 변환하는 예시 코드가 제공된다. [140]

TensorFlow: tf2onnx 명령어를 사용하여 .pb 파일을 ONNX로 변환한다. [140]

Keras: keras2onnx.convert_keras 함수를 사용하여 Keras 모델을 ONNX로 변환한다. [141]

Chainer: chainer.serializers.save_onnx 함수를 사용하여 Chainer 모델을 ONNX로 저장한다. [143]

PyTorch: torch.onnx.export 함수를 사용하여 PyTorch 모델을 ONNX로 내보낸다. [144]
