
클로드(claude)의 **에이전트**** 역량**을 극대화하는 Skills와 MCP(Model Context Protocol)의 관계를 명쾌하게 해설합니다. MCP가 외부 시스템에 대한 **연결성****(Connectivity)**을 제공하여 클로드에게 도구 사용 접근권을 부여한다면, Skills는 이 도구들을 이용해 팀의 고유한 **업무 흐름(Workflow Logic)**과 도메인 전문성을 가르치는 역할을 합니다. 이 콘텐츠를 통해 독자들은 단순한 데이터 접근을 넘어, 금융 분석이나 회의 준비와 같은 복잡한 다단계 프로세스에서 **일관되고 신뢰할 수 있는 결과물**을 도출하는 최적의 AI 에이전트 구축 방법을 실질적인 예시를 통해 배울 수 있습니다.
## 1. 클로드 역량 확대를 위한 Skills와 MCP 서버의 관계 
1. **배경 및 주요 질문**:
  - Anthropic이 Skills를 출시한 이후, 고객들은 Skills와 MCP(Model Context Protocol)가 어떻게 함께 작동하는지, 그리고 언제 하나를 다른 것 대신 사용해야 하는지에 대해 질문하고 있다. 

2. **Skills****와 MCP의 역할 정의**:
  - **MCP(Model Context Protocol)**: 클로드(Claude)를 외부 시스템(타사 도구)에 연결하는 역할을 담당한다. 
  - **Skills**: 클로드에게 연결된 도구들을 <em>잘</em> 사용하는 방법을 가르친다. 

3. **결합의 이점**:
  - Skills와 MCP를 결합하면, 지속적인 수정이 필요한 일반적인 프로세스가 아닌, **팀의 고유한 업무 흐름(Workflow)**을 따르는 에이전트를 구축할 수 있다.

## 2. Skills와 MCP에 대한 이해: 비유 및 구체적 정의 
1. **하드웨어 상점 비유**:
  - **문제 상황**: 고장 난 캐비닛을 수리하려고 하드웨어 상점에 갔을 때, 필요한 모든 것(목재 접착제, 클램프, 경첩)이 있지만, 무엇을 사서 어떻게 사용해야 하는지는 또 다른 문제이다. 
  - **MCP의 역할**: 상점의 통로에 접근할 수 있는 것과 같다. 
  - **Skills****의 역할**: 직원의 전문 지식과 같다. 
  - **결론**: 세상의 모든 재고가 있더라도 필요한 물품이 무엇인지, 사용하는 방법을 모르면 소용이 없다. Skill은 수리 과정을 안내하고, 올바른 용품을 알려주며, 적절한 기술을 시연해 주는 **도움이 되는 직원**과 같다. 

2. **구체적인 기술적 정의**:
  - **MCP 서버**: 클로드에게 외부 시스템, 서비스, 플랫폼에 대한 접근권을 부여한다. 
  - **Skills**: 클로드가 해당 접근권을 효과적으로 사용하기 위해 필요한 맥락(Context)을 제공하며, 접근권을 얻은 후 <em>무엇을 해야 하는지</em> 가르친다. 
  - **맥락의 중요성**: Skill이 제공하는 맥락이 없으면 클로드는 사용자가 원하는 바를 추측해야 하지만, Skill이 있으면 클로드는 **팀의 플레이북(Playbook)**을 따를 수 있다. 


## 3. Skills와 MCP가 상호 보완적인 이유 


### 3.1. 역할 분리 및 아키텍처 구성 가능성 
1. **MCP의 역할: ****연결성****(Connectivity) 담당**:
  - MCP는 GitHub, Salesforce, Notion, 또는 자체 내부 API 등 외부 시스템에 **안전하고 ****표준화****된 접근**을 처리한다. 
  - MCP 서버는 클로드에게 도구 및 데이터에 도달할 수 있는 능력을 부여한다. 

2. **Skills****의 역할: ****전문성****(Expertise) 담당**:
  - Skill은 도메인 지식과 워크플로 논리(Workflow Logic)를 처리하여, 도구 접근(Raw Tool Access)을 신뢰할 수 있는 결과로 바꾼다. 
  - Skill은 다음을 포함한 **판단 기준**을 제공한다. 
  - 언제 CRM에 쿼리해야 하는지
  - 결과에서 무엇을 찾아야 하는지
  - 출력을 어떻게 형식화해야 하는지
  - 어떤 예외 상황(Edge Cases)에 다른 처리가 필요한지

3. **구성 가능성(Composability)**:
  - 이러한 역할 분리는 아키텍처를 구성 가능하게 유지한다. 
  - **유연한 연결**:
  - 하나의 Skill이 여러 MCP 서버를 조정(Orchestrate)할 수 있다. 
  - 하나의 MCP 서버는 수십 개의 다른 Skill을 지원할 수 있다. 
  - 새로운 연결이 추가되면 기존 Skill이 이를 통합할 수 있으며, Skill을 개선하면 모든 연결된 도구에서 작동한다. 


### 3.2. 결합을 통한 결과 개선 효과 
1. **명확한 발견 (Clear Discovery)**: 클로드가 어디를 찾아야 할지 추측하는 것을 멈춘다. 
  - **회의 준비**** Skill**: 프로젝트 페이지를 먼저 확인한 후, 이전 회의 노트, 그리고 이해관계자 프로필을 확인하도록 지정할 수 있다. 
  - **연구 Skill**: 공유 드라이브에서 시작하여 CRM과 상호 참조한 후, 웹 검색으로 부족한 부분을 채우도록 지정할 수 있다. 
  - Skill은 어떤 작업에 어떤 소스가 중요한지에 대한 **기관 지식****(Institutional Knowledge)**을 인코딩한다. 

2. **신뢰할 수 있는 조정 (Reliable Orchestration)**: 다단계 워크플로가 예측 가능해진다. 
  - Skill이 없으면 클로드는 데이터가 충분한지 확인하기 전에 데이터를 가져와서 형식화할 수 있다. 
  - Skill은 순서를 명시적으로 정의하여, 클로드가 **매번 동일한 방식**으로 워크플로를 실행하도록 한다. 

3. **일관된 성과 (Consistent Performance)**: 결과물이 실제로 표준을 충족시킨다. 
  - 일반적인 결과는 편집이 필요하다. 
  - Skill은 팀에게 "완료(Done)"의 기준이 무엇인지 정의한다 (예: 올바른 구조, 적절한 세부 수준, 청중에 맞는 톤). 
  - 시간이 지남에 따라 팀은 상호 관련된 Skill과 연결을 구축하여, 클로드에게 특정 도메인에 대한 **전문 지식**을 부여한다. 


## 4. Skills와 MCP 간의 잠재적 중첩 및 해결 원칙 
1. **중첩 영역**:
  - MCP 서버는 일반적인 작업을 위해 도구 사용 힌트나 프롬프트 형태의 지침을 포함할 수 있으며, 이는 도구별 지식을 도구 가까이에 유지한다. 
  - 그러나 이러한 지침은 설계상 **일반적(generic)**으로 유지되어야 한다. 

2. **엄지손가락 규칙 (Rule of Thumb)**:
  - **MCP 지침**: 서버와 그 도구를 <em>올바르게 사용하는 방법</em>을 다룬다. 
  - **Skill 지침**: 주어진 프로세스나 다중 서버 워크플로에서 해당 도구들을 <em>어떻게 사용해야 하는지</em>를 다룬다. 

3. **예시 (****Salesforce****)**:
  - Salesforce MCP 서버는 쿼리 구문(Syntax)과 API 형식을 지정할 수 있다. 
  - Skill은 다음을 지정한다: 
  - 어떤 기록(Records)을 먼저 확인해야 하는지
  - 최근 맥락을 위해 Slack 대화와 어떻게 교차 참조해야 하는지
  - 팀의 파이프라인 검토를 위해 출력을 어떻게 구조화해야 하는지

4. **충돌 방지**:
  - MCP 서버와 Skill을 결합할 때는 **충돌하는 지침**이 없는지 확인해야 한다. 
  - 만약 MCP 서버가 JSON 반환을 요구하고, Skill이 마크다운 테이블 형식 지정을 요구한다면 클로드는 어느 것이 옳은지 추측해야 한다. 
  - **역할 분리 결론**: MCP가 **연결성**을 처리하도록 하고, Skill이 **표현(Presentation), 순서 지정(Sequencing), 워크플로 논리(Workflow Logic)**를 처리하도록 해야 한다. 


## 5. 실세계 워크플로 예시 
mcp 서버는 도구에 대한 접근을 제공하고, Skill은 해당 도구로 무엇을 할지 정의한다. 


### 5.1. 금융 분석: 회사 가치 평가 자동화 Skill 
1. **배경**:
  - Anthropic은 비교 가능한 회사 분석(Comparable company analysis)을 포함한 일반적인 금융 워크플로를 위한 사전 구축된 Skill 세트를 출시했다. 
  - 비교 가능한 회사 분석은 표준적인 가치 평가 방법이다. 
  - 애널리스트는 이 분석을 위해 여러 출처에서 재무 지표를 가져오고, 동일한 평가 방법론을 적용하며, 규정 준수 표준을 충족하도록 출력을 형식화하는 데 많은 시간을 소비하는데, 이 과정은 반복적이고 오류 발생 가능성이 높아 Skill과 MCP 결합의 이점을 얻을 수 있다. 

2. **구성 요소**:
  - **Skill (비교 가능한 회사 분석)**: 여러 출처에서 데이터를 가져오고, 일관된 방법론을 적용하며, 특정 표준에 맞춰 출력을 형식화하여 가치 평가 워크플로를 자동화한다. 
  - **MCP 서버**: 실시간 시장 데이터를 위한 S&P Capital IQ, Daloopa, Morningstar 연결을 제공한다. 

3. **워크플로 단계**:
  1. Skill이 쿼리할 데이터 출처를 식별한다 (**Discovery**). 
  2. MCP 연결이 실시간 재무 데이터를 가져온다. 
  3. Skill이 방법론을 적용하고 출력을 형식화한다 (**Orchestration**). 
  4. Skill이 규정 준수 요구 사항에 대해 유효성을 검사한다 (**Performance**). 


### 5.2. 프로젝트 관리: Notion의 Meeting Intelligence Skill 
1. **배경**:
  - 회의 준비(Meeting prep)는 지루한 작업이다. 
  - 프로젝트 문서, 이전 회의 노트, 이해관계자 정보 등 여러 곳에서 맥락을 가져와 사전 읽기 자료(Pre-read)와 의제(Agenda)로 종합해야 하는, 매번 다시 설명하게 되는 다단계 프로세스이다. 

2. **구성 요소**:
  - **Skill (Meeting Intelligence)**: 검색할 페이지, 출력 구조화 방식, 포함할 섹션 등을 정의한다. 
  - **MCP 서버**: Notion 페이지를 검색하고, 읽고, 생성하는 Notion 연결을 제공한다. 

3. **워크플로 단계**:
  1. Skill이 프로젝트, 이전 회의, 이해관계자 정보 등 검색할 관련 페이지를 식별한다 (**Discovery**). 
  2. MCP 연결이 Notion에서 콘텐츠를 검색하고 검색한다. 
  3. Skill이 내부용 사전 읽기 자료와 외부용 의제라는 두 문서를 구조화한다 (**Orchestration**). 
  4. MCP 연결이 두 문서를 Notion에 조직화하고 연결된 상태로 저장한다. 
  5. Skill이 출력물이 형식화 표준과 일치하도록 보장한다 (**Performance**). 


## 6. Skills와 MCP 사용 시점 결정 


### 6.1. Skills를 사용해야 할 경우 
Skill은 팀에 새로운 사람이 합류할 때마다 다시 설명해야 하거나, 팀원의 머릿속에만 존재하는 지식을 포착한다. 다음 경우에 가장 적합하다.

1. **도구가 관련된 다단계 워크플로**: 여러 출처에서 정보를 가져와 구조화된 문서를 생성하는 회의 준비와 같은 경우. 
2. **일관성****이 중요한 ****프로세스**: 매번 동일한 방법론을 따라야 하는 분기별 재무 분석, 필수 검사 지점이 있는 규정 준수 검토와 같은 경우. 
3. **포착하고 공유하려는 도메인 전문 지식**: 연구 방법론, 코드 검토 표준, 작성 지침과 같은 경우. 
4. **팀원이 떠나도 유지되어야 하는 워크플로**: 재사용 가능한 지침으로 인코딩된 기관 지식. 


### 6.2. MCP 서버를 사용해야 할 경우 
MCP는 클로드가 접근하고 사용할 수 있는 범위를 확장한다. 다음이 필요할 때 MCP를 사용해야 한다.

1. **실시간 데이터**** 접근**: Notion 페이지 검색, Slack 메시지 읽기, 데이터베이스 쿼리. 
2. **외부 시스템에서의 조치(Actions)**: GitHub 이슈 생성, 프로젝트 관리 도구 업데이트, 알림 전송. 
3. **파일 작업**: Google Drive에서 읽고 쓰기, 로컬 파일 시스템 접근. 
4. **API**** 통합**: 클로드 네이티브 지원이 없는 서비스에 연결. 

결론적으로, **무언가를 ****어떻게**** 해야 하는지 설명한다면 그것은 Skill이고, 클로드가 ****접근****해야 한다면 그것은 MCP이다.** 


## 7. 자주 묻는 질문 및 시작 방법 


### 7.1. 자주 묻는 질문 (Quick Reference) 
1. **Skill이 MCP를 대체하는가?** 
  - **아니다.** Skill과 MCP는 서로 다른 문제를 해결한다. 
  - MCP는 외부 도구 및 데이터에 대한 **연결성**을 제공한다. 
  - Skill은 해당 연결성을 효과적으로 사용하기 위한 **절차적 지식**을 제공한다. 
  - 가장 강력한 워크플로는 둘 다 사용한다. 

2. **하나의 Skill이 여러 ****MCP 서버****를 사용할 수 있는가?** 
  - **그렇다.** 하나의 Skill이 여러 MCP 서버를 동시에 조정할 수 있다. 
  - 예시: 기술 경쟁 분석 Skill은 Google Drive에서 내부 연구를 검색하고, GitHub에서 경쟁사 저장소(repos)를 가져오며, 웹 검색을 통해 시장 데이터를 수집할 수 있다. 

3. **하나의 ****MCP 서버****에 대해 여러 Skill을 구축할 수 있는가?** 
  - **그렇다.** Skill은 단일 MCP 연결을 통해 얻는 가치를 높일 수 있다. 
  - Notion은 Meeting Prep, 연구, 지식 캡처, 스펙-구현 전환을 위한 별도의 Skill을 통해 이러한 패턴을 보여준다. 


### 7.2. 시작 방법 
1. **Skills****를 사용하려면**: 
  - Claude.ai의 Settings → Capabilities에서 Skill을 활성화한다. 
  - 사전 구축된 예시를 위해 Skill 라이브러리를 탐색한다. 
  - Skill 문서를 읽는다. 

2. **MCP를 사용하려면**: 
  - 자신의 도구에 맞는 MCP 서버를 탐색한다. 
  - MCP 문서를 읽는다. 
  - MCP 퀵 스타트를 통해 자체 서버를 구축한다. 

3. **둘을 결합하려면**: 
  - MCP 서버를 연결한 다음, 이를 사용하는 Skill을 추가한다.
