## 1. 클로드(Claude)의 발전과 AI의 미래 [2]

클로드(Claude)는 모델 개발의 경계를 넓히며 AI의 능력을 기하급수적으로 발전시키고 있으며, 개발자들은 이러한 발전이 실제 문제 해결에 활용될 수 있도록 돕는 중요한 역할을 한다.

### 1.1. 클로드(Claude)의 발전과 그 영향 [2]

개인에게 부여되는 초능력 [2]

클로드(Claude)는 과거 컴퓨터 과학 연구실에서만 가능했던 복잡한 작업을 이제 누구나 쉽게 접근하여 수행할 수 있도록 한다 [2].

사용자들은 클로드(Claude)를 통해 마치 초능력을 얻은 것 같다고 표현하며, 이는 클로드(Claude)가 제공하는 즐거움, 발견, 안도감을 나타낸다 [24].

실제 문제 해결 사례 [30]

스트라이프(Stripe)의 개발팀은 5만 줄의 스칼라(Scala) 코드를 자바(Java)로 전환하는 데 클로드(Claude)를 사용하여 예상 10주를 4일로 단축했다 [30].

빈티(Binti)의 펠리시아 크라쿠루(Felicia Krakuru)는 클로드(Claude) API를 활용하여 위탁 아동 배치 서류 작업 시간을 20일 단축함으로써, 아이들이 더 빨리 가족과 연결될 수 있도록 도왔다 [36].

기하급수적인 모델 발전 속도 [46]

클로드(Claude)의 발전 속도는 매우 빨라, 몇 년 전에는 이메일 작성 수준이었던 모델이 이제는 복잡한 작업을 자율적으로 수행한다 [52].

6개월 전에는 에이전트가 밤새 작업을 완료하는 수준이었고, 지난달에는 미토스(Mythos)가 27년 된 취약점을 발견하는 등 발전의 폭과 속도가 계속 증가하고 있다 [57].

### 1.2. AI 발전과 현실 간의 격차 해소 [62]

AI 능력과 실제 활용 간의 격차 [62]

모델의 능력은 기하급수적으로 발전하지만, 대부분의 조직은 AI를 선형적으로 도입하고 있어 AI가 할 수 있는 것과 실제로 하는 것 사이에 격차가 존재한다 [62].

이 격차를 해소하고 모델의 능력을 실제 문제 해결에 적용하는 것이 개발자들의 역할이며, 클로드 플랫폼의 API 사용량은 17배 증가했고, 클로드 코드 개발자들은 주당 20시간을 클로드 사용에 할애하고 있다 [66].

클로드(Claude)의 새로운 기능 소개 [73]

앤트로픽(Anthropic)은 새로운 모델을 발표하는 대신, 기존 제품을 개선하여 개발자들이 격차를 해소할 수 있도록 돕는 데 집중한다 [73].

클로드 관리 에이전트(Claude Managed Agents)에 멀티 에이전트 오케스트레이션(Multi-agent orchestration), 아웃컴(Outcomes), 드리밍(Dreaming) 기능이 추가되어 복잡한 작업을 협업하고, 목표 달성 여부를 스스로 평가하며, 과거 경험을 통해 자율적으로 학습하고 개선할 수 있게 되었다 [80].

클로드 코드(Claude Code)에는 루틴(routines)과 같은 새로운 기본 요소가 추가되어 사용자가 자리를 비워도 클로드(Claude)가 스스로 프롬프트를 생성할 수 있게 되었다 [82].

개발자 지원 강화 [86]

앤트로픽(Anthropic)은 개발자들이 AI를 통해 모든 사람을 위한 경험을 만들어가는 데 기여하는 것에 감사하며, 이를 지원하기 위해 클로드 코드(Claude Code) 및 클로드 플랫폼(Claude platform)의 API 호출 제한(rate limits)을 두 배로 늘렸다 [86].

특히 클로드 오푸스(Claude Opus)의 API 제한을 크게 늘리기 위해 스페이스X(SpaceX)의 콜로서스 원(Colossus One) 데이터 센터 용량을 활용하는 등 컴퓨팅 파트너십을 확장하고 있다 [94].

## 2. 클로드(Claude) 모델의 혁신과 개발자를 위한 도구 [102]

클로드(Claude) 모델은 지속적인 혁신을 통해 지능과 기능이 기하급수적으로 향상되고 있으며, 앤트로픽(Anthropic)은 개발자들이 이러한 최신 기능을 활용하여 복잡한 문제를 해결하고 새로운 시장을 창출할 수 있도록 다양한 도구와 플랫폼을 제공한다.

### 2.1. 클로드(Claude) 모델의 발전과 새로운 기능 [102]

모델 개발의 역사와 성과 [102]

앤트로픽(Anthropic)은 2023년부터 클로드 2(Claude 2) 이후 18개 버전의 클로드(Claude) 모델(Haiku, Sonnet, Opus, Mythos)을 출시했다 [102].

오푸스 3(Opus 3)는 JSON 준수 및 장문 코드 작성 능력을 향상시켰고, 소네트 3.5 뉴(Sonnet 3.5 Nu)는 컴퓨터 사용법을 학습했으며, 소네트 3.7(Sonnet 3.7)은 과도한 적극성을 조절하여 사용자에게 최적화되었다 [107].

지난 12개월 동안 8개의 프론티어 모델(frontier models)을 출시하여 개발자들이 더 나은 코드를 작성하고 제품을 발전시킬 수 있도록 지원했다 [110].

기하급수적인 지능 향상 [114]

모델 지능이 증가함에 따라 개발자들이 구축할 수 있는 사용 사례도 기하급수적으로 증가하며, 이는 코드 자동 완성보다 에이전트 코딩(agentic coding)이 훨씬 더 큰 영향력을 가지는 것과 같다 [114].

연구팀은 모델 지능 향상을 단순히 수치 증가로 보지 않고, 도구 사용(tool use), 컴퓨터 사용(computer use), 문제 적응적 사고(thinking that adapts to the problem), 수천 단계에 걸쳐 계획을 유지하는 에이전트 루프(agentic loops), 그리고 긴 컨텍스트 창(long context windows)과 같은 새로운 기능을 창출하는 것으로 본다 [121].

이러한 기능들은 코드뿐만 아니라 시각 디자인 생성 및 반복, 복잡한 업무 분석 및 생성, 모호한 비즈니스 영역 탐색 등 다양한 분야로 확장된다 [124].

오푸스 4.7(Opus 4.7)의 혁신 사례 [129]

코딩 에이전트 AMP는 오푸스 4.7(Opus 4.7)이 벤치마크에서 최고 점수를 기록하자 전체 스마트 모드를 오푸스 4.7로 전환하여 툴링을 간소화했다 [129].

라쿠텐(Rakuten)은 오푸스 4.7을 통해 기존보다 3배 많은 프로덕션 엔지니어링 작업을 해결했다 [132].

인튜이트(Intuit)는 오푸스 4.7이 계획 단계에서 자체 논리적 오류를 식별하고 해결하여 더 빠르고 깔끔한 실행을 가능하게 하는 것을 확인했다 [133].

클로드 디자인(Claude Design)은 오푸스 4.7의 시각 디자인 능력을 활용하여 생산 인터페이스를 구축하는 데 사용되고 있으며, 이는 오푸스 4.7이 디자인 원칙을 준수하면서도 미묘한 차이를 표현하는 능력을 가졌기 때문이다 [135].

미래를 위한 개발 전략 [139]

모델은 아직 미완성 단계이며, 때로는 기본적인 문제에 막히거나 많은 컨텍스트가 주어지면 혼란스러워할 수 있다 [139].

앤트로픽(Anthropic)은 고품질 코드 능력(Quality code taste), 무한한 컨텍스트 창(infinite context windows), 그리고 멀티 에이전트 조정(multi-agent coordination)을 통해 클로드(Claude)의 자율 작업 능력을 향상시키고 있다 [142].

개발자들은 현재 모델뿐만 아니라 미래의 더 강력한 클로드(Claude) 버전을 위해 설계해야 하며, 이를 위해 더 어려운 평가(harder evals)를 만들고, 야심찬 프로토타입(ambitious prototypes)을 구축하며, 모델 업그레이드를 저렴하게 만드는 전략이 필요하다 [152].

### 2.2. 클로드 플랫폼(Claude Platform)의 새로운 기능: 멀티 에이전트, 아웃컴, 드리밍 [176]

비즈니스 문제 해결을 위한 클로드 플랫폼 [176]

모델의 기하급수적인 발전에도 불구하고, 비즈니스는 여전히 선형적으로 운영되고 있어, AI의 잠재력을 최대한 활용하는 것이 중요하다 [176].

비즈니스가 AI를 빠르게 도입하지 못하는 두 가지 주요 문제는 올바른 결과 도출의 어려움과 빠르고 확장 가능한 배포의 어려움이다 [179].

클로드 플랫폼은 이러한 문제를 해결하기 위해 클로드(Claude) 모델에 최적화된 API 기본 요소(API primitives), 에이전트 시스템 구축 및 확장을 위한 인프라, 그리고 시스템 운영을 위한 제어 기능을 제공한다 [190].

어드바이저 전략(Advisor Strategy)을 통한 비용 효율성 [195]

클로드 플랫폼은 어드바이저 전략(advisor strategy)을 통해 높은 지능을 유지하면서도 비용을 절감할 수 있도록 돕는다 [195].

이 전략은 실행을 담당하는 작은 모델과 조언을 제공하는 큰 모델로 에이전트 아키텍처를 분리한다 [200].

예를 들어, 소네트(Sonnet)가 실행하고 오푸스(Opus)가 조언하는 경우, 소네트(Sonnet) 단독보다 성능이 향상되고 비용도 절감된다 [202].

이브 리갈(Eve Legal)은 이 전략을 사용하여 프론티어 모델(frontier model) 수준의 품질을 5배 낮은 비용으로 달성했다 [205].

클로드 관리 에이전트(Claude Managed Agents)의 혁신 [210]

클로드 관리 에이전트(Claude Managed Agents)는 프로덕션 수준의 인프라와 결합된 에이전트 시스템으로, 프로토타입을 며칠 만에 프로덕션으로 전환할 수 있게 하여 배포 속도를 10배 빠르게 한다 [210].

이 시스템은 에이전트에게 메모리(memory)를 부여하는 등 모범 사례를 기본으로 제공하여 사용자 선호도를 유지하고 세션 간 일관성을 확보한다 [216].

노션(Notion)은 클로드 관리 에이전트를 활용하여 제품 내에서 복잡하고 자율적인 장기 작업을 수행하는 클로드(Claude) 에이전트를 구축했다 [222].

새로운 3가지 강력한 기능 [228]

멀티 에이전트 오케스트레이션(Multi-agent orchestration): 여러 에이전트가 협력하여 복잡한 작업을 해결할 수 있도록 한다 [229].

가상의 스타트업 루마라(Lumara)는 달에 드론을 착륙시키는 임무를 위해 지휘관(commander), 탐지기(detector), 항해사(navigator) 에이전트를 구성하여 협업하도록 했다 [241].

지휘관 에이전트는 각 하위 에이전트가 독립적인 컨텍스트 창을 갖는 세션을 생성하여 더 나은 성능을 제공한다 [262].

아웃컴(Outcomes): 성공 기준을 명확히 정의하면 클로드(Claude)가 해당 기준을 충족할 때까지 반복 작업을 수행한다 [230].

루마라(Lumara)는 드론이 부드럽게 착륙하고, 깨끗한 지면에 착륙하며, 지구로 돌아올 충분한 연료를 확보하는 등의 성공 기준을 마크다운 파일로 정의했다 [266].

별도의 평가자 에이전트(grader agent)가 세션 전반에 걸쳐 정의된 기준을 충족하는지 평가하며, 필요에 따라 여러 번 반복하여 목표를 달성한다 [275].

드리밍(Dreaming): 클로드(Claude)가 이전 세션을 검토하여 놓친 기술이나 배워야 할 교훈을 스스로 학습하고 메모리에 적용하여 자율적으로 개선한다 [231].

루마라(Lumara)는 시뮬레이션 결과에 만족하지 못하자 드리밍(Dreaming) 기능을 사용하여 과거 시뮬레이션 세션을 검토하고 학습 내용을 메모리에 기록했다 [281].

드리밍(Dreaming) 에이전트는 하강 플레이북(descent playbook)을 작성하여 향후 모든 세션에서 이를 참조하도록 함으로써, 드론 착륙 시뮬레이션의 성공률을 높였다 [291].

### 2.3. 클로드 코드(Claude Code)의 발전과 개발자 경험 혁신 [307]

소프트웨어 개발의 재창조 [307]

클로드 코드(Claude Code)는 개발자들이 아이디어를 제품으로 빠르게 구현할 수 있도록 돕는 것을 목표로 한다 [313].

앤트로픽(Anthropic)은 개발자들과 함께 미지의 영역을 탐험하며, AI 능력 향상에 발맞춰 새로운 도전을 해결해 나간다 [319].

과거에는 개발자가 클로드(Claude)의 모든 편집 내용을 검토하고 상세한 피드백을 제공해야 했지만, 이제는 대부분의 개발자가 자동 모드(auto mode)로 클로드(Claude)에게 권한을 위임하고 작업 완료 후 PR(Pull Request)을 검토하는 방식으로 변화했다 [321].

다양한 인터페이스와 개발 환경 [326]

클로드 코드(Claude Code)는 터미널(terminal), IDE(통합 개발 환경), 데스크톱(desktop) 등 다양한 인터페이스를 제공하여 사용자의 필요에 맞춰 선택할 수 있도록 한다 [326].

클로드 코드 데스크톱 앱(Claude Code on Desktop)은 전체 화면 그래픽 인터페이스, 내장 미리보기, 에이전트 제어판, 이미지 및 풍부한 출력 렌더링 기능을 제공하며, 로컬 및 원격 세션을 모두 관리할 수 있다 [332].

이러한 인터페이스는 클로드 에이전트 SDK(Claude Agent SDK)를 기반으로 구축되었으며, 앤트로픽(Anthropic) 내부적으로도 엔지니어당 PR 수를 200% 증가시키는 데 기여했다 [336].

개발자 피드백 기반 기능 개선 [340]

코드 리뷰(Code Review): 코드 리뷰 시간을 줄이기 위해 에이전트 팀이 중요한 버그를 찾아내는 기능을 제공하며, 앤트로픽(Anthropic) 내부 팀을 포함한 수천 개의 회사에서 사용 중이다 [343].

원격 제어(Remote Control): 이동 중에도 코딩할 수 있도록 iOS 및 Android 클로드 앱에 원격 제어 기능을 추가하여, 언제 어디서든 작업을 시작할 수 있게 했다 [345].

자동 수정(Autofix): PR(Pull Request) 관리, CI(Continuous Integration) 테스트 수정, 코드 리뷰 댓글 처리, 병합 충돌 해결 등 반복적인 작업을 자동으로 처리하여 PR을 항상 녹색(green) 상태로 유지한다 [350].

루틴(Routines): 웹훅(webhooks), API 이벤트 또는 스케줄에 따라 클로드 코드(Claude Code) 작업을 자동으로 시작하도록 구성할 수 있어, 수동으로 작업을 시작할 필요가 없다 [353].

클로드 보안(Claude Security): 코드베이스를 밤새 스캔하여 취약점을 찾아내고, 클로드 코드(Claude Code)를 통해 이를 해결하도록 한다 [357].

산업 전반의 변화와 미래 비전 [361]

쇼피파이(Shopify)는 클로드 코드(Claude Code)를 엔지니어링 팀뿐만 아니라 디자인, 제품, 데이터 과학 등 비엔지니어링 팀에서도 활용하여 내부 도구 구축 방식을 혁신했다 [362].

메르카도리브레(MercadoLibre)는 23,000명의 엔지니어가 클로드 코드(Claude Code)를 사용하여 50만 개 이상의 PR을 검토하고 9,000개 이상의 앱을 현대화했으며, 올해 3분기까지 90%의 자율 코딩과 에이전트 기반 PR 루프를 목표로 한다 [369].

클로드 코드(Claude Code)는 수십 년간 로드맵과 검토에 집중했던 관리자와 VP들이 다시 코딩에 참여할 수 있도록 하여, 코딩을 다시 그들의 손에 돌려주고 있다 [377].

데스크톱 앱(Desktop app)에서 클로드(Claude)는 환불 기능을 구현하고 자체 작업을 검증하며, 실패 시 문제점을 추적하고 수정하는 과정을 보여준다 [390].

이제 코딩은 비동기적(async) 방식으로 이루어지며, 클로드(Claude)가 작업을 검증할 수 있다면 개발자는 다른 작업을 하는 동안 클로드(Claude)가 작업을 완료하도록 맡길 수 있다 [404].

루틴(Routines)을 통해 개발자는 비동기 자동화를 설정하고, 아침에 병합할 준비가 된 PR을 확인할 수 있다 [413].

CI 자동 수정(CI autofix)은 PR을 모니터링하고, 코드 리뷰 및 보안 리뷰의 댓글을 자동으로 수정하며, CI 문제를 해결하고 병합 충돌 시 자동으로 리베이스하여 PR이 항상 녹색(green) 상태를 유지하도록 한다 [426].

미래에는 개발자가 직접 클로드 코드(Claude Code)에 프롬프트를 제공하는 대신, 클로드(Claude)가 클로드 코드(Claude Code)에 프롬프트를 제공하는 것이 기본이 될 것이다 [439].

앤트로픽(Anthropic)은 이러한 기능들이 개발자들의 아이디어를 제품으로 구현하는 데 걸리는 시간을 단축하고, 모델 평가, 플랫폼 구축, 일상 개발 작업에 클로드(Claude)를 통합하는 데 도움이 되기를 기대한다 [446].
