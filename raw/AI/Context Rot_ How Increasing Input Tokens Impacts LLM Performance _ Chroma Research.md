
최신 llm들이 수백만 토큰의 긴 컨텍스트 윈도우를 자랑하지만, 본 연구는 **입력 길이**** 증가에 따른 모델 성능의 실제적인 저하(Context Rot)** 현상을 단순 벤치마크를 넘어서 정밀하게 분석합니다. 단순 검색 작업인 'Needle in a Haystack(NIAH)' 테스트를 확장하여 **비유사 질문-답변 쌍**의 영향, **방해 요소(Distractors)** 유무, 그리고 **컨텍스트의 구조적 일관성**이 llm의 성능을 비균일적(non-uniform)으로 악화시키는 과정을 구체적인 실험 데이터를 통해 확인합니다. 이 분석은 실제 복잡한 에이전트 및 요약 작업에서 **효율적인 '컨텍스트 엔지니어링'**이 왜 필수적이며, llm의 장문 처리 능력을 맹신해서는 안 되는 이유를 명확하게 제시합니다.
## 1. 서론: LLM의 긴 컨텍스트 윈도우와 성능 저하 문제 (Context Rot) 
1. **배경 및 현황**:
  1. 최근 LLM 개발 추세는 컨텍스트 윈도우 확장에 있으며, 최신 모델들은 수백만 토큰의 입력 토큰 수를 자랑한다. 
  2. 예시: Gemini 1.5 Pro (1M, 2024년 초), GPT-4.1 (1M), Llama 4 (10M) 등이 있다. 
  3. 긴 컨텍스트의 유용성: LLM이 한 번의 호출로 더 많은 정보를 처리하고 더 정보에 기반한 출력을 생성할 수 있게 한다. 
  4. 이러한 모델들은 널리 사용되는 벤치마크인 NIAH(Needle in a Haystack)에서 거의 완벽한 점수를 달성했기 때문에, 긴 컨텍스트 작업에서 성능이 균일할 것이라고 흔히 가정된다. 
2. **기존 ****벤치마크****의 한계**:
  1. NIAH의 본질: NIAH는 단순한 **검색(retrieval) 작업**으로, 관련 없는 긴 문서('haystack') 속에 알려진 문장('needle')을 넣어 모델이 이를 검색하도록 요청하는 방식이다. 
  2. NIAH는 확장성은 있지만, 일반적으로 **직접적인 어휘적 일치(direct ****Lexical Matching****)**를 평가하므로 유연하고 의미론적인 작업들을 대표하지 못한다. 
  3. 실제 애플리케이션(에이전트 작업, 요약 등)은 훨씬 복잡하며, 모호한 정보에 대한 더 광범위한 처리와 추론을 요구한다. 
3. **연구의 필요성 (컨텍스트 로트 현상)**:
  1. 실제 세계 애플리케이션은 훨씬 더 큰 복잡성을 포함하고 있어, 입력 길이의 영향이 실제로는 더욱 두드러질 수 있다. 
  2. 기존 벤치마크 설계의 어려움: 입력 길이가 증가함에 따라 작업 복잡도도 증가하는 경향이 있어, 성능 저하가 단순히 긴 입력 때문인지, 아니면 문제 자체가 어려워져서인지 분리하기 어렵다. 
  3. **본 연구의 접근 방식**: 작업 복잡도를 일정하게 유지하고 **입력 길이****만을 변화**시켜, 입력 길이의 영향만을 직접 측정한다. 
  4. **발견**: 이러한 최소한의 통제된 조건에서도 모델 성능은 입력 길이가 증가함에 따라 **일관성 없이(non-uniform)** 저하된다는 것을 입증한다. 


## 2. 관련 연구 및 선행 NIAH 변형 분석 
1. **NIAH의 한계와 인식**:
  1. NIAH는 확장 가능한 테스트로 유용하나, 평가하는 능력은 **어휘적 검색(lexical retrieval)**이라는 좁은 범위에 국한된다. 
  2. 모델들이 NIAH에서 일반적으로 좋은 성능을 보이면서 긴 컨텍스트 문제는 대부분 해결되었다는 인식이 생겨났다. 
  3. 하지만 NIAH는 실제 대부분의 긴 컨텍스트 작업이 요구하는 수준을 과소평가한다. 
2. **NIAH의 변형 연구**:
  1. **NoLiMa**** **: 바늘-질문 쌍이 비어휘적 일치(non-lexical matches)를 포함할 경우, 모델 성능이 크게 저하됨을 밝혀냈다. 
  2. **AbsenceBench**** **: 주어진 텍스트 조각의 부재를 인식하는 능력을 테스트하며, 입력 길이가 증가할수록 성능 저하를 보여주었다. 
  3. **방해 요소(Distractors) 문제**: 긴 컨텍스트 작업은 종종 방해 요소들 사이에서 모호성을 해소해야 하며, 이와 관련된 연구(예: Multi-round co-reference resolution, MRCR [8, 9])가 존재하지만, 긴 컨텍스트 환경에서 방해 요소의 영향에 대한 조사는 여전히 부족하다. 
3. **입력 길이**** 스케일링 방식의 중요성**:
  1. **Latent List**** **: 모델이 다양한 입력 길이에서 고정된 수의 Python 리스트 작업을 수행하도록 요구하는 작업이다. 
  2. **결과**: 관련 없는 컨텍스트를 채우는 방식에 따라 모델 성능에 비균일적인 영향이 있음이 드러났다. 
  - 예시: 로컬에서 서로 상쇄되는 리스트 작업을 추가하는 것이 단순히 print 구문을 추가하는 것보다 모델 성능을 더 크게 저하시킨다. 
  - 이는 '관련 없는 내용'의 유형이 중요하며, 일부 내용은 입력 길이가 길어짐에 따라 복잡도를 증가시킬 수 있음을 시사한다. 
  3. **Graphwalks**** **: 그래프 순회 작업으로, 입력 길이가 증가하면 순회해야 할 그래프의 크기가 증가하여 작업 난이도가 높아진다. 
  4. **결론**: 작업 복잡도와 입력 길이를 분리하기 어렵기 때문에, **성능에 대한 ****입력 길이****만의 영향을 격리**하는 것이 LLM이 긴 입력에서 실제로 어떻게 작동하는지를 이해하는 데 필수적이다. 


## 3. 확장된 Needle in a Haystack (NIAH) 실험 설계 
1. **NIAH 확장 배경**:
  1. 기존 NIAH는 어휘적 일치를 사용하는 바늘-질문 쌍을 사용하지만, 실제 장문 컨텍스트 활용은 종종 모호한 작업에 대한 **의미론적 이해**를 요구한다. 
  2. NoLiMa는 비어휘적 일치가 긴 컨텍스트에서 모델에 도전이 된다는 것을 입증했다. 
  3. <em>NoLiMa</em><em> 예시</em>: 질문 "어떤 캐릭터가 헬싱키에 갔는가?"에 대한 바늘이 "사실, 유키는 키아스마 미술관 옆에 산다"인 경우, 모델은 키아스마 미술관이 헬싱키에 있다는 **외부 지식**과 잠재적 연관성을 추론해야 한다. 
  4. NoLiMa 바늘-질문 쌍의 72.4%는 이러한 외부 지식을 요구하여, 순수한 비어휘적 일치 테스트가 아닌 두 가지 작업을 동시에 평가하는 벤치마크에 가깝다. 
  5. 본 연구는 비어휘적 일치의 영향을 격리하여 테스트하는 측면이 부족하고, 실제 QA 시나리오에서 질문-답변 쌍이 **유사성 스펙트럼** 상에 존재한다는 점에서, 단순히 '어휘적' 대 '비어휘적'으로 구분하는 것은 단순화라고 지적한다. 
2. **방해 요소(Distractors) 도입**:
  1. 방해 요소는 성능을 저하시키는 것으로 알려져 있지만, 대부분의 기존 평가는 짧은 입력 길이와 구형 모델을 대상으로 했다. 
  2. 본 연구는 입력 길이가 증가할 때 최신 모델의 방해 요소 대처 능력을 광범위하게 테스트한다. 
  3. **방해 요소 대 무관한 컨텍스트 정의**: 
  - **방해 요소 (Distractor)**: 바늘과 주제적으로 관련이 있지만, 질문에 정확히 답하지 않는 내용이다.
  - **무관한 컨텍스트 (Irrelevant content)**: 바늘 및 질문과 전혀 관련이 없는 내용이다.
3. **Haystack(배경 문서)의 영향 조사**:
  1. 기존 NIAH에서 Haystack은 단순히 입력 길이를 확장하는 수단으로 취급되었으나, 그 내용 자체가 작업 성능에 영향을 미치지 않는다는 가정은 테스트되지 않았다. 
  2. 본 연구는 Haystack의 내용(주제, 서술 흐름) 변화가 LLM 결과에 영향을 미치는지 조사한다. 
4. **4가지 통제된 실험 설계**: 
  1. **바늘-질문 유사성**** (Needle-Question Similarity)**: 임베딩을 사용하여 바늘-질문 쌍의 코사인 유사도를 측정하고, 입력 길이 증가에 따른 성능 변화를 관찰한다. 
  2. **방해 요소의 영향 (Impact of Distractors)**: 높은 유사도의 바늘-질문 쌍을 사용하여, 방해 요소가 없을 때(Baseline), 하나일 때, 그리고 네 개일 때의 성능 변화를 측정한다. 
  3. **바늘-Haystack 유사성 (Needle-Haystack Similarity)**: 주제적으로 구별되는 두 가지 Haystack(Paul Graham 에세이와 arXiv 논문)을 사용하고, 각 바늘에 대해 Haystack과의 의미론적 유사도를 측정하여 성능을 비교한다. 
  4. **Haystack 구조 (Haystack Structure)**: 각 발췌문의 자연스러운 흐름이 보존된 **Original** 조건과 문장들이 무작위로 재배열되어 논리적 연속성이 없는 **Shuffled** 조건을 비교하여 구조의 영향력을 평가한다. 
5. **전반적인 결과 요약**:
  1. 모든 실험에서 모델 성능은 입력 길이가 증가함에 따라 **일관되게 저하**된다. 
  2. 바늘-질문 유사도가 낮을수록 성능 저하율이 증가한다. 
  3. 방해 요소는 서로 다른 정도로 비균일적인 영향을 미치며, 이 영향은 입력 길이가 증가할수록 두드러진다. 
  4. 바늘-Haystack 유사성은 모델 성능에 **균일하지 않은(non-uniform)** 영향을 미친다. 
  5. Haystack의 구조적 패턴(논리적 일관성)은 모델이 긴 입력을 처리하는 방식에 **일관되게 영향**을 미친다. 


## 4. NIAH 확장 실험 상세 및 결과 


### 4.1. 실험 공통 설정 및 평가 방법 
1. **테스트 조건**: 모든 바늘 유형, Haystack 주제, Haystack 구조의 고유한 조합에 대해 다음 조건을 테스트한다. 
  - **입력 길이**: 8가지 입력 길이 
  - **바늘 위치**: 11가지 바늘 위치 
2. **모델 평가**:
  - 각 모델은 최대 컨텍스트 윈도우에서 평가되며, 온도(temperature)는 0으로 설정된다 (일부 모델 호환성 예외 제외). 
  - Qwen 모델의 경우, YaRN 방법 을 적용하여 컨텍스트 윈도우를 32,768 토큰에서 131,072 토큰으로 확장한다. 
  - 모델 출력 평가는 정렬된 **GPT-4.1 평가자**를 사용하여 진행되었다. 
  - 모델이 작업을 시도하지 않고 거부하는 희귀한 사례(전체 호출의 0.035%)가 관찰되었으며, 예시로 Claude Opus 4가 stop_reason=”refusal”로 빈 출력을 내는 경우가 있다. 


### 4.2. 바늘-질문 유사성 (Needle-Question Similarity)의 영향 
1. **실험 목적**: 실제 환경에서는 모델이 정확한 어휘적 일치 없이 관련성을 추론해야 하므로, 바늘-질문 쌍의 유사도를 변화시켜 성능 영향을 측정한다. 
2. **핵심 발견**: **바늘-질문 유사성****이 감소**하면, 입력 길이가 증가할 때 모델 성능은 **더욱 빠르게 저하**된다. 
  - 이는 실제 시나리오에서 의미적 모호성이 장문 처리의 어려움을 가중시키는 것을 반영한다. 
3. **실험 설계**:
  1. Haystack 콘텐츠: Paul Graham 에세이와 arXiv 논문 두 가지 도메인을 사용한다. 
  2. 질문 및 바늘 생성:
  - 문서 청크 분할, 임베딩, 차원 축소(UMAP), 클러스터링(HDBSCAN)을 통해 Haystack의 공통 주제를 파악했다. 
  - PG 에세이는 '글쓰기 조언', arXiv 논문은 '정보 검색(재순위 지정)'을 공통 주제로 식별하고 이에 해당하는 질문을 작성했다. 
  - Haystack 내용에 질문의 정답이 없는지 수동으로 검증하여, 오답이 모델 환각(Hallucinations) 때문임을 보장했다. 
  3. 바늘 작성: 각 질문에 대해 8개의 바늘을 작성했으며, 이들은 해당 주제 클러스터에 속할 확률이 높도록(>0.9) 토픽적으로 Haystack과 조화되게 했다. 
  4. 유사도 측정: 5개 임베딩 모델의 코사인 유사도를 평균하여 바늘-질문 쌍의 유사도를 정량화했다. 
  - PG 에세이 주제: 유사도 범위 0.445~0.775 (표준편차 <0.1) 
  - arXiv 주제: 유사도 범위 0.521~0.829 (표준편차 <0.1) 
4. **결과 상세**:
  1. 짧은 입력 길이에서는 모델들이 낮은 유사도 쌍에서도 잘 수행되어, 이들이 해당 작업을 수행할 능력이 있음을 보여준다. 
  2. 성능 저하는 바늘-질문 쌍의 고유한 난이도 때문이 아니라, **입력 크기**가 증가함에 따라 무관한 콘텐츠가 늘어나는 것이 주요 원인임을 격리해냈다. 
  3. **바늘 위치**: 11가지 바늘 위치에서 테스트했지만, 이 특정 NIAH 작업에서는 성능에 눈에 띄는 변화가 없었다. 


### 4.3. 방해 요소(Distractors)의 영향 
1. **실험 목적**: 방해 요소가 모델 성능을 저하시키고 그 영향이 비균일적이라는 것이 구형 모델에서 확인되었는데, 입력 길이가 증가할 때 최신 모델에서 이 주장이 유지되는지 검증한다. 
2. **핵심 발견**: 방해 요소의 영향과 그 **비균일성**은 입력 길이가 증가함에 따라 최신 SOTA 모델을 포함한 모든 모델에서 **증폭**된다. 
3. **실험 설계**:
  1. 바늘 선택: 각 Haystack 주제에서 바늘-질문 유사도가 높은 바늘(8개 중 두 번째로 높음)을 선택하여, 바늘 식별이 상대적으로 쉬운 조건으로 설정했다. 
  2. 방해 요소 작성: 수동으로 4개의 방해 요소를 작성했으며, 이들은 바늘과 주제적으로 유사하지만 정확한 답은 아니다. 
  3. 테스트 조건 (3가지): 
  - **No distractors (Baseline)**: 바늘만 포함
  - **Single distractor**: 바늘 + 무작위로 배치된 방해 요소 1개
  - **Multiple distractors**: 바늘 + 무작위로 배치된 방해 요소 4개 모두
4. **결과 상세**:
  1. 단 하나의 방해 요소도 기준선 대비 성능을 감소시키며, 4개의 방해 요소를 추가하면 성능 저하가 더욱 심해진다. 
  2. **비균일적 영향**: 방해 요소들이 성능에 미치는 영향은 균일하지 않으며, 특정 방해 요소(예: arXiv/PG 에세이 조합에서 distractor 3)가 다른 것들에 비해 더 큰 성능 저하를 일으킨다. 
  3. **실패 분석**: 4개 방해 요소 조건에서 모델이 실패한 응답을 분석한 결과, 방해 요소 2와 3이 모델의 환각(hallucinated responses)에 가장 빈번하게 나타났다. 
  4. **모델별 행동**:
  - **Claude 모델**: 모호한 상황에서 가장 낮은 환각률을 보이며, 특히 Claude Sonnet 4와 Opus 4는 불확실할 때 정답이 없다고 명시하며 **기권하는 경향(conservative and abstain)**이 있다. 
  - **GPT 모델**: 가장 높은 환각률을 보였으며, 방해 요소가 있을 때 종종 확신하지만 **틀린 응답**을 생성했다. 


### 4.4. 바늘-Haystack 유사성 (Needle-Haystack Similarity)의 영향 
1. **실험 목적**: 무관한 컨텍스트(Haystack)의 내용이 중립적인 자리 표시자로 간주되지만, 바늘-Haystack 유사성이 작업 난이도에 영향을 미치는지 확인한다. 
  - 직관적으로 바늘이 Haystack 내용과 **비슷하게 섞여 들어가면** 추출하기 더 어려울 것으로 예상된다. 
2. **핵심 발견**: 바늘-Haystack 유사성은 모델 성능에 **비균일적인 영향**을 미친다. 
3. **실험 설계**:
  1. Haystack과 유사도 측정: Haystack을 임베딩하고 각 바늘에 대해 가장 유사한 상위 5개 청크를 검색한 후, 그 코사인 유사도 점수를 평균하여 유사도를 측정했다. 
  2. 유사도 비교: PG 에세이 Haystack에 PG 에세이 바늘(평균 0.529, 높은 유사도)과 arXiv 바늘(평균 0.368, 낮은 유사도)을 삽입하여 비교했다. arXiv Haystack에서도 유사한 대조를 설정했다. 
4. **결과 상세**:
  1. **Paul Graham 에세이 Haystack**: arXiv 바늘(낮은 유사도)이 PG 에세이 바늘(높은 유사도)에 비해 **상당히 더 나은 성능**을 보였다. 즉, 바늘이 Haystack과 의미론적으로 섞여 들어가지 않을 때 모델 성능이 더 좋았다. 
  2. **arXiv Haystack**: arXiv 바늘과 PG 에세이 바늘 사이에 **최소한의 성능 차이**만 관찰되었다. 
  3. **결론**: 단 두 가지 주제로 일반화된 결론을 내릴 수는 없지만, 이는 장문 처리의 **비균일적인 특성**을 보여준다. 
  4. 작업 구조와 바늘-질문 유사도가 일정하더라도, 바늘과 Haystack 간의 의미론적 유사도를 바꾸는 것만으로도 결과에 영향을 줄 수 있으며, 이는 향후 연구의 중요한 방향임을 시사한다. 


### 4.5. Haystack 구조 (Haystack Structure)의 영향 
1. **실험 목적**: Haystack이 논리적으로 일관된 텍스트(예: 에세이)로 구성될 경우, 무작위로 삽입된 바늘이 논리적 흐름을 방해하여 오히려 더 눈에 띄게 만들 수 있다. Haystack 구조의 논리적 흐름이 모델 성능에 영향을 미치는지 확인한다. 
2. **핵심 발견**: 구조적 일관성이 **일관되게 모델 성능을 저해**한다. 
  - **반직관적 결과**: Haystack이 논리적인 아이디어 흐름을 보존할 때 모델 성능이 더 나빴다. 
  - Haystack을 섞어서 국소적 일관성(local coherence)을 제거했을 때 성능이 일관되게 향상되었다. 
3. **실험 설계**: Haystack을 두 가지 변형으로 생성했다. 
  - **Original**: 각 발췌문 내에서 아이디어의 자연스러운 흐름을 보존
  - **Shuffled**: 전체 Haystack 내에서 문장들을 무작위로 재배열하여, 전체 주제는 유지하되 논리적 연속성은 제거
4. **결과 상세**:
  1. 18개 모델과 모든 바늘-Haystack 구성에서, 모델들이 논리적으로 구조화된 Haystack보다 **Shuffled Haystack에서 더 나은 성능**을 보인다는 일관된 패턴이 관찰되었다. 
  2. **시사점**: 이러한 결과는 모델의 내부 처리 방식에 영향을 미칠 수 있으며, 특히 입력 길이가 증가함에 따라 주의 메커니즘이 어떻게 적용되는지에 대한 **구조적 패턴의 영향**을 시사한다. 
  3. 이러한 구조적 영향력을 이해하는 것은 긴 컨텍스트 실패 패턴을 설명하는 데 도움이 될 수 있다. 


## 5. LongMemEval을 이용한 대화형 QA 평가 
1. **실험 목적**: NIAH보다 더 현실적인 환경인 **대화형 질문-답변** 벤치마크인 LongMemEval을 사용하여 모델을 평가한다. 
  - 긴 입력을 사용하는 것은 대화형 어시스턴트가 관련 대화 기록을 유지하는 일반적인 방법이다. 
2. **작업의 복합성**:
  1. 나이브한 접근 방식(전체 채팅 기록을 프롬프트에 포함)은 모델에게 두 가지 과제(검색 및 추론)를 동시에 수행하도록 요구한다. 
  2. 관련 없는 컨텍스트를 추가하는 것은 모델에게 **무엇이 관련 있는지 식별**하는 추가 단계를 강제하여 두 작업을 동시에 수행하게 한다. 
  3. 본 연구는 이 추가 단계가 성능에 미치는 영향을 체계적으로 테스트한다. 
3. **테스트 조건 (두 가지)**: 
  1. **Focused input (집중된 입력)**: 관련 부분만 포함하여 모델이 단순 추론에만 집중하도록 한다 (~300 토큰).
  2. **Full input (전체 입력)**: 관련 없는 컨텍스트를 포함한 전체 113k 토큰의 LongMemEval 입력을 사용하여, 모델이 추론 외에 긴 컨텍스트 내에서 검색도 수행하도록 한다.
4. **핵심 발견**: 모델들이 집중된 입력에서는 매우 잘 수행되는 것으로 확인되었지만, 전체 입력에서는 **일관된 ****성능 저하**가 관찰되었다. 
  - 이는 무관한 컨텍스트를 추가하여 **검색이라는 추가 단계**를 넣는 것이 모델의 안정적인 성능 유지 능력에 심각한 영향을 미친다는 것을 시사한다. 
5. **실험 상세**:
  1. 데이터셋: LongMemEval\_s에서 지식 업데이트, 시간적 추론, 다중 세션 범주에 해당하는 작업을 사용했으며, 모호한 질문을 수동으로 필터링하여 총 306개의 프롬프트를 사용했다. 
  2. 프롬프트 길이: 전체 프롬프트는 평균 ~113k 토큰이며, 대부분 질문과 무관한 컨텍스트로 구성된다. 집중된 프롬프트는 평균 ~300 토큰이다. 
  3. 평가: 정렬된 LLM 평가자(GPT-4.1, 인간 판단과 99% 이상 일치)를 사용하여 모델 출력을 평가했다. 
6. **결과 상세**:
  1. 모든 모델에서 전체 프롬프트 대비 집중된 프롬프트에서 **현저히 높은 성능**을 보였다. 
  2. **Claude 모델**: 집중/전체 프롬프트 간의 성능 격차가 가장 두드러졌다. 
  - 이 차이는 NIAH의 방해 요소 실험에서 관찰된 것과 유사하게, 모호성으로 인해 발생하는 **기권(abstentions)**에 의해 크게 좌우된다. 
  - 특히 Claude Opus 4와 Sonnet 4에서 이러한 보수적인 행동이 두드러져, 구형 Claude 모델에 비해 전체 프롬프트에서 낮은 성능을 보였다. 
  - <em>예시</em>: 날짜 정보가 전체 프롬프트에 포함되어 있음에도, Claude Sonnet 4는 답변할 수 없다고 명시하며 기권했다. 
  3. **GPT, Gemini, ****Qwen 모델**: 이 모델군에서도 집중된 프롬프트에서 더 강한 성능을 보이는 경향은 유지되었다. 
  4. **사고 모드(Thinking Modes)의 영향**: 사고 모드를 지원하는 모델의 경우, 집중 및 전체 프롬프트 모두에서 상당한 성능 향상을 보였으나, 최신 모델조차도 이 기능을 사용하더라도 두 입력 길이 사이의 성능 격차는 여전히 존재했다. 
  5. **질문 유형별 패턴 (Claude Opus 4)**:
  - 비사고 모드에서는 **지식 업데이트 > 다중 세션 > 시간적 추론** 순으로 성능이 좋았다. 
  - 사고 모드가 활성화되면 순위가 **지식 업데이트 > 시간적 추론 > 다중 세션**으로 변화했다. 


## 6. 반복되는 단어 (Repeated Words) 합성 작업 평가 
1. **실험 목적**: 앞선 실험들은 출력이 상대적으로 짧게 고정되었던 반면, 이 실험은 **출력 길이가 ****입력 길이****와 함께 확장**될 때의 모델 성능을 평가한다. 
  - LLM은 자기회귀적이므로, 각 토큰은 입력과 앞서 생성된 토큰에 조건부로 생성된다. 
  - 본 연구는 단순한 문자열 반복 작업에서도 컨텍스트 길이(입력+출력 길이)가 증가함에 따라 모델 성능이 비균일적으로 변하는지 확인한다. 
2. **실험 설계**:
  1. 작업: 모델은 특정 위치에 단 하나의 고유한 단어가 삽입된 **반복되는 단어 시퀀스**를 정확히 복제하도록 지시받는다. 
  2. 컨텍스트 및 인덱스 변화: 12가지 단어 수(~25개부터 10000개까지)와 고유 단어 인덱스를 변화시킨 1090가지 변형을 생성했다. 
  3. 단어 조합 (7가지): 'apple'/'apples', 'golden'/'Golden', 'orange'/'run', 'San Francisco'/'sf' 등 다양한 조합을 사용했다. 
  4. 모델 설정:
  - max_output_tokens = input_tokens * 2 (모델의 최대 출력 토큰 한도 내에서) 
  - temperature = 0 
  - 사고 모델은 최소 사고 예산(minimum thinking budget)을 적용했다. 
  5. 평가: 정규화된 **레벤슈타인 거리(Normalized Levenshtein distance)**로 점수를 계산했다. 
3. **실패 및 거부 처리**:
  1. 모델이 작업을 시도하지 않는 경우(빈 출력, 부적절한 출력, 순수한 관찰 후 시도 없음, 거부 등)는 제외하고, 그 비율을 별도로 기록했다. 
  2. 작업을 시도했으나 시작 문구가 있는 경우(예: "I notice there's a discrepancy...")는 동일한 채점 과정으로 약간의 불이익을 주어 포함했다. 
  3. GPT-3.5 turbo는 60.29%의 높은 거부율(finish_reason='content_filter')로 인해 전체 실험에서 제외되었다. 
4. **결과 측정 기준**: 
  1. 정규화된 레벤슈타인 거리
  2. 고유 단어의 존재 및 위치 정확도
  3. 단어 수 차이 (입력 단어 수 - 생성된 단어 수)
5. **전반적인 결과**: 컨텍스트 길이(입력/출력 길이)가 증가함에 따라 **모든 모델에서 성능이 일관되게 저하**되었다. 


### 6.1. Claude 모델군 결과 
1. **성능 및 거부**: Sonnet 3.5는 최대 출력 토큰 한도(8192)까지 최신 Claude 모델보다 성능이 우수했다. 
2. **Opus 4의 특이 행동**:
  - 가장 느린 성능 저하율을 보이지만, 유일하게 작업을 거부하는 모델이었다 (2.89%). 
  - 2500 단어부터는 시도 전 **관찰을 먼저 수행**하고, 이후 시도 또는 거부를 결정하는 패턴이 흔히 나타났다. 
  - 거부 사유: 저작권 침해 우려(verbatim 복제 회피) 또는 반복 시퀀스 내의 불일치 감지. 
3. **위치 정확도**: 고유 단어가 시퀀스의 **초기 부분**에 배치될 때 정확도가 가장 높았다. 
4. **단어 수 차이**: 컨텍스트 길이가 증가함에 따라 모델은 종종 출력 토큰 한도에 도달할 때까지 반복되는 단어를 생성하는 경향이 있으며, 단어 수 차이를 통해 모델이 **과소 생성(Positive)** 또는 **과잉 생성(Negative)** 했는지 확인할 수 있다. 


### 6.2. GPT 모델군 결과 
1. **거부율**: GPT-4.1은 2.55%의 거부율을 보였고, 이는 보통 2500 단어 주변에서 시작되었다. 
2. **GPT-4 Turbo의 성능 변동**:
  - 500 단어 주변에서 **국소적인 성능 정점**을 관찰했다. 
  - 50~250 단어 사이에서는 과잉 생성하는 경향이 있지만, 500 단어에서는 단어 수가 더 정확해진다. 
  - 500 단어 이후부터는 입력/출력 단어 수 차이가 양수(+)로 나타나며 과소 생성하기 시작한다. 
3. **위치 정확도**: Claude 모델군과 마찬가지로 고유 단어가 입력 **초기에 나타날 때** 정확도가 높았다. 
4. **모델별 특이 행동**:
  - **GPT-4.1 mini**: 모든 작업을 시도했으나, "Golden Gate Bridge" / "Golden Gate Park" 조합에서 때때로 **무작위 단어**를 생성했다. 
  - 무작위 단어: 입력에 없는 단어 또는 단어 시퀀스. 
  - 예시: 입력에 없는 "Golden Golden", "Gate Gate"와 같은 중복 단어를 고유 단어 위치가 아닌 텍스트의 후반부 위치에서 출력했다. 
  - **GPT-4.1 nano**: "San Francisco" / "sf" 쌍에서 가끔 소문자 "san"을 출력하는 유사한 행동을 보였다. 
  - **무작위 단어의 구조**: 무작위 단어가 나타나는 위치와 고유 단어의 위치 사이에 상관관계가 있다는 힌트가 관찰되었다. 
  - **GPT-4 Turbo**: 이 모델군에서 가장 가변적인 출력(가장 높은 무작위 출력 경향과 다양한 무작위 출력 세트)을 보였다.

## 7. 결론 및 시사점 
1. **주요 연구 결과 요약**:
  1. 본 연구의 실험들은 LLM이 단순한 작업에서도 컨텍스트 길이에 따라 **일관되지 않은 성능**을 보인다는 것을 입증했다. 
  2. 비어휘적 검색이나 텍스트 복제와 같이 단순한 작업에서도 입력 길이가 증가함에 따라 성능의 비균일성이 증가하는 현상이 나타났다. 
  3. 가장 능력 있는 모델들조차도 정보가 **어떻게 제시되는지**에 민감하다는 것을 증명했으며, 이로 인해 효율적인 **컨텍스트 엔지니어링**이 필수적이다. 
2. **실제 환경에 대한 시사점**:
  1. 본 평가는 실제 사용 사례를 완전히 망라하지 못했지만, 실제 장문 컨텍스트 애플리케이션(합성, 다단계 추론)은 훨씬 더 복잡하므로, 이러한 조건 하에서는 성능 저하가 **훨씬 더 심각할 것으로 예상**된다. 
  2. **컨텍스트 엔지니어링의 중요성**: 정보가 모델의 컨텍스트에 '존재하는 것'이 전부가 아니며, **'어떻게 제시되는가'**가 더 중요하다. 
  3. 모델의 컨텍스트 윈도우 내에서 정보가 어디에, 그리고 어떤 방식으로 구성되고 관리되는지가 작업 성능에 강력하게 영향을 미친다. 
3. **향후 연구 방향**:
  1. **난이도와 길이 분리**: 긴 컨텍스트 벤치마크에 대한 공통된 한계는 입력 길이와 작업 복잡도를 혼동하는 경향인데, 향후 연구에서는 성능 저하가 작업 자체의 본질적 난이도에서 비롯되는지, 아니면 긴 컨텍스트 처리 능력에서 비롯되는지를 명확하게 분리해야 한다. 
  2. **메커니즘 조사**: 본 연구는 성능 저하의 메커니즘을 설명하지 않았으나, 컨텍스트의 구조적 속성(관련 정보의 배치, 반복)이 모델 행동에 영향을 미친다는 관찰 결과는 **메커니즘적 해석 가능성(mechanistic interpretability)** 연구의 방향을 제시한다. 
  3. 이러한 결과는 현재의 벤치마크를 넘어서는 보다 엄격한 장문 컨텍스트 평가의 필요성을 강조한다.
