## 1. Foundation Model 패러다임

### 한 줄 직관

Foundation model은 “처음부터 매번 새로 배우는 모델”이 아니라, 아주 큰 데이터로 먼저 넓게 배워 둔 뒤 여러 작업에 맞게 조금씩 적응시키는 기본 모델입니다.

### 개념 정의

Foundation model은 대규모 데이터로 사전학습(pretraining)되어, 번역, 요약, 검색, 코딩, 이미지 이해, 음성 이해처럼 여러 작업의 출발점이 되는 모델입니다. 여기서 foundation은 “기초 공사”에 가깝습니다. 건물을 지을 때 매번 땅을 새로 다지는 대신 튼튼한 기초 위에 집, 학교, 병원 같은 다양한 건물을 올리는 것과 비슷합니다.

기술적으로는 하나의 모델이 입력 데이터 안의 일반적인 패턴을 많이 배웁니다. LLM에서는 단어와 문장 패턴, 추론 패턴, 지식의 연결을 배웁니다. 이미지 모델에서는 색, 모서리, 물체, 장면 구성을 배웁니다. 이렇게 배운 공통 표현(representation)을 여러 downstream task, 즉 실제로 풀고 싶은 구체적인 작업에 재사용합니다.

### 왜 이런 개념이 필요한가

예전 방식은 작업마다 모델을 따로 만드는 경우가 많았습니다. 스팸 메일 분류 모델, 감정 분석 모델, 번역 모델, 질의응답 모델을 각각 따로 학습했습니다. 이 방식은 데이터와 시간이 많이 들고, 작은 회사나 개인이 좋은 모델을 만들기 어렵습니다.

Foundation model 패러다임에서는 큰 모델을 한 번 넓게 학습해 둡니다. 그다음 사용자는 prompt를 잘 쓰거나, 작은 데이터로 fine-tuning하거나, retrieval 같은 외부 도구를 붙여서 원하는 작업에 맞춥니다. 그래서 현대 AI 시스템은 “모델 하나”가 아니라 “범용 모델 + 적응(adaptation) 방법 + 데이터/도구”의 조합으로 만들어지는 경우가 많습니다.

### 아주 쉬운 예시

어떤 사람이 한국어를 잘하고, 영어도 어느 정도 알고, 수학 문제 풀이도 해 본 적이 있다고 해 봅시다. 이 사람에게 “이 문장을 요약해 줘”, “이 코드를 설명해 줘”, “이 표를 보고 결론을 말해 줘”라고 하면 완전히 처음 배우는 사람보다 훨씬 빨리 적응합니다.

작은 숫자 예시로 보면 이렇습니다.

- 작업 A: 영화 리뷰가 긍정인지 부정인지 분류
- 작업 B: 상품 문의에 답변 생성
- 작업 C: 문서에서 핵심 문장 요약

작업마다 처음부터 100만 개 데이터를 모아 모델을 학습하려면 너무 비쌉니다. 하지만 이미 1조 개 토큰으로 학습된 foundation model이 있다면, 작업 A에는 예시 100개와 prompt만으로도 어느 정도 동작할 수 있고, 작업 B에는 회사 FAQ를 붙여서 답하게 할 수 있고, 작업 C에는 요약 instruction을 주면 됩니다.

### 개념 구조와 핵심 포인트

Foundation model 패러다임은 보통 다음 흐름으로 이해하면 쉽습니다.

1. Pretraining: 아주 큰 데이터에서 일반 패턴을 배웁니다. LLM은 보통 “다음 토큰 예측” 같은 목표로 학습합니다.
2. Representation learning: 단어, 문장, 이미지, 코드 등을 embedding이나 hidden state 같은 내부 벡터 표현으로 바꿉니다.
3. General-purpose capability: 하나의 모델이 여러 종류의 입력과 작업에 어느 정도 대응합니다.
4. Adaptation: prompt engineering, instruction tuning, fine-tuning, RLHF, RAG, tool use 같은 방법으로 특정 목적에 맞춥니다.
5. Deployment: 실제 서비스에서는 모델만 쓰지 않고 검색 시스템, 데이터베이스, 안전 필터, 평가 시스템, 모니터링을 함께 붙입니다.

핵심은 “모든 문제를 처음부터 다시 학습하지 않는다”입니다. 이미 배운 공통 능력을 재사용하고, 필요한 부분만 바꿉니다.

### 핵심 수학 포인트

Foundation model의 수학적 핵심은 큰 데이터 분포에서 패턴을 압축해 파라미터(parameter)에 저장하는 것입니다. 아주 단순하게 말하면 모델은 입력 x를 받아 출력 y를 예측하는 함수입니다.

- 입력 x: “오늘 날씨가”
- 목표 y: “좋다” 또는 다음 토큰
- 모델 fθ(x): 파라미터 θ를 가진 예측 함수

학습은 예측이 틀렸을 때 loss를 계산하고, gradient와 optimizer로 θ를 조금씩 바꾸는 과정입니다.

작은 숫자 예시를 보겠습니다.

- 실제 다음 단어가 “좋다”일 확률을 1.0이라고 생각합니다.
- 모델이 처음에는 “좋다” 확률을 0.30으로 예측합니다.
- 학습 후에는 0.60, 더 학습하면 0.85처럼 올라갑니다.

이 변화는 모델 내부의 수많은 weight가 조금씩 조정되면서 일어납니다. Foundation model에서는 이런 조정을 엄청나게 많은 문장, 이미지, 코드 예시에 대해 반복합니다. 그 결과 hidden state 안에 단어 의미, 문맥, 관계, 스타일 같은 정보가 들어가게 됩니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- foundation model: 여러 작업의 기반이 되는 대규모 사전학습 모델입니다.
- general-purpose model: 하나의 특정 작업만이 아니라 다양한 작업에 쓰일 수 있는 범용 모델입니다.
- adaptation: 이미 학습된 모델을 특정 목적에 맞게 조정하는 과정입니다.
- pretraining: 큰 데이터로 먼저 넓게 학습하는 단계입니다.
- downstream task: foundation model을 실제로 적용하려는 구체적인 작업입니다.
- representation: 모델 내부에서 입력을 벡터 형태로 표현한 것입니다.

### AI에서 어디에 쓰이는가

현대 LLM 서비스는 대부분 foundation model 패러다임 위에 있습니다. ChatGPT, Claude, Gemini 같은 모델은 대규모 pretraining을 거친 뒤 instruction tuning과 안전성 학습을 통해 대화형 assistant가 됩니다. 기업용 챗봇은 여기에 회사 문서 검색(RAG)을 붙이고, 코딩 assistant는 코드 데이터와 도구 실행 능력을 붙입니다.

이미지 쪽에서도 CLIP, Stable Diffusion, vision-language model은 큰 데이터에서 먼저 이미지와 텍스트의 관계를 배운 뒤, 검색, 생성, 분류, captioning 같은 작업에 활용됩니다.

### 헷갈리기 쉬운 포인트

- Foundation model이 항상 모든 일을 완벽히 잘한다는 뜻은 아닙니다. 넓게 배웠다는 뜻이지, 특정 회사 내부 규칙을 자동으로 아는 것은 아닙니다.
- 큰 모델이면 무조건 foundation model이라고 부르지는 않습니다. 여러 작업의 기반으로 적응 가능해야 합니다.
- Prompt만으로 해결되는 작업도 있지만, 데이터가 정확해야 하는 업무에서는 RAG, fine-tuning, 평가 데이터가 필요합니다.
- Pretraining에서 배운 지식은 오래되거나 틀릴 수 있습니다. 그래서 실제 시스템에서는 최신 데이터 검색과 검증이 중요합니다.

## 2. Transfer Learning과 파라미터 효율화

### 한 줄 직관

Transfer learning은 이미 배운 지식을 새 문제에 옮겨 쓰는 것이고, PEFT와 LoRA는 큰 모델 전체를 고치지 않고 일부 작은 부분만 바꿔서 싸고 빠르게 적응시키는 방법입니다.

### 개념 정의

Transfer learning은 한 작업이나 큰 데이터에서 배운 모델의 지식을 다른 작업에 재사용하는 학습 방식입니다. 예를 들어 이미지 모델이 이미 고양이, 자동차, 나무의 기본 모양을 배웠다면, 병원 X-ray 분류를 배울 때도 “모서리, 질감, 형태를 보는 능력”을 재사용할 수 있습니다.

LLM에서도 마찬가지입니다. 모델이 이미 언어 구조, 문맥, 사실 지식, 코드 패턴을 배웠다면, 법률 문서 요약이나 고객센터 답변 생성 같은 새 작업에 적은 데이터로 적응할 수 있습니다.

파라미터 효율화(parameter-efficient fine-tuning)는 큰 모델의 모든 파라미터를 업데이트하지 않고, 작은 추가 파라미터만 학습하거나 일부 경로만 조정하는 방법입니다. 대표적인 방법이 PEFT(Parameter-Efficient Fine-Tuning), LoRA(Low-Rank Adaptation), adapter입니다.

### 왜 이런 개념이 필요한가

요즘 LLM은 파라미터가 수십억에서 수천억 개입니다. 모델 전체를 fine-tuning하려면 GPU 메모리, 학습 시간, 저장 공간이 많이 필요합니다.

예를 들어 모델 전체가 70억 개 파라미터라면, 모든 weight를 학습하려면 큰 GPU 여러 대가 필요할 수 있습니다. 그런데 실제로는 특정 업무에 필요한 변화가 전체 모델을 다 바꿀 만큼 크지 않을 때가 많습니다. “말투를 바꾸기”, “특정 문서 형식으로 답하기”, “특정 도메인 용어에 익숙해지기” 같은 작업은 작은 조정으로도 충분할 수 있습니다.

그래서 현대 AI 실무에서는 foundation model을 그대로 두고, 작고 학습 가능한 모듈만 붙여서 비용을 줄이는 방법이 중요합니다.

### 아주 쉬운 예시

자전거를 잘 타는 사람이 전기자전거를 배우는 상황을 생각해 봅시다. 이 사람은 균형 잡기, 핸들 조작, 브레이크 사용을 이미 압니다. 새로 배울 것은 전기 모터의 가속 감각 정도입니다. 처음부터 “두 바퀴 탈것”을 다시 배우지 않아도 됩니다. 이것이 transfer learning의 느낌입니다.

숫자 예시로 보면 더 분명합니다.

- 전체 모델 파라미터: 1,000,000개
- 새 작업에 필요한 조정 파라미터: 10,000개
- 학습하는 비율: 10,000 / 1,000,000 = 1%

전체를 다 고치지 않고 1%만 학습해도 새 작업에 충분히 적응할 수 있다면, 시간과 비용이 크게 줄어듭니다.

LoRA의 직관도 간단히 볼 수 있습니다. 원래 큰 weight matrix W가 있다고 합시다. 전체 W를 직접 바꾸는 대신, 작은 두 행렬 A와 B를 학습해서 변화량 ΔW를 만듭니다.

- 원래 W는 고정합니다.
- 작은 A, B만 학습합니다.
- 실제 계산에서는 W + ΔW처럼 사용합니다.

이렇게 하면 모델의 큰 지식은 유지하면서, 필요한 방향으로만 살짝 조정할 수 있습니다.

### 개념 구조와 핵심 포인트

Transfer learning은 보통 다음 방식으로 진행됩니다.

1. Source learning: 큰 데이터나 관련 작업에서 먼저 학습합니다.
2. Reuse: 학습된 weight, embedding, hidden representation을 새 작업의 출발점으로 사용합니다.
3. Adaptation: 새 작업 데이터로 모델을 조정합니다.
4. Evaluation: 새 작업에서 실제로 성능이 좋아졌는지 확인합니다.

파라미터 효율화 방법은 여러 종류가 있습니다.

- Full fine-tuning: 전체 파라미터를 업데이트합니다. 강력하지만 비싸고 과적합 위험도 있습니다.
- Adapter: 모델 층 사이에 작은 trainable module을 끼웁니다.
- LoRA: 큰 weight matrix는 고정하고, 낮은 rank의 작은 변화량만 학습합니다.
- Prompt tuning / prefix tuning: 입력 앞쪽에 학습 가능한 prompt vector를 붙여 모델 행동을 바꿉니다.
- PEFT: 이런 파라미터 효율적 방법들을 포괄하는 넓은 용어입니다.

핵심 포인트는 “모델의 기존 지식은 보존하고, 새 작업에 필요한 작은 변화만 학습한다”입니다.

### 핵심 수학 포인트

모델의 한 linear layer를 아주 단순화하면 다음처럼 볼 수 있습니다.

- 입력 vector x
- weight matrix W
- 출력 h = Wx

Full fine-tuning은 W 전체를 직접 바꿉니다. LoRA는 W를 그대로 두고 변화량 ΔW만 작게 학습합니다.

- h = (W + ΔW)x
- ΔW = BA

여기서 A와 B는 W보다 훨씬 작은 행렬이 되도록 설계합니다. 이를 low-rank라고 부릅니다. rank는 행렬이 얼마나 많은 독립적인 방향을 표현할 수 있는지를 나타내는 개념입니다. 복잡한 변화가 아니라 “몇 가지 중요한 방향의 변화”만 학습하겠다는 뜻으로 이해하면 됩니다.

작은 숫자 예시를 보겠습니다.

- W가 100 × 100 행렬이면 파라미터는 10,000개입니다.
- LoRA rank를 4로 두면 A는 4 × 100, B는 100 × 4가 될 수 있습니다.
- 학습 파라미터는 400 + 400 = 800개입니다.

10,000개를 모두 바꾸는 대신 800개만 학습합니다. 실제 LLM에서는 이 차이가 GPU 메모리와 학습 비용에 큰 영향을 줍니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- transfer learning: 한 곳에서 배운 지식을 다른 작업에 옮겨 쓰는 학습 방식입니다.
- PEFT: Parameter-Efficient Fine-Tuning의 약자로, 적은 파라미터만 학습하는 fine-tuning 방법들의 묶음입니다.
- LoRA: Low-Rank Adaptation의 약자로, 큰 weight는 고정하고 작은 low-rank 변화량만 학습하는 방법입니다.
- adapter: 기존 모델 사이에 끼워 넣는 작은 학습 모듈입니다.
- fine-tuning: 사전학습된 모델을 특정 작업 데이터로 추가 학습하는 과정입니다.
- frozen parameters: 학습 중 업데이트하지 않고 고정해 둔 파라미터입니다.
- trainable parameters: 학습 중 gradient로 업데이트되는 파라미터입니다.

### AI에서 어디에 쓰이는가

LLM 실무에서 LoRA와 PEFT는 매우 자주 사용됩니다. 예를 들어 회사 내부 문서 스타일에 맞는 답변을 만들거나, 의료/법률/금융 도메인 문체에 적응시키거나, 특정 instruction을 잘 따르게 만들 때 사용합니다.

또한 여러 고객에게 각각 다른 모델을 제공해야 할 때도 유용합니다. foundation model 하나는 공유하고, 고객별 LoRA adapter만 따로 저장하면 저장 공간을 크게 줄일 수 있습니다. 예를 들어 base model은 10GB인데 고객별 adapter가 100MB라면, 고객 10명을 위해 100GB를 쓰는 대신 10GB + 1GB 정도로 운영할 수 있습니다.

### 헷갈리기 쉬운 포인트

- Transfer learning은 단순히 “복사해서 쓰기”가 아닙니다. 기존 지식을 출발점으로 쓰고 새 작업에 맞게 조정하는 것입니다.
- LoRA를 쓰면 항상 full fine-tuning보다 좋은 것은 아닙니다. 데이터가 충분하고 큰 변화가 필요하면 full fine-tuning이 더 나을 수도 있습니다.
- PEFT는 모델을 작게 만드는 compression과 다릅니다. PEFT는 주로 “학습해야 하는 파라미터 수”를 줄이는 방법입니다.
- Adapter나 LoRA가 작아도, base model을 추론할 때는 여전히 큰 모델을 실행해야 합니다. 학습 비용은 줄지만 추론 비용이 완전히 사라지는 것은 아닙니다.

## 3. 멀티모달 모델 구조

### 한 줄 직관

멀티모달(multimodal) 모델은 텍스트만 보는 모델이 아니라 이미지, 소리, 영상, 표 같은 여러 종류의 정보를 함께 이해하도록 만든 모델입니다.

### 개념 정의

Multimodal 모델은 서로 다른 modality, 즉 데이터 종류를 함께 다루는 모델입니다. 여기서 modality는 텍스트, 이미지, 오디오, 비디오, 센서 데이터처럼 정보가 표현되는 형식을 뜻합니다.

Vision-language model은 그중에서도 이미지와 텍스트를 함께 다루는 모델입니다. 예를 들어 이미지를 보고 “강아지가 공을 물고 있다”라고 설명하거나, “이 사진에서 빨간 물체는 어디에 있어?” 같은 질문에 답할 수 있습니다.

Cross-modal alignment는 서로 다른 modality의 의미를 같은 공간에서 맞추는 과정입니다. 쉽게 말해 “고양이 사진”과 “cat이라는 단어”가 모델 내부에서 가까운 의미로 연결되도록 만드는 것입니다.

### 왜 이런 개념이 필요한가

사람은 세상을 텍스트로만 이해하지 않습니다. 사진을 보고, 소리를 듣고, 영상을 보고, 표를 읽고, 몸으로 감각을 느낍니다. 실제 AI 시스템도 텍스트만으로는 부족한 경우가 많습니다.

예를 들어 다음 작업은 텍스트 LLM만으로는 어렵습니다.

- 영수증 사진을 보고 금액과 날짜를 읽기
- 의료 이미지를 보고 이상 부위를 설명하기
- 공장 카메라 화면에서 결함 찾기
- 수학 문제 사진을 보고 풀이하기
- 로봇이 카메라로 본 물체를 잡기

이런 작업에서는 이미지 encoder, audio encoder, video encoder 등 각 modality를 처리하는 구조와, 그 정보를 LLM의 token/hidden state와 연결하는 구조가 필요합니다.

### 아주 쉬운 예시

“사과”라는 단어만 보면 우리는 빨간 과일을 떠올립니다. 사과 사진만 봐도 같은 대상을 떠올립니다. 멀티모달 모델은 이 두 입력이 같은 의미를 가리킨다는 것을 배워야 합니다.

작은 숫자 예시로 생각해 봅시다.

- 텍스트 “apple”의 embedding: [0.9, 0.1]
- 사과 사진의 image embedding: [0.8, 0.2]
- 자동차 사진의 image embedding: [0.1, 0.9]

텍스트 “apple”과 사과 사진 embedding은 서로 가깝습니다. 자동차 사진은 멉니다. 이런 식으로 서로 다른 modality의 표현을 같은 의미 공간에 정렬하면, 텍스트로 이미지를 찾거나 이미지에 대해 질문할 수 있습니다.

실제 모델에서는 2차원 벡터가 아니라 수백~수천 차원의 embedding을 사용합니다. 하지만 기본 아이디어는 “의미가 같으면 가까이, 다르면 멀리”입니다.

### 개념 구조와 핵심 포인트

멀티모달 모델은 보통 다음 구성 요소를 가집니다.

1. Modality-specific encoder: 이미지, 오디오, 텍스트 등 각 입력을 먼저 처리하는 encoder입니다. 이미지는 Vision Transformer, 텍스트는 Transformer, 오디오는 spectrogram 기반 encoder를 쓸 수 있습니다.
2. Projection layer: 서로 다른 encoder의 출력 차원을 맞춰 줍니다. 예를 들어 이미지 encoder 출력이 1024차원이고 LLM hidden size가 4096이면, linear layer로 4096차원에 맞춥니다.
3. Fusion mechanism: 여러 modality 정보를 합치는 방식입니다. 단순히 vector를 이어 붙일 수도 있고, attention으로 서로를 보게 할 수도 있습니다.
4. Language model or decoder: 합쳐진 정보를 바탕으로 답변, caption, 행동 명령 등을 생성합니다.
5. Alignment objective: 이미지-텍스트 쌍이 의미상 맞도록 학습하는 loss입니다.

핵심 포인트는 “데이터 형식은 달라도 모델 내부에서는 비교하고 연결할 수 있는 표현으로 바꾼다”입니다.

### 핵심 수학 포인트

멀티모달 모델의 기본 수학은 embedding space와 alignment loss로 이해할 수 있습니다.

이미지 encoder가 이미지 I를 vector v로 바꾸고, 텍스트 encoder가 문장 T를 vector t로 바꾼다고 해 봅시다.

- v = image_encoder(I)
- t = text_encoder(T)

이제 같은 의미의 이미지와 텍스트는 v와 t가 가깝게, 다른 의미의 쌍은 멀게 학습합니다. 가까움을 재는 방법으로 cosine similarity를 자주 씁니다. cosine similarity는 두 vector가 같은 방향을 보는지 재는 값입니다.

작은 예시입니다.

- 사과 사진 v = [1, 0]
- “apple” 텍스트 t = [0.9, 0.1]
- “car” 텍스트 c = [0, 1]

v와 t는 방향이 비슷해서 similarity가 높습니다. v와 c는 방향이 달라서 similarity가 낮습니다. 학습은 맞는 쌍의 similarity를 올리고, 틀린 쌍의 similarity를 낮추는 방향으로 loss를 줄입니다.

LLM과 연결할 때는 tensor shape도 중요합니다. 예를 들어 이미지 한 장을 16개의 patch token으로 바꾸고, 각 token의 hidden size가 4096이라면 이미지 정보는 [16, 4096] 형태의 tensor가 됩니다. 여기에 텍스트 token의 hidden state를 이어 붙이면 LLM이 attention으로 이미지 token과 텍스트 token을 함께 볼 수 있습니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- multimodal: 여러 데이터 형식, 예를 들어 텍스트와 이미지와 오디오를 함께 다루는 방식입니다.
- vision-language model: 이미지와 텍스트를 함께 이해하거나 생성하는 모델입니다.
- cross-modal alignment: 서로 다른 modality의 의미 표현을 맞추는 과정입니다.
- modality: 텍스트, 이미지, 오디오처럼 정보가 들어오는 형식입니다.
- image encoder: 이미지를 vector나 token 표현으로 바꾸는 모델 부분입니다.
- projection layer: 한 모델의 출력 차원을 다른 모델이 받을 수 있는 차원으로 바꾸는 layer입니다.
- fusion: 여러 modality의 정보를 합치는 과정입니다.

### AI에서 어디에 쓰이는가

멀티모달 구조는 GPT-4o, Gemini, Claude의 vision 기능, CLIP, BLIP, LLaVA 같은 모델에서 중요합니다. 사용자는 이미지를 올리고 질문할 수 있고, 모델은 이미지 속 객체, 텍스트, 관계를 읽어 답합니다.

실무에서는 OCR, 문서 이해, 의료 영상 보조, 자율주행, 로봇, 쇼핑 검색, 콘텐츠 moderation, 교육 문제 풀이에 쓰입니다. 예를 들어 쇼핑 앱에서 “이 사진과 비슷한 가방 찾아 줘”라고 하면 이미지 embedding과 상품 텍스트 embedding을 같은 공간에서 비교해 검색할 수 있습니다.

### 헷갈리기 쉬운 포인트

- Multimodal 모델이 이미지를 “사람처럼 본다”는 뜻은 아닙니다. 이미지는 patch나 embedding으로 바뀌고, 모델은 그 숫자 표현을 처리합니다.
- 이미지와 텍스트를 함께 학습했다고 해서 모든 시각적 추론을 완벽하게 하는 것은 아닙니다. 작은 글자, 복잡한 표, 공간 관계는 여전히 어려울 수 있습니다.
- Cross-modal alignment는 단순 번역이 아닙니다. 이미지의 시각적 의미와 텍스트의 언어적 의미를 같은 의미 공간에서 연결하는 과정입니다.
- Vision-language model과 image generation model은 다릅니다. 전자는 이해와 질의응답에 초점이 있을 수 있고, 후자는 이미지를 생성하는 데 초점이 있습니다. 물론 둘을 결합한 시스템도 많습니다.

[AI/ML 오늘의 복습 정답 Day 28/30]

오늘은 Foundation Model, LoRA/PEFT, 멀티모달 정렬을 차근차근 다시 확인해 볼게요.

### 1. Foundation model이 작업마다 처음부터 학습하는 모델과 다른 점은 무엇인가요?

**정답**

Foundation model은 매 작업마다 처음부터 새로 학습하지 않습니다.

대신 아주 큰 데이터로 먼저 넓게 pretraining, 즉 사전학습을 해 둔 뒤, 여러 downstream task에 맞게 prompt, fine-tuning, RAG, tool use 같은 방법으로 adaptation, 즉 적응시켜 사용합니다.

반대로 작업마다 처음부터 학습하는 모델은 감정 분석, 번역, 요약, 분류 같은 각각의 작업마다 데이터를 따로 모으고 모델을 새로 학습해야 합니다.

**설명**

Foundation model의 핵심은 “공통 능력을 먼저 크게 배워 두고 재사용한다”입니다.

예를 들어 LLM은 pretraining 과정에서 많은 문장을 보며 단어의 의미, 문맥, 문장 구조, 추론 패턴, 지식의 연결을 배웁니다. 이미지 모델이라면 색, 모서리, 질감, 물체 모양 같은 기본 시각 패턴을 배웁니다.

이렇게 배운 능력은 하나의 작업에만 갇히지 않습니다. 문서 요약, 질의응답, 번역, 코딩, 정보 검색, 이미지 설명 등 여러 작업의 출발점이 될 수 있습니다.

그래서 foundation model은 “완성된 단일 업무 모델”이라기보다, 여러 AI 시스템을 만들기 위한 기본 바탕에 가깝습니다. 실제 서비스에서는 여기에 회사 문서 검색 시스템, 안전 필터, 평가 데이터, 사용자 인터페이스, tool calling 같은 요소를 붙여서 사용합니다.

중요한 점은 foundation model이 모든 것을 자동으로 완벽히 안다는 뜻은 아니라는 것입니다. 넓게 배운 모델이지만, 특정 회사의 최신 정책이나 내부 문서, 매우 전문적인 규칙은 따로 연결하거나 적응시켜야 합니다.

**예시**

요리로 비유하면 foundation model은 “기본 요리 실력이 좋은 사람”입니다.

이 사람은 칼질, 굽기, 끓이기, 간 맞추기 같은 기본기를 이미 알고 있습니다. 그래서 한식, 양식, 디저트를 배울 때 처음부터 “불을 켜는 법”부터 다시 배우지 않아도 됩니다.

작은 숫자 예시로 보면:

- 처음부터 학습하는 방식: 감정 분석 모델에 데이터 100만 개, 요약 모델에 데이터 100만 개, 번역 모델에 데이터 100만 개가 각각 필요할 수 있음
- Foundation model 방식: 큰 모델을 먼저 1조 개 토큰으로 학습해 두고, 감정 분석은 예시 100개와 prompt로 시작하거나, 요약은 instruction만 주거나, 회사 업무는 RAG로 문서를 붙여서 처리할 수 있음

즉, 매번 새 모델을 처음부터 만드는 것이 아니라 이미 배운 큰 지식을 재사용합니다.

**실전 연결**

실제 LLM 서비스는 대부분 foundation model 패러다임 위에 있습니다. ChatGPT, Claude, Gemini 같은 모델은 대규모 pretraining을 거친 뒤 instruction tuning, RLHF, safety tuning 등을 통해 대화형 assistant가 됩니다. 기업용 챗봇은 여기에 RAG를 붙여 회사 문서를 검색하게 만들고, 코딩 assistant는 코드 데이터와 실행 도구를 연결합니다. 현대 AI 시스템을 이해하려면 “모델 하나”보다 “foundation model + adaptation + 데이터/도구”라는 구조로 보는 것이 중요합니다.

### 2. LoRA는 왜 큰 모델의 모든 weight를 직접 바꾸지 않고 작은 행렬 A, B를 학습하나요?

**정답**

LoRA는 큰 모델 전체 weight를 직접 바꾸면 비용이 너무 크기 때문에, 원래 weight는 고정하고 작은 행렬 A, B만 학습합니다.

이 작은 행렬 A, B로 변화량 ΔW를 만들고, 실제 계산에서는 원래 weight W에 이 변화량을 더한 것처럼 사용합니다.

즉, 전체 모델을 다 고치는 대신 “필요한 방향으로만 살짝 조정”하는 방법입니다.

**설명**

LLM 같은 큰 모델은 파라미터 수가 매우 많습니다. 수십억 개, 수백억 개, 때로는 그 이상입니다. 이런 모델의 모든 weight를 fine-tuning하려면 GPU 메모리, 학습 시간, 저장 공간이 많이 필요합니다.

하지만 실제 업무 적응에서는 전체 모델의 지식을 다 바꿀 필요가 없는 경우가 많습니다.

예를 들어 모델에게 다음과 같은 능력을 추가하고 싶다고 해 봅시다.

- 답변 말투를 더 공손하게 만들기
- 회사 문서 형식에 맞춰 답하게 하기
- 특정 도메인 용어에 익숙하게 만들기
- 고객센터 답변 패턴을 따르게 하기

이런 경우에는 모델 전체의 언어 능력을 다시 학습할 필요가 없습니다. 이미 언어 이해와 생성 능력은 base model에 들어 있습니다. 필요한 것은 특정 업무에 맞는 작은 조정입니다.

LoRA는 이 아이디어를 수학적으로 구현한 방법입니다.

원래 linear layer의 계산을 단순하게 보면:

- h = Wx

입니다.

여기서 W는 큰 weight matrix입니다. Full fine-tuning은 W 전체를 바꿉니다.

LoRA는 W를 직접 바꾸지 않고:

- h = (W + ΔW)x
- ΔW = BA

처럼 생각합니다.

여기서 A와 B는 W보다 훨씬 작은 행렬입니다. 이 작은 행렬만 trainable parameters, 즉 학습되는 파라미터로 두고, 원래 W는 frozen parameters, 즉 고정된 파라미터로 둡니다.

이렇게 하면 모델의 기존 지식은 보존하면서도, 새 작업에 필요한 변화만 효율적으로 배울 수 있습니다.

**예시**

큰 책 전체를 다시 쓰는 상황을 생각해 봅시다.

책이 1,000쪽짜리인데, 회사 스타일에 맞추기 위해 필요한 수정이 사실은 몇몇 표현과 형식뿐이라면 1,000쪽 전체를 다시 쓰는 것은 비효율적입니다. 대신 “이런 표현은 이렇게 바꿔라”라는 작은 수정 메모를 붙이면 훨씬 가볍습니다.

LoRA의 A, B는 이 “작은 수정 메모”에 가깝습니다.

작은 숫자 예시로 보면:

- 원래 weight W가 100 × 100 행렬이면 파라미터는 10,000개입니다.
- LoRA rank를 4로 두면 A는 4 × 100, B는 100 × 4가 될 수 있습니다.
- 그러면 학습하는 파라미터는 400 + 400 = 800개입니다.

즉, 10,000개를 모두 학습하는 대신 800개만 학습합니다. 이 차이는 실제 LLM에서는 GPU 비용과 저장 공간에 매우 큰 영향을 줍니다.

**실전 연결**

LLM 실무에서 LoRA와 PEFT는 매우 자주 쓰입니다. 예를 들어 하나의 base model을 두고, 고객 A용 LoRA adapter, 고객 B용 LoRA adapter, 의료 문서용 LoRA adapter, 법률 문서용 LoRA adapter를 따로 만들 수 있습니다. base model 전체를 고객마다 복사하지 않아도 되므로 저장 공간과 학습 비용이 크게 줄어듭니다. 다만 LoRA가 항상 full fine-tuning보다 좋은 것은 아닙니다. 데이터가 충분하고 모델 행동을 크게 바꿔야 한다면 full fine-tuning이 더 적절할 수도 있습니다.

### 3. 멀티모달 모델에서 cross-modal alignment가 필요한 이유를 “사과 사진”과 “apple”이라는 단어 예시로 설명해 보세요.

**정답**

Cross-modal alignment가 필요한 이유는 서로 다른 데이터 형식인 이미지와 텍스트가 같은 의미를 가리킬 때, 모델 내부에서도 그 둘을 가깝게 연결해야 하기 때문입니다.

즉, “사과 사진”과 “apple”이라는 단어는 입력 형태는 다르지만 의미는 같습니다. 멀티모달 모델은 이 둘의 embedding이 비슷한 위치에 오도록 학습해야 합니다.

그래야 이미지를 보고 텍스트로 설명하거나, 텍스트로 이미지를 검색하거나, 이미지에 대해 질문에 답할 수 있습니다.

**설명**

Multimodal 모델은 여러 modality를 함께 다루는 모델입니다. 여기서 modality는 정보가 들어오는 형식을 말합니다. 예를 들어 텍스트, 이미지, 오디오, 비디오가 각각 다른 modality입니다.

문제는 이미지와 텍스트가 원래 완전히 다른 형태의 데이터라는 점입니다.

- 텍스트 “apple”은 단어 token입니다.
- 사과 사진은 pixel 값들의 모음입니다.

사람에게는 둘 다 “사과”로 쉽게 연결되지만, 모델 입장에서는 처음에는 완전히 다른 숫자 배열입니다. 그래서 image encoder는 이미지를 vector로 바꾸고, text encoder는 텍스트를 vector로 바꿉니다. 그런 다음 같은 의미를 가진 이미지 vector와 텍스트 vector가 가까워지도록 학습합니다.

이 과정을 cross-modal alignment라고 합니다.

여기서 alignment는 “정렬”이라는 뜻입니다. 서로 다른 modality의 의미 표현을 같은 embedding space 안에서 맞추는 것입니다.

가까움을 재는 방법으로 cosine similarity를 자주 씁니다. Cosine similarity는 두 vector가 같은 방향을 바라보는지 측정하는 값입니다. 의미가 비슷하면 방향이 비슷해지고 similarity가 높아지도록 학습합니다.

**예시**

아주 작은 2차원 vector로 생각해 봅시다.

- 텍스트 “apple”의 embedding: [0.9, 0.1]
- 사과 사진의 image embedding: [0.8, 0.2]
- 자동차 사진의 image embedding: [0.1, 0.9]

여기서 “apple”과 사과 사진은 숫자 방향이 비슷합니다. 둘 다 첫 번째 값이 크고 두 번째 값이 작습니다. 그래서 모델은 둘을 의미적으로 가깝다고 볼 수 있습니다.

반대로 자동차 사진은 [0.1, 0.9]라서 방향이 다릅니다. 따라서 “apple”과는 멀다고 판단해야 합니다.

이렇게 학습되어야 사용자가 “apple 사진 찾아 줘”라고 했을 때 사과 이미지를 찾을 수 있고, 사과 사진을 보여 주면 “이것은 apple입니다”라고 설명할 수 있습니다.

**실전 연결**

Cross-modal alignment는 CLIP, BLIP, LLaVA, GPT-4o, Gemini 같은 vision-language model에서 핵심입니다. 예를 들어 쇼핑 앱에서 사용자가 가방 사진을 올리고 “이것과 비슷한 상품 찾아 줘”라고 하면, 이미지 embedding과 상품 텍스트 embedding을 같은 공간에서 비교해야 합니다. 또 문서 OCR, 의료 영상 설명, 수학 문제 사진 풀이, 로봇 시각 인식에서도 이미지와 텍스트의 의미를 연결하는 능력이 필요합니다. 결국 멀티모달 AI가 “보고 말하는” 능력을 가지려면 cross-modal alignment가 기본 바탕이 됩니다.
