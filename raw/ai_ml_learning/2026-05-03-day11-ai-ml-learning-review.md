## 1. SVM과 최대 마진

### 한 줄 직관

SVM(support vector machine)은 두 그룹을 나누는 선을 그을 때, “가장 아슬아슬한 데이터들로부터 최대한 멀리 떨어진 선”을 고르는 모델입니다.

### 개념 정의

SVM은 분류(classification)를 위한 고전 머신러닝 모델입니다. 핵심 아이디어는 단순합니다. 데이터가 두 클래스, 예를 들어 “스팸 메일”과 “정상 메일”로 나뉘어 있을 때, 이 둘을 가르는 경계(decision boundary)를 찾습니다.

그런데 경계는 여러 개가 가능할 수 있습니다. SVM은 그중에서도 margin, 즉 경계와 가장 가까운 데이터 사이의 거리가 가장 큰 경계를 선택합니다. 이때 경계에 가장 가까이 붙어 있어서 결정에 큰 영향을 주는 데이터들을 support vector라고 부릅니다.

쉽게 말하면 SVM은 “가장 여유 있게 나누는 선”을 찾는 모델입니다. 여기서 여유가 바로 maximum margin입니다.

### 왜 이런 개념이 필요한가

분류 문제에서는 단순히 훈련 데이터를 맞히는 것만으로는 부족합니다. 훈련 데이터는 잘 맞혔지만 새 데이터에서 틀릴 수 있기 때문입니다. 예를 들어 시험 문제 10개를 외워서 맞힌 학생은 비슷한 새 문제가 나오면 틀릴 수 있습니다. 반대로 원리를 이해한 학생은 새 문제에도 강합니다.

SVM의 maximum margin은 이 “새 데이터에 강한 경계”를 만들기 위한 아이디어입니다. 경계가 데이터에 너무 바짝 붙어 있으면 조금만 노이즈가 생겨도 분류가 바뀝니다. 하지만 경계가 양쪽 데이터에서 넉넉히 떨어져 있으면 작은 변화에 덜 흔들립니다.

딥러닝에서도 비슷한 생각이 계속 나옵니다. 모델이 훈련 데이터만 외우지 않고 일반화(generalization)를 잘해야 합니다. margin은 일반화와 연결되는 중요한 직관입니다.

### 아주 쉬운 예시

1차원 숫자 예시를 보겠습니다.

- 클래스 A: 1, 2
- 클래스 B: 6, 7

A와 B를 나누는 기준값은 여러 개가 가능합니다.

- 기준값 3: 3보다 작으면 A, 크면 B
- 기준값 4: 4보다 작으면 A, 크면 B
- 기준값 5: 5보다 작으면 A, 크면 B

모두 훈련 데이터는 맞힙니다. 하지만 가장 가까운 점까지의 거리를 보면 다릅니다.

- 기준값 3: 가장 가까운 데이터는 2, 거리 1
- 기준값 4: 2까지 거리 2, 6까지 거리 2
- 기준값 5: 가장 가까운 데이터는 6, 거리 1

SVM의 관점에서는 기준값 4가 가장 좋습니다. 양쪽에서 가장 여유가 크기 때문입니다. 이 “가장 가까운 점까지의 최소 거리”를 크게 만드는 것이 maximum margin의 핵심입니다.

2차원에서는 기준값이 하나의 숫자가 아니라 선(line)이 됩니다. 더 높은 차원에서는 hyperplane이라고 부르는 평면 형태의 경계가 됩니다.

### 개념 구조와 핵심 포인트

- SVM은 분류 경계(decision boundary)를 찾는 모델입니다.
- 이 경계는 단순히 아무 경계가 아니라 margin이 최대가 되는 경계입니다.
- margin은 경계와 가장 가까운 훈련 데이터 사이의 거리입니다.
- support vector는 경계 근처에 있는 중요한 데이터 포인트입니다.
- 멀리 떨어진 데이터보다 support vector가 경계 결정에 더 큰 영향을 줍니다.
- 데이터가 직선으로 나뉘지 않을 때는 kernel trick을 사용할 수 있습니다.

kernel trick은 어려워 보이지만 직관은 간단합니다. 현재 공간에서는 나누기 어려운 데이터를 더 높은 차원의 공간에서 보면 나누기 쉬워질 수 있습니다. 예를 들어 종이 위에 섞여 있는 점들이 원 안과 원 밖으로 나뉘어 있다면, 직선 하나로는 나누기 어렵습니다. 하지만 “중심에서 얼마나 멀리 떨어져 있는가”라는 새 특징을 추가하면 더 쉽게 나눌 수 있습니다.

### 핵심 수학 포인트

가장 단순한 선형 SVM에서는 경계를 다음처럼 씁니다.

```text
w · x + b = 0
```

여기서 x는 데이터의 feature vector이고, w는 경계의 방향을 정하는 weight vector입니다. b는 bias입니다. `w · x`는 dot product입니다.

분류는 보통 부호로 결정됩니다.

```text
w · x + b > 0 이면 클래스 +1
w · x + b < 0 이면 클래스 -1
```

margin을 크게 만든다는 것은 이 경계가 양쪽 클래스에서 최대한 멀어지도록 w와 b를 고른다는 뜻입니다. 수학적으로는 벡터 크기(norm)와 관련됩니다. 실무에서는 “norm”이라는 영어 표현을 그대로 많이 씁니다. 여기서는 norm을 “벡터의 크기” 정도로 이해하면 충분합니다.

kernel trick의 핵심은 실제로 높은 차원의 좌표를 직접 만들지 않고도, kernel function으로 “높은 차원에서의 dot product와 같은 효과”를 계산하는 것입니다. 그래서 계산량을 줄이면서 복잡한 경계를 만들 수 있습니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- support vector machine: 최대 margin을 찾는 분류 모델입니다.
- maximum margin: 가장 가까운 데이터와 경계 사이의 최소 거리를 최대화하는 아이디어입니다.
- support vector: 결정 경계에 가장 가까워서 경계를 정하는 데 중요한 데이터 포인트입니다.
- decision boundary: 모델이 클래스를 나누는 경계입니다.
- hyperplane: 고차원 공간에서의 선형 경계입니다. 2차원에서는 선, 3차원에서는 평면처럼 생각할 수 있습니다.
- kernel trick: 데이터를 직접 높은 차원으로 바꾸지 않고도 높은 차원에서 분리하는 효과를 내는 방법입니다.
- norm: 벡터의 크기입니다. margin 계산에서 중요합니다.

### AI에서 어디에 쓰이는가

SVM은 딥러닝 이전에 텍스트 분류, 이미지 분류, 생물정보학, 문서 분류 등에서 매우 강력한 기본 모델이었습니다. 특히 데이터 수가 아주 많지 않고 feature가 잘 만들어져 있을 때 좋은 성능을 냈습니다.

LLM 시대에도 SVM의 관점은 여전히 중요합니다. 예를 들어 문장을 embedding으로 바꾸면 각 문장은 고차원 벡터가 됩니다. 이 embedding 벡터들을 어떤 기준으로 분류할 때 “두 클래스가 embedding 공간에서 얼마나 잘 떨어져 있는가”를 보는 것은 SVM의 margin 직관과 닮아 있습니다.

또한 contrastive learning이나 metric learning에서도 “비슷한 것은 가깝게, 다른 것은 멀게” 만드는 생각이 나옵니다. SVM의 margin은 이런 거리 기반 표현 학습을 이해하는 데 좋은 출발점입니다.

### 헷갈리기 쉬운 포인트

- SVM은 “항상 직선만 그리는 모델”이 아닙니다. 기본은 선형 경계지만 kernel trick을 쓰면 비선형 경계도 만들 수 있습니다.
- support vector는 모든 데이터가 아닙니다. 경계 근처의 핵심 데이터입니다.
- margin이 크다고 항상 무조건 좋은 것은 아닙니다. 데이터에 노이즈가 많으면 일부 오류를 허용하는 soft margin이 필요합니다.
- kernel trick은 데이터를 실제로 눈에 보이게 변환하는 것이라기보다, 높은 차원에서 계산한 것 같은 효과를 주는 계산 기법입니다.

## 2. KNN의 거리 기반 추론

### 한 줄 직관

KNN(K-nearest neighbors)은 새 데이터를 판단할 때 “가장 가까운 이웃 K개가 무엇인지”를 보고 따라가는 모델입니다.

### 개념 정의

KNN은 매우 직관적인 머신러닝 알고리즘입니다. 훈련 과정에서 복잡한 weight를 학습하지 않습니다. 대신 훈련 데이터를 저장해 두고, 새 데이터가 들어오면 기존 데이터 중에서 가장 가까운 K개를 찾습니다.

분류 문제에서는 가까운 이웃들이 가장 많이 속한 클래스로 새 데이터를 분류합니다. 회귀(regression) 문제에서는 가까운 이웃들의 평균값을 예측값으로 사용할 수 있습니다.

즉 KNN은 “이 데이터와 비슷한 과거 사례들은 어떤 답을 가졌는가?”라고 묻는 모델입니다.

### 왜 이런 개념이 필요한가

AI에서는 어떤 대상을 숫자 벡터로 표현한 뒤, 벡터 사이의 가까움으로 의미적 유사성을 판단하는 일이 많습니다. KNN은 이 생각을 가장 단순한 형태로 보여줍니다.

예를 들어 영화 추천을 한다고 합시다. 어떤 사용자가 액션 영화와 SF 영화를 좋아합니다. 이 사용자의 취향 벡터가 다른 사용자들과 가까우면, 가까운 사용자들이 좋아한 영화를 추천할 수 있습니다. 이것은 KNN과 매우 비슷한 사고방식입니다.

LLM에서도 embedding search, vector database, retrieval-augmented generation(RAG) 같은 기술이 KNN의 직관과 연결됩니다. 질문을 embedding으로 바꾸고, 문서들도 embedding으로 바꾼 뒤, 가장 가까운 문서를 찾아 LLM에게 보여주는 방식입니다.

### 아주 쉬운 예시

과일을 분류한다고 해봅시다. feature는 두 개만 사용합니다.

- x축: 무게
- y축: 단맛 점수

훈련 데이터가 다음과 같습니다.

| 과일 | 무게 | 단맛 | 라벨 |
|---|---:|---:|---|
| A | 100 | 8 | 사과 |
| B | 105 | 7 | 사과 |
| C | 180 | 3 | 자몽 |
| D | 190 | 4 | 자몽 |

새 과일 X가 있습니다.

- 무게: 102
- 단맛: 8

X는 A와 B에 매우 가깝고, C와 D에는 멉니다. K=3이라면 가장 가까운 이웃 3개를 찾습니다. 예를 들어 A, B, C가 선택되었다고 합시다.

- A: 사과
- B: 사과
- C: 자몽

다수결로 사과가 2표, 자몽이 1표입니다. 그래서 KNN은 X를 사과로 분류합니다.

거리 계산을 아주 단순하게 1차원으로 보면 더 쉽습니다.

- 훈련 데이터: 1(A), 2(A), 8(B), 9(B)
- 새 데이터: 3
- K=3

3과 가까운 숫자는 2(A), 1(A), 8(B)입니다. A가 2개, B가 1개이므로 새 데이터 3은 A로 분류됩니다.

### 개념 구조와 핵심 포인트

- KNN은 학습 단계가 거의 없는 lazy learning 방식입니다.
- 예측할 때 훈련 데이터와 새 데이터 사이의 거리를 계산합니다.
- K는 볼 이웃의 개수입니다.
- distance metric은 “가깝다”를 어떻게 정의할지 정하는 방법입니다.
- local neighborhood는 새 데이터 주변의 가까운 데이터 영역입니다.
- K가 너무 작으면 노이즈에 민감합니다.
- K가 너무 크면 가까운 이웃보다 먼 이웃까지 섞여서 지역적 패턴을 놓칠 수 있습니다.

KNN의 핵심은 “전체 규칙 하나를 강하게 가정하지 않고, 주변 사례를 본다”는 점입니다. 그래서 데이터의 모양이 복잡할 때도 어느 정도 대응할 수 있습니다. 하지만 데이터가 많아지면 예측할 때 매번 많은 거리 계산을 해야 하므로 느려질 수 있습니다.

### 핵심 수학 포인트

KNN에서 가장 중요한 수학은 거리(distance)입니다. 가장 흔한 거리는 Euclidean distance입니다.

2차원에서 두 점이 다음과 같다고 합시다.

```text
A = (1, 2)
B = (4, 6)
```

두 점 사이의 차이는 x축에서 3, y축에서 4입니다. 그래서 거리는 다음과 같습니다.

```text
sqrt(3^2 + 4^2) = sqrt(9 + 16) = 5
```

이것은 피타고라스 정리와 같습니다. 단순히 “직선거리”입니다.

하지만 모든 문제에서 Euclidean distance가 좋은 것은 아닙니다. 텍스트 embedding에서는 cosine similarity를 자주 씁니다. cosine similarity는 벡터의 길이보다 방향이 얼마나 비슷한지를 봅니다. 예를 들어 두 문장이 비슷한 주제를 말하면 embedding 방향이 비슷해질 수 있습니다.

KNN에서는 feature scale도 중요합니다. 예를 들어 키(cm)는 150~190 정도이고, 나이(year)는 1~100 정도인데, 소득은 0~100000000처럼 훨씬 클 수 있습니다. scale이 큰 feature가 거리 계산을 지배할 수 있으므로 normalization이나 standardization이 필요할 수 있습니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- KNN: K-nearest neighbors의 줄임말입니다. 가까운 K개의 이웃을 보고 예측합니다.
- distance metric: 두 데이터가 얼마나 가까운지 재는 기준입니다.
- local neighborhood: 새 데이터 주변의 가까운 데이터 영역입니다.
- Euclidean distance: 일반적인 직선거리입니다.
- cosine similarity: 두 벡터의 방향 유사도를 보는 방식입니다.
- lazy learning: 훈련 때 많은 계산을 하지 않고 예측 때 계산하는 방식입니다.
- feature scaling: 거리 계산이 특정 feature에 과하게 끌리지 않도록 scale을 맞추는 과정입니다.

### AI에서 어디에 쓰이는가

KNN 자체는 매우 단순하지만, 현대 AI의 여러 중요한 시스템과 연결됩니다.

첫째, embedding search입니다. 문장, 이미지, 사용자, 상품을 embedding vector로 바꾼 뒤 가까운 벡터를 찾습니다. 이때 “가까운 이웃을 찾는다”는 생각이 KNN과 같습니다.

둘째, RAG입니다. 사용자의 질문을 embedding으로 만들고, 문서 데이터베이스에서 가장 가까운 문서 조각을 찾아 LLM에 넣습니다. 이 과정은 사실상 “질문의 nearest neighbors 문서 찾기”입니다.

셋째, 추천 시스템입니다. 비슷한 사용자 또는 비슷한 아이템을 찾아 추천하는 방식은 KNN의 local neighborhood 직관과 닮아 있습니다.

넷째, 모델 디버깅에도 유용합니다. 어떤 데이터가 잘못 예측되었을 때 embedding 공간에서 가까운 샘플들을 보면, 모델이 무엇을 비슷하다고 보고 있는지 이해할 수 있습니다.

### 헷갈리기 쉬운 포인트

- KNN은 K-means와 다릅니다. KNN은 지도학습(supervised learning)이고, K-means는 비지도학습(clustering)입니다.
- KNN은 훈련을 안 한다고 해서 “학습이 없는 모델”이라는 뜻은 아닙니다. 훈련 데이터를 저장하고 예측 때 사용합니다.
- 거리 기준이 바뀌면 결과가 크게 바뀔 수 있습니다.
- feature scale을 맞추지 않으면 거리 계산이 왜곡될 수 있습니다.
- 고차원에서는 모든 점들이 비슷하게 멀어지는 문제가 생길 수 있습니다. 이를 curse of dimensionality라고 부릅니다.

## 3. 결정트리와 정보이득

### 한 줄 직관

결정트리(decision tree)는 질문을 하나씩 던지며 데이터를 나누는 모델이고, information gain은 “어떤 질문이 데이터를 가장 깔끔하게 나누는가”를 재는 기준입니다.

### 개념 정의

결정트리는 스무고개처럼 작동합니다. “나이가 30보다 큰가?”, “소득이 일정 수준 이상인가?”, “단어에 무료라는 표현이 들어 있는가?” 같은 질문을 차례대로 던집니다. 각 질문의 답에 따라 데이터는 가지(branch)를 따라 내려가고, 마지막 leaf node에서 예측이 나옵니다.

이때 중요한 문제는 “어떤 질문을 먼저 할 것인가?”입니다. 좋은 질문은 데이터를 더 순수하게 나눕니다. 예를 들어 스팸 메일 분류에서 “무료 쿠폰이라는 단어가 있는가?”라는 질문이 스팸과 정상 메일을 잘 나눈다면 좋은 질문입니다.

information gain은 질문을 던진 뒤 불확실성이 얼마나 줄었는지를 측정합니다. 불확실성이 많이 줄어드는 질문일수록 좋은 split입니다.

### 왜 이런 개념이 필요한가

머신러닝 모델은 데이터를 보고 예측 규칙을 찾아야 합니다. 결정트리는 이 규칙을 사람이 이해하기 쉬운 질문들의 조합으로 표현합니다. 그래서 해석 가능성(interpretability)이 좋습니다.

딥러닝 모델은 보통 수많은 weight로 이루어져 있어서 왜 그런 예측을 했는지 이해하기 어렵습니다. 반면 결정트리는 “이 feature가 이 값보다 커서 왼쪽으로 갔고, 다음 feature 조건을 만족해서 최종적으로 클래스 A가 되었다”처럼 설명할 수 있습니다.

또한 결정트리의 정보이득 개념은 “좋은 feature는 불확실성을 줄인다”는 매우 중요한 직관을 줍니다. 이 직관은 feature selection, classification loss, attention에서 중요한 token을 고르는 관점과도 느슨하게 연결됩니다.

### 아주 쉬운 예시

동물 분류를 해봅시다. 데이터가 6개 있습니다.

| 동물 | 날 수 있음? | 물에서 삶? | 라벨 |
|---|---|---|---|
| 참새 | 예 | 아니오 | 새 |
| 독수리 | 예 | 아니오 | 새 |
| 펭귄 | 아니오 | 예 | 새 |
| 고등어 | 아니오 | 예 | 물고기 |
| 상어 | 아니오 | 예 | 물고기 |
| 연어 | 아니오 | 예 | 물고기 |

처음에는 새 3개, 물고기 3개가 섞여 있습니다. 불확실성이 큽니다. 이제 질문을 하나 해봅니다.

질문 1: “날 수 있음?”

- 예: 참새, 독수리 → 모두 새
- 아니오: 펭귄, 고등어, 상어, 연어 → 새 1개, 물고기 3개

질문 1은 일부 데이터를 아주 깔끔하게 나눕니다.

질문 2: “물에서 삶?”

- 예: 펭귄, 고등어, 상어, 연어 → 새 1개, 물고기 3개
- 아니오: 참새, 독수리 → 모두 새

이 예시에서는 두 질문이 비슷한 정도로 도움을 줍니다. 하지만 실제 데이터에서는 어떤 질문이 훨씬 더 불확실성을 많이 줄일 수 있습니다. 결정트리는 그런 질문을 우선 선택하려고 합니다.

더 작은 숫자 예시로 entropy를 보겠습니다.

- 어떤 노드에 데이터 4개가 있음: A 2개, B 2개
- 반반이므로 매우 섞여 있음
- 좋은 split 후:
  - 왼쪽: A 2개
  - 오른쪽: B 2개

split 전에는 불확실성이 큽니다. split 후에는 각 그룹이 완전히 순수합니다. 이때 information gain이 큽니다.

### 개념 구조와 핵심 포인트

- 결정트리는 node와 branch로 이루어집니다.
- root node는 가장 처음 질문을 던지는 시작점입니다.
- internal node는 중간 질문입니다.
- leaf node는 최종 예측이 나오는 끝 지점입니다.
- split은 데이터를 어떤 조건으로 나누는 것입니다.
- entropy는 데이터가 얼마나 섞여 있는지를 재는 값입니다.
- information gain은 split 후 entropy가 얼마나 줄었는지입니다.
- Gini impurity도 데이터가 얼마나 섞여 있는지를 재는 다른 기준입니다.

좋은 결정트리는 적은 질문으로 데이터를 잘 나눕니다. 하지만 트리가 너무 깊어지면 훈련 데이터를 외워버릴 수 있습니다. 이것을 overfitting이라고 합니다. 그래서 max depth를 제한하거나, 너무 작은 split을 막거나, pruning을 사용하기도 합니다.

### 핵심 수학 포인트

entropy는 불확실성을 재는 값입니다. 클래스가 하나로만 이루어져 있으면 불확실성이 0입니다. 클래스가 반반 섞여 있으면 불확실성이 큽니다.

이진 분류에서 entropy는 다음 형태입니다.

```text
Entropy = - p(A) log2 p(A) - p(B) log2 p(B)
```

예를 들어 A와 B가 반반이면 p(A)=0.5, p(B)=0.5입니다.

```text
Entropy = -0.5 log2(0.5) -0.5 log2(0.5) = 1
```

완전히 A만 있으면 p(A)=1, p(B)=0입니다. 이때 entropy는 0입니다. 즉 섞여 있지 않으면 불확실성이 없습니다.

information gain은 이렇게 생각하면 됩니다.

```text
Information gain = split 전 entropy - split 후 가중평균 entropy
```

예를 들어 split 전 entropy가 1이고, split 후 두 그룹이 모두 순수해서 entropy가 0이면 information gain은 1입니다. 매우 좋은 split입니다.

Gini impurity도 비슷한 목적입니다. 이진 분류에서는 대략 다음처럼 봅니다.

```text
Gini = 1 - p(A)^2 - p(B)^2
```

반반이면 Gini = 1 - 0.25 - 0.25 = 0.5입니다. 한 클래스만 있으면 Gini = 0입니다. entropy와 마찬가지로 작을수록 더 순수합니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- decision tree: 질문을 순서대로 던져 예측하는 트리 구조 모델입니다.
- root node: 트리의 시작 질문입니다.
- internal node: 중간 질문 노드입니다.
- leaf node: 최종 예측이 나오는 끝 노드입니다.
- split: feature 조건으로 데이터를 나누는 과정입니다.
- entropy: 데이터가 얼마나 섞여 있고 불확실한지 재는 값입니다.
- information gain: split으로 entropy가 얼마나 줄었는지입니다.
- Gini impurity: 데이터의 섞임 정도를 재는 또 다른 기준입니다.
- pruning: 트리가 너무 복잡해지는 것을 줄이는 과정입니다.

### AI에서 어디에 쓰이는가

결정트리는 단독으로도 쓰이지만, 실제로는 Random Forest, Gradient Boosting, XGBoost, LightGBM, CatBoost 같은 강력한 모델들의 기반입니다. 특히 표 형태 데이터(tabular data)에서는 지금도 트리 기반 모델이 매우 강합니다.

딥러닝과 비교하면 결정트리는 feature의 조건 분기를 명확히 보여줍니다. 그래서 모델이 어떤 feature를 중요하게 보는지 이해하는 데 도움이 됩니다. 예를 들어 신용평가 모델에서 “연체 이력”, “소득”, “부채 비율”이 어떤 순서로 판단에 쓰였는지 설명하기 좋습니다.

LLM과 직접 같은 구조는 아니지만, “불확실성을 줄이는 질문을 고른다”는 관점은 중요합니다. 예를 들어 attention은 모든 token을 똑같이 보지 않고 중요한 token에 더 큰 weight를 줍니다. 결정트리의 split 선택도 “어떤 feature가 지금 예측에 가장 도움이 되는가?”를 고르는 과정이라고 볼 수 있습니다.

### 헷갈리기 쉬운 포인트

- 결정트리는 단순히 사람이 만든 if문이 아닙니다. 데이터에서 좋은 split을 자동으로 찾습니다.
- information gain은 정확도 자체가 아니라 불확실성 감소량입니다.
- entropy가 높다는 것은 데이터가 많이 섞여 있다는 뜻입니다.
- Gini impurity와 entropy는 목적이 비슷하지만 계산 방식이 다릅니다.
- 트리가 깊을수록 항상 좋은 것은 아닙니다. 너무 깊으면 overfitting이 생길 수 있습니다.

## 복습 질문 정답

[AI/ML 오늘의 복습 정답 Day 11/30]

오늘은 고전 머신러닝 모델인 SVM, KNN, 결정트리의 핵심 직관을 복습합니다.

### 1. SVM에서 margin을 크게 만들면 새 데이터에 더 강해질 수 있는 이유는 무엇인가요?

**정답**

SVM에서 margin을 크게 만들면 decision boundary, 즉 분류 경계가 양쪽 클래스의 데이터로부터 더 멀리 떨어집니다. 그래서 새 데이터가 조금 흔들리거나 노이즈가 섞여도 쉽게 반대 클래스로 잘못 분류되지 않습니다.

즉, margin이 크다는 것은 “분류 기준선 주변에 여유 공간이 많다”는 뜻이고, 이 여유가 클수록 모델이 훈련 데이터만 외우는 대신 새 데이터에도 더 안정적으로 반응할 가능성이 커집니다.

**설명**

SVM, 즉 support vector machine은 두 클래스를 나누는 경계를 찾는 모델입니다. 그런데 가능한 경계는 여러 개일 수 있습니다. SVM은 그중에서 가장 가까운 데이터들과의 거리가 최대가 되는 경계를 고르려고 합니다. 이 거리를 margin이라고 합니다.

margin이 작으면 경계가 데이터에 너무 바짝 붙어 있는 상태입니다. 이런 경우 새 데이터가 아주 조금만 달라져도 경계 반대편으로 넘어갈 수 있습니다. 예를 들어 측정 오차, 노이즈, 약간 다른 입력값 때문에 분류 결과가 쉽게 바뀔 수 있습니다.

반대로 margin이 크면 경계와 데이터 사이에 완충 지대가 생깁니다. 이 완충 지대 덕분에 새 데이터가 조금 달라져도 같은 쪽에 남아 있을 가능성이 큽니다. 그래서 SVM의 maximum margin 아이디어는 generalization, 즉 훈련에 없던 새 데이터에도 잘 맞는 능력과 연결됩니다.

여기서 중요한 데이터는 support vector입니다. support vector는 경계에 가장 가까운 데이터 포인트들입니다. SVM은 멀리 떨어진 모든 데이터보다, 경계 근처의 support vector들을 기준으로 “어디에 선을 그어야 가장 여유가 큰가?”를 결정합니다.

**예시**

숫자 하나로 두 클래스를 나눈다고 해봅시다.

- 클래스 A: 1, 2
- 클래스 B: 6, 7

A와 B를 나누는 기준값은 3, 4, 5 모두 가능합니다.

하지만 기준값 3은 A의 2와 너무 가깝습니다. 거리 여유가 1뿐입니다. 기준값 5는 B의 6과 너무 가깝습니다. 역시 거리 여유가 1입니다.

기준값 4는 A의 2와도 거리 2, B의 6과도 거리 2입니다. 양쪽에서 가장 여유가 큽니다. 만약 새 데이터가 5.8처럼 약간 흔들려 들어와도 여전히 B 쪽으로 볼 가능성이 높습니다. 그래서 기준값 4가 더 안정적인 경계입니다.

**실전 연결**

실제 ML에서는 훈련 데이터를 100% 맞히는 것보다 새 데이터에서 잘 작동하는 것이 더 중요합니다. SVM의 margin 개념은 이 generalization을 이해하는 좋은 출발점입니다. LLM이나 딥러닝에서도 embedding 공간에서 서로 다른 클래스나 의미가 얼마나 잘 떨어져 있는지를 볼 때 margin과 비슷한 직관이 쓰입니다. 예를 들어 스팸 문장 embedding과 정상 문장 embedding이 넉넉히 떨어져 있으면, 새 문장이 들어와도 더 안정적으로 분류할 수 있습니다.

### 2. KNN에서 K 값을 너무 작게 또는 너무 크게 잡으면 각각 어떤 문제가 생길 수 있나요?

**정답**

KNN에서 K 값을 너무 작게 잡으면 가까운 몇 개의 데이터에만 크게 영향을 받아서 노이즈에 민감해집니다. 특히 K=1이면 가장 가까운 데이터 하나가 틀리거나 이상한 값이어도 그대로 따라갈 수 있습니다.

반대로 K 값을 너무 크게 잡으면 너무 먼 이웃들까지 판단에 포함됩니다. 그러면 새 데이터 주변의 local neighborhood, 즉 가까운 주변 패턴을 놓치고 전체 평균에 가까운 둔한 판단을 할 수 있습니다.

**설명**

KNN은 K-nearest neighbors의 줄임말입니다. 새 데이터가 들어왔을 때 훈련 데이터 중 가장 가까운 K개의 이웃을 찾고, 그 이웃들의 라벨을 보고 예측합니다.

여기서 K는 “몇 명의 이웃에게 물어볼 것인가?”를 정하는 값입니다.

K가 너무 작으면 판단 기준이 너무 예민해집니다. 예를 들어 K=1이면 가장 가까운 데이터 하나만 보고 결정합니다. 그런데 그 데이터가 우연히 잘못 라벨링되었거나, 특이한 outlier라면 새 데이터도 잘못 분류됩니다. 이것은 노이즈에 약한 상태입니다.

K가 너무 크면 반대로 판단이 너무 둔해집니다. 가까운 이웃뿐 아니라 멀리 떨어진 데이터까지 포함되기 때문입니다. 그러면 새 데이터 근처에서는 클래스 A가 많은데, 멀리 있는 클래스 B들이 많이 섞여 들어와 결과가 바뀔 수 있습니다. 즉, K가 너무 크면 local pattern을 잃어버립니다.

KNN에서는 K뿐 아니라 distance metric도 중요합니다. distance metric은 두 데이터가 얼마나 가까운지 재는 방법입니다. 숫자 데이터에서는 Euclidean distance, 즉 직선거리를 자주 쓰고, 텍스트 embedding에서는 cosine similarity를 자주 씁니다. cosine similarity는 두 벡터의 방향이 얼마나 비슷한지를 보는 기준입니다.

**예시**

아주 작은 1차원 예시를 보겠습니다.

- 훈련 데이터: 1(A), 2(A), 3(B), 8(B), 9(B)
- 새 데이터: 2.5

K=1이면 가장 가까운 데이터는 3(B)일 수 있습니다. 그러면 새 데이터는 B로 분류됩니다. 하지만 주변을 조금 넓게 보면 1(A), 2(A), 3(B)이 있어서 A가 2개, B가 1개입니다.

K=3이면 새 데이터는 A로 분류됩니다. 이 경우 K=1보다 조금 더 안정적입니다.

그런데 K=5로 모든 데이터를 다 보면 A는 2개, B는 3개입니다. 그러면 새 데이터는 B로 분류됩니다. 하지만 8(B), 9(B)는 새 데이터 2.5와 꽤 멉니다. 너무 먼 이웃까지 포함해서 주변 패턴을 흐리게 만든 것입니다.

**실전 연결**

KNN의 직관은 현대 AI에서도 매우 중요합니다. 특히 embedding search, vector database, RAG에서 자주 등장합니다. RAG에서는 사용자의 질문을 embedding vector로 바꾼 뒤, 가장 가까운 문서 조각들을 찾아 LLM에게 제공합니다. 이때 너무 적은 문서만 가져오면 중요한 정보를 놓치거나 노이즈 문서 하나에 휘둘릴 수 있습니다. 반대로 너무 많은 문서를 가져오면 관련 없는 내용까지 섞여 LLM의 답변 품질이 떨어질 수 있습니다. 그래서 “가까운 이웃을 몇 개 볼 것인가?”는 실제 시스템 성능에 직접 영향을 줍니다.

### 3. 결정트리에서 information gain이 크다는 것은 split 전후로 무엇이 많이 줄었다는 뜻인가요?

**정답**

결정트리에서 information gain이 크다는 것은 split 전후로 entropy, 즉 데이터의 불확실성 또는 섞임 정도가 많이 줄었다는 뜻입니다.

쉽게 말해, split 전에는 여러 클래스가 섞여 있어서 헷갈렸는데, split 후에는 각 그룹이 더 순수해졌다는 의미입니다.

**설명**

결정트리, 즉 decision tree는 질문을 하나씩 던지며 데이터를 나누는 모델입니다. 예를 들어 “나이가 30보다 큰가?”, “무료라는 단어가 들어 있는가?”, “구매 횟수가 3회 이상인가?” 같은 질문을 던지고, 답에 따라 데이터를 왼쪽 또는 오른쪽 가지로 보냅니다.

이때 중요한 것은 “어떤 질문을 먼저 던질 것인가?”입니다. 좋은 질문은 데이터를 깔끔하게 나눕니다. 예를 들어 스팸 메일과 정상 메일이 섞여 있을 때, “무료 쿠폰이라는 단어가 있는가?”라는 질문으로 스팸이 한쪽에 많이 모이고 정상 메일이 다른 쪽에 많이 모이면 좋은 split입니다.

entropy는 데이터가 얼마나 섞여 있는지를 재는 값입니다. 한 노드 안에 A와 B가 반반 섞여 있으면 entropy가 큽니다. 반대로 한 노드 안에 A만 있거나 B만 있으면 entropy는 0에 가깝습니다. 즉, 불확실성이 거의 없습니다.

information gain은 split 전 entropy에서 split 후 entropy를 뺀 값입니다.

다시 말하면:

Information gain = split 전 불확실성 - split 후 불확실성

따라서 information gain이 크다는 것은 어떤 질문을 던진 뒤 데이터가 훨씬 덜 섞이게 되었고, 예측하기 쉬운 상태가 되었다는 뜻입니다.

Gini impurity도 비슷한 역할을 합니다. Gini impurity 역시 데이터가 얼마나 섞여 있는지를 재는 기준입니다. entropy와 계산 방식은 다르지만, 둘 다 “나눈 뒤 얼마나 순수해졌는가?”를 보기 위해 사용됩니다.

**예시**

데이터 4개가 있다고 해봅시다.

- split 전: A 2개, B 2개

이 상태는 반반 섞여 있습니다. 새 데이터가 이 노드에 오면 A인지 B인지 확신하기 어렵습니다. entropy가 높은 상태입니다.

이제 어떤 질문으로 split했더니 이렇게 나뉘었다고 합시다.

- 왼쪽: A 2개
- 오른쪽: B 2개

이제 왼쪽은 전부 A이고, 오른쪽은 전부 B입니다. 각 그룹 안에는 섞임이 없습니다. split 후 entropy가 크게 줄었습니다. 그래서 이 split의 information gain은 큽니다.

반대로 split 후에도 이렇게 나뉘었다고 해봅시다.

- 왼쪽: A 1개, B 1개
- 오른쪽: A 1개, B 1개

그러면 양쪽 모두 여전히 반반입니다. 불확실성이 거의 줄지 않았습니다. 이런 split은 information gain이 작습니다.

**실전 연결**

information gain은 결정트리가 좋은 feature와 좋은 split을 고르는 핵심 기준입니다. 이 개념은 Random Forest, XGBoost, LightGBM 같은 강력한 트리 기반 모델을 이해할 때도 중요합니다. 특히 표 형태 데이터, 즉 tabular data에서는 이런 트리 기반 모델이 지금도 매우 많이 쓰입니다. LLM과 구조는 다르지만, “어떤 정보가 불확실성을 줄이는 데 도움이 되는가?”라는 관점은 attention이나 feature importance를 이해할 때도 연결됩니다. 모델이 모든 정보를 똑같이 보는 것이 아니라, 예측에 더 도움이 되는 정보를 더 중요하게 보는 것입니다.
