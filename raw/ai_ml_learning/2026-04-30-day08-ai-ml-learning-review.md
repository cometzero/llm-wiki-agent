## 1. 과적합과 과소적합의 구조

### 한 줄 직관

모델 학습은 시험 공부와 비슷합니다. 원리를 이해하면 새 문제도 풀지만, 답안지만 외우면 연습 문제는 맞혀도 새 문제에서 틀립니다. 답안지만 외운 상태가 과적합(overfitting)이고, 원리도 제대로 못 배운 상태가 과소적합(underfitting)입니다.

### 개념 정의

과적합(overfitting)은 모델이 학습 데이터(training data)에 너무 딱 맞게 적응해서, 학습 데이터 안의 우연한 노이즈(noise)나 특이한 패턴까지 정답처럼 외워 버리는 현상입니다. 이때 학습 데이터에서는 loss가 낮고 정확도가 높지만, 새로운 데이터(test data 또는 validation data)에서는 성능이 떨어집니다.

과소적합(underfitting)은 반대로 모델이 데이터의 기본적인 규칙조차 충분히 배우지 못한 상태입니다. 모델이 너무 단순하거나, 학습이 부족하거나, 입력 특징(feature)이 부족할 때 생깁니다. 이 경우 학습 데이터에서도 성능이 낮고, 새로운 데이터에서도 당연히 성능이 낮습니다.

여기서 핵심은 “학습 데이터에 잘 맞는다”와 “새 데이터에 잘 일반화한다(generalize)”가 같은 말이 아니라는 점입니다. 머신러닝의 목표는 학습 데이터를 완벽히 외우는 것이 아니라, 아직 보지 못한 데이터에서도 좋은 예측을 하는 것입니다.

### 왜 이런 개념이 필요한가

AI 모델은 항상 제한된 데이터로 학습합니다. 예를 들어 고양이 사진 1,000장으로 학습한 모델을 실제 서비스에 넣으면, 모델은 학습 때 보지 못한 조명, 각도, 품종, 배경을 만납니다. 모델이 학습 사진을 외웠다면 새로운 고양이를 놓칠 수 있습니다.

딥러닝과 LLM에서도 똑같습니다. LLM이 특정 문장을 통째로 외우면 benchmark나 학습 데이터에서는 좋아 보일 수 있지만, 실제 사용자가 조금 다르게 물어보면 틀릴 수 있습니다. 반대로 모델이 너무 작거나 학습이 부족하면 언어의 기본 패턴도 제대로 잡지 못합니다.

그래서 실전에서는 training loss만 보지 않습니다. validation loss, test accuracy, held-out set 성능을 함께 봅니다. “모델이 진짜 배웠는가, 아니면 외웠는가?”를 확인하기 위해서입니다.

### 아주 쉬운 예시

점 3개가 있다고 해봅시다.

- 입력 x: 1, 2, 3
- 정답 y: 2, 4, 6

이 데이터는 사실 `y = 2x`라는 아주 단순한 규칙입니다.

1. 적절한 모델은 `y = 2x`를 배웁니다. 그러면 x=4가 들어왔을 때 y=8이라고 예측할 수 있습니다.
2. 과소적합 모델은 너무 단순해서 항상 y=4만 말한다고 해봅시다. x=1에서도 4, x=3에서도 4라고 하니 학습 데이터도 잘 못 맞힙니다.
3. 과적합 모델은 세 점을 지나기 위해 이상하게 구불구불한 곡선을 만들 수 있습니다. x=1,2,3은 완벽히 맞추지만, x=4에서는 갑자기 y=100 같은 이상한 값을 낼 수 있습니다.

작은 숫자로 보면 과적합은 “지나치게 복잡한 설명”이고, 과소적합은 “너무 대충인 설명”입니다.

### 개념 구조와 핵심 포인트

- 학습 성능은 좋은데 검증 성능이 나쁘면 과적합(overfitting)을 의심합니다.
- 학습 성능과 검증 성능이 모두 나쁘면 과소적합(underfitting)을 의심합니다.
- 모델이 너무 복잡하거나 데이터가 적으면 과적합이 쉬워집니다.
- 모델이 너무 단순하거나 학습 시간이 부족하면 과소적합이 쉬워집니다.
- 좋은 모델은 학습 데이터의 핵심 패턴은 배우되, 우연한 노이즈까지 외우지 않아야 합니다.

실전에서는 learning curve를 봅니다. epoch이 늘어날수록 training loss는 계속 내려가는데 validation loss가 어느 순간부터 올라가면, 그 지점부터 모델이 데이터의 일반 규칙보다 학습 데이터의 세부사항을 외우기 시작했다고 볼 수 있습니다.

### 핵심 수학 포인트

아주 단순하게 말하면, 모델의 예측 오차는 두 가지 성격을 가집니다.

- bias: 모델이 기본 규칙을 얼마나 놓치는가
- variance: 학습 데이터가 조금 바뀌었을 때 모델 예측이 얼마나 흔들리는가

과소적합은 보통 bias가 큰 상태입니다. 모델이 너무 단순해서 진짜 규칙에 가까이 가지 못합니다. 과적합은 보통 variance가 큰 상태입니다. 데이터 샘플이 조금만 바뀌어도 모델이 크게 달라집니다.

예를 들어 `y = 2x`를 배워야 하는데 항상 y=4라고 예측하면 bias가 큽니다. 반대로 점 몇 개마다 복잡하게 꺾이는 곡선을 만들면 training error는 작아도 variance가 커질 수 있습니다.

수식보다 중요한 직관은 이것입니다. “오차가 낮다”는 말은 반드시 “일반화가 좋다”는 뜻이 아닙니다. 어떤 데이터에서 측정한 오차인지가 중요합니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- overfitting: 학습 데이터에 과하게 맞아서 새 데이터 성능이 떨어지는 현상
- underfitting: 학습 데이터의 기본 규칙도 충분히 배우지 못한 현상
- bias: 모델의 가정이 실제 규칙에서 벗어나는 정도
- variance: 학습 데이터 변화에 따라 모델 예측이 흔들리는 정도
- generalization: 보지 못한 데이터에도 잘 작동하는 능력
- training loss: 학습 데이터에서 계산한 손실
- validation loss: 모델 선택과 점검을 위해 따로 둔 데이터에서 계산한 손실

### AI에서 어디에 쓰이는가

이미지 분류 모델에서 training accuracy가 99%인데 validation accuracy가 70%라면 과적합일 가능성이 큽니다. 모델이 배경, 촬영 기기, 특정 데이터셋의 습관까지 외웠을 수 있습니다.

LLM에서는 더 미묘합니다. 모델이 학습 데이터에 있던 문장을 그대로 기억하면 특정 질문에는 매우 잘 답하지만, 새 조합의 reasoning 문제에서는 약할 수 있습니다. 그래서 데이터 중복 제거, validation benchmark, instruction tuning 평가가 중요합니다.

embedding 모델에서도 과적합은 생깁니다. 예를 들어 상품 검색 embedding을 만들 때 학습 데이터에 있던 상품명 조합만 외우면, 새 상품이나 새로운 표현의 검색어를 잘 연결하지 못합니다. 좋은 embedding은 표면 단어만이 아니라 의미적으로 가까운 hidden state 표현을 만들어야 합니다.

### 헷갈리기 쉬운 포인트

- training loss가 낮다고 무조건 좋은 모델은 아닙니다. validation/test 성능을 봐야 합니다.
- 과적합은 모델이 “똑똑하다”는 뜻이 아니라 “학습 데이터에 너무 맞춰졌다”는 뜻입니다.
- 과소적합은 데이터가 부족해서만 생기는 것이 아닙니다. 모델이 너무 작거나 학습 설정이 나빠도 생깁니다.
- 딥러닝 모델은 크다고 항상 과적합되는 것은 아닙니다. 데이터 규모, 정규화, optimizer, early stopping, pretraining 방식에 따라 달라집니다.

## 2. Bias-Variance Tradeoff

### 한 줄 직관

Bias-Variance Tradeoff는 “너무 단순하면 큰 흐름을 놓치고, 너무 민감하면 작은 잡음까지 따라간다”는 균형 문제입니다.

### 개념 정의

Bias-Variance Tradeoff는 모델의 예측 오류를 이해하는 중요한 틀입니다. bias는 모델이 너무 단순하거나 잘못된 가정을 해서 실제 규칙을 놓치는 오차입니다. variance는 모델이 학습 데이터의 작은 차이에 너무 민감해서 예측이 흔들리는 오차입니다.

tradeoff라는 말은 둘 사이에 균형이 필요하다는 뜻입니다. 모델을 복잡하게 만들면 bias는 줄어들 수 있습니다. 더 다양한 패턴을 표현할 수 있기 때문입니다. 하지만 너무 복잡해지면 variance가 커질 수 있습니다. 데이터의 우연한 흔들림까지 따라가기 때문입니다.

반대로 모델을 단순하게 만들면 variance는 줄어들 수 있습니다. 예측이 안정적이기 때문입니다. 하지만 너무 단순하면 bias가 커져서 실제 규칙을 제대로 표현하지 못합니다.

### 왜 이런 개념이 필요한가

머신러닝에서 우리는 단순히 “더 큰 모델이 좋다” 또는 “더 단순한 모델이 좋다”라고 말할 수 없습니다. 데이터 양, 노이즈, 문제 난이도, regularization, 학습 시간에 따라 적절한 복잡도가 다릅니다.

예를 들어 집값 예측 모델을 만든다고 해봅시다. 집 크기만 쓰는 모델은 너무 단순할 수 있습니다. 위치, 층수, 연식, 역세권 여부를 넣으면 bias가 줄어듭니다. 하지만 집 주소의 마지막 숫자, 사진 파일 이름, 우연히 데이터에 들어간 광고 문구 같은 의미 없는 feature까지 쓰면 variance가 커질 수 있습니다.

딥러닝에서는 이 균형이 더 중요합니다. neural network는 매우 복잡한 함수를 표현할 수 있기 때문에 training data를 외울 힘이 있습니다. 그래서 model capacity, regularization, data augmentation, validation monitoring을 함께 사용합니다.

### 아주 쉬운 예시

시험 점수를 예측한다고 해봅시다. 입력은 공부 시간 x, 출력은 점수 y입니다.

데이터가 이렇게 있다고 합시다.

- 1시간 공부 → 50점
- 2시간 공부 → 60점
- 3시간 공부 → 70점
- 4시간 공부 → 80점

실제 규칙은 대략 “1시간 늘면 10점 증가”입니다.

- bias가 큰 모델: 항상 65점이라고 예측합니다. 안정적이지만 공부 시간이 늘어나는 규칙을 무시합니다.
- variance가 큰 모델: 1시간은 50점, 2시간은 60점, 3시간은 70점, 4시간은 80점을 정확히 맞추려고 아주 복잡한 곡선을 만듭니다. 그런데 2.5시간 공부한 사람에게 갑자기 95점이라고 예측할 수 있습니다.
- 균형 잡힌 모델: `점수 = 40 + 10 × 공부시간` 정도를 배웁니다. 학습 점수도 꽤 맞고, 새 입력에도 자연스럽게 예측합니다.

### 개념 구조와 핵심 포인트

Bias-Variance Tradeoff의 핵심 구조는 다음과 같습니다.

1. 모델이 너무 단순하다.
   - 표현력이 부족합니다.
   - training error가 높습니다.
   - bias가 큽니다.
   - underfitting이 생기기 쉽습니다.

2. 모델이 적절히 복잡하다.
   - 핵심 패턴을 배웁니다.
   - training error와 validation error가 모두 낮아집니다.
   - 일반화가 좋습니다.

3. 모델이 너무 복잡하다.
   - 학습 데이터의 노이즈까지 따라갑니다.
   - training error는 매우 낮지만 validation error가 높아질 수 있습니다.
   - variance가 큽니다.
   - overfitting이 생기기 쉽습니다.

중요한 점은 bias와 variance가 완전히 따로 움직이지 않는다는 것입니다. 모델 복잡도, 데이터 수, regularization strength, optimizer, 학습 epoch이 함께 영향을 줍니다.

### 핵심 수학 포인트

회귀 문제에서 예측 오차를 직관적으로 나누면 다음과 같이 볼 수 있습니다.

`예상 테스트 오차 ≈ bias² + variance + noise`

여기서 noise는 데이터 자체에 들어 있는 설명 불가능한 흔들림입니다. 예를 들어 같은 공부 시간을 가진 두 사람이 컨디션 때문에 다른 점수를 받을 수 있습니다. 모델이 아무리 좋아도 이런 부분은 완전히 없앨 수 없습니다.

bias²는 모델의 평균 예측이 진짜 정답에서 얼마나 떨어져 있는지를 뜻합니다. variance는 학습 데이터를 다르게 뽑았을 때 예측이 얼마나 달라지는지를 뜻합니다.

아주 작은 숫자로 보면:

- 실제 정답이 10이라고 합시다.
- 어떤 모델이 여러 번 학습해도 항상 6 근처를 예측하면 안정적이지만 틀립니다. bias가 큽니다.
- 다른 모델이 2, 10, 18처럼 매번 크게 흔들리면 평균은 10일 수도 있지만 예측이 불안정합니다. variance가 큽니다.

이 관점은 모델을 고칠 때 도움이 됩니다. bias가 문제라면 모델을 더 표현력 있게 만들거나 feature를 개선해야 합니다. variance가 문제라면 regularization, 더 많은 데이터, data augmentation, early stopping을 고려합니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- bias-variance tradeoff: 단순함에서 오는 오차와 민감함에서 오는 오차 사이의 균형
- variance error: 학습 데이터 변화에 따라 예측이 흔들려 생기는 오류
- approximation error: 모델 구조가 실제 함수를 충분히 표현하지 못해서 생기는 오류. bias와 연결해서 이해할 수 있음
- irreducible noise: 데이터 자체의 우연성 때문에 줄이기 어려운 오차
- model capacity: 모델이 얼마나 복잡한 패턴을 표현할 수 있는지의 능력

### AI에서 어디에 쓰이는가

모델 선택(model selection)에서 가장 자주 쓰입니다. 작은 linear model이 계속 낮은 성능을 보이면 bias가 큰 것일 수 있습니다. 더 깊은 neural network, 더 좋은 feature, pre-trained model을 써야 할 수 있습니다.

반대로 큰 transformer를 작은 데이터셋에 fine-tuning할 때 validation 성능이 빠르게 나빠지면 variance 문제가 커진 것입니다. 이때는 learning rate를 낮추거나, weight decay를 넣거나, dropout을 쓰거나, early stopping을 적용할 수 있습니다.

attention 모델에서도 비슷합니다. 모델이 학습 데이터의 특정 token 위치나 문장 패턴에만 과하게 의존하면 새 문장 구조에서 약해질 수 있습니다. 좋은 모델은 hidden states 안에 더 일반적인 의미 패턴을 담아야 합니다.

### 헷갈리기 쉬운 포인트

- bias는 사회적 편향만 뜻하는 말이 아닙니다. 여기서는 모델 예측이 구조적으로 한쪽으로 틀어지는 수학적 의미입니다.
- variance는 데이터 분산 자체만 말하는 것이 아니라, 학습 데이터가 바뀔 때 모델 예측이 얼마나 흔들리는지를 말합니다.
- 큰 모델은 항상 variance만 큰 것이 아닙니다. 대규모 pretraining과 충분한 데이터가 있으면 큰 모델도 잘 일반화할 수 있습니다.
- noise는 모델이 배울 수 있는 규칙과 다릅니다. 모든 오차를 모델 탓으로 보면 안 됩니다.

## 3. 정규화와 모델 복잡도 제어

### 한 줄 직관

정규화(regularization)는 모델에게 “정답을 맞히되, 너무 복잡한 방법으로 억지로 맞히지는 말라”고 주는 부드러운 제약입니다.

### 개념 정의

정규화(regularization)는 모델이 학습 데이터에 과하게 맞춰지는 것을 막기 위해 loss에 추가 제약을 넣거나 학습 과정을 조절하는 방법입니다. 핵심 목표는 모델 복잡도를 제어해서 일반화 성능을 높이는 것입니다.

가장 대표적인 방식은 loss에 penalty를 더하는 것입니다. 예를 들어 모델의 weight 값이 너무 커지면 penalty를 주는 방식이 있습니다. weight는 neural network가 입력 feature를 얼마나 강하게 사용할지 정하는 숫자입니다. weight가 너무 커지면 모델이 특정 feature에 과하게 의존할 수 있습니다.

L2 penalty는 weight의 제곱 크기를 벌점으로 더합니다. 딥러닝에서는 weight decay라는 이름으로 자주 쓰입니다. L1 penalty는 weight의 절댓값 크기를 벌점으로 더합니다. L1은 일부 weight를 정확히 0에 가깝게 만들어 feature selection 효과를 낼 수 있습니다.

### 왜 이런 개념이 필요한가

모델은 학습 loss를 줄이려고 합니다. 그런데 loss만 줄이라고 하면 모델은 때때로 매우 복잡한 방식으로 학습 데이터를 맞힙니다. 예를 들어 어떤 이미지 분류 모델이 “고양이 귀 모양”이 아니라 “사진 구석의 특정 워터마크”를 보고 고양이라고 판단할 수도 있습니다.

정규화는 이런 억지 맞춤을 줄입니다. 모델이 너무 큰 weight나 너무 복잡한 결정 경계를 만들지 않도록 유도합니다. 즉, 정규화는 모델이 더 단순하고 안정적인 규칙을 선호하게 만드는 장치입니다.

LLM fine-tuning에서도 정규화는 중요합니다. 작은 데이터로 큰 모델을 fine-tuning하면 모델이 특정 답변 스타일이나 예시 문장을 외우기 쉽습니다. weight decay, dropout, early stopping, 데이터 다양화는 이런 문제를 줄이는 데 도움을 줍니다.

### 아주 쉬운 예시

집값을 예측하는 아주 작은 모델을 생각해봅시다.

`예측 집값 = 10 × 방 개수 + 500 × 우연히 붙은 데이터 ID`

여기서 “데이터 ID”는 실제 집값과 관련이 없어야 합니다. 그런데 학습 데이터에서 우연히 ID가 큰 집들이 비쌌다면 모델이 ID에 weight 500을 줄 수 있습니다. 학습 데이터는 잘 맞을지 몰라도 새 데이터에서는 망가질 가능성이 큽니다.

정규화를 넣으면 모델에게 이렇게 말하는 셈입니다.

“정답을 맞히는 것도 중요하지만, weight를 너무 크게 만들면 벌점을 줄게.”

그러면 모델은 `500 × 데이터 ID`처럼 불안정한 의존을 줄이고, 방 개수나 위치처럼 더 의미 있는 feature를 사용하려고 합니다.

숫자로 보면 원래 loss가 5라고 합시다. 그런데 weight가 10과 500이라면 L2 penalty는 `10² + 500² = 100 + 250000`처럼 매우 커집니다. 실제 구현에서는 여기에 작은 계수 λ(lambda)를 곱하지만, 큰 weight가 강하게 벌점을 받는다는 직관은 같습니다.

### 개념 구조와 핵심 포인트

정규화는 크게 다음 방식으로 이해할 수 있습니다.

1. loss에 penalty 추가
   - L1 penalty: weight 절댓값의 합을 벌점으로 사용합니다.
   - L2 penalty: weight 제곱의 합을 벌점으로 사용합니다.
   - weight decay: 딥러닝 optimizer에서 L2와 비슷한 효과로 weight를 조금씩 줄이는 방식입니다.

2. 학습 과정 제어
   - early stopping: validation loss가 나빠지기 전에 학습을 멈춥니다.
   - dropout: 학습 중 일부 neuron을 임시로 꺼서 특정 경로에 과하게 의존하지 않게 합니다.

3. 데이터 관점의 정규화
   - data augmentation: 이미지를 살짝 회전하거나 자르는 등 데이터를 다양하게 만들어 외우기 어렵게 합니다.
   - noise injection: 입력이나 hidden state에 약간의 흔들림을 줘서 더 robust한 표현을 배우게 합니다.

이 중 오늘의 핵심은 L1, L2, weight decay입니다. 모두 “복잡한 모델을 조금 덜 복잡하게 만들자”는 같은 목적을 가집니다.

### 핵심 수학 포인트

기본 학습 목표는 보통 다음과 같습니다.

`최소화할 값 = data loss`

정규화를 넣으면 다음처럼 바뀝니다.

`최소화할 값 = data loss + λ × penalty`

여기서 λ(lambda)는 정규화의 세기입니다.

- λ가 너무 작으면 penalty 효과가 거의 없습니다. 과적합을 못 막을 수 있습니다.
- λ가 너무 크면 모델이 weight를 너무 작게 만들려고 해서 과소적합이 생길 수 있습니다.

L2 penalty는 보통 weight 제곱의 합입니다.

`L2 penalty = w1² + w2² + ...`

예를 들어 weight가 3과 4라면 L2 penalty는 `3² + 4² = 25`입니다. 이것은 벡터 크기(norm)와 연결됩니다. 여기서는 “weight 벡터가 너무 커지지 않게 한다”고 이해하면 충분합니다.

L1 penalty는 weight 절댓값의 합입니다.

`L1 penalty = |w1| + |w2| + ...`

weight가 3과 -4라면 L1 penalty는 `|3| + |-4| = 7`입니다. L1은 많은 weight를 0으로 만들기 쉬워서, 필요 없는 feature를 끄는 효과가 있습니다.

### 배워야 할 용어 (영문 term 중심, 필요 시 한국어 설명 보조)

- regularization: 일반화를 위해 모델 복잡도에 제약을 주는 방법
- weight decay: 학습 중 weight가 너무 커지지 않게 줄이는 방식. 딥러닝 optimizer에서 자주 사용
- L1 penalty: weight 절댓값 합에 대한 벌점. 일부 weight를 0에 가깝게 만들 수 있음
- L2 penalty: weight 제곱 합에 대한 벌점. 큰 weight를 강하게 억제함
- lambda 또는 regularization strength: 정규화 penalty를 얼마나 강하게 줄지 정하는 값
- model complexity: 모델이 얼마나 복잡한 패턴을 표현하는지의 정도

### AI에서 어디에 쓰이는가

딥러닝 학습에서 weight decay는 매우 흔하게 사용됩니다. AdamW optimizer의 W가 decoupled weight decay를 뜻할 정도로 실전에서 중요합니다. transformer, vision model, embedding model fine-tuning에서 자주 설정하는 hyperparameter입니다.

예를 들어 작은 의료 이미지 데이터셋으로 큰 vision model을 fine-tuning할 때, weight decay가 없으면 모델이 특정 병원 장비의 노이즈나 이미지 스타일을 외울 수 있습니다. weight decay를 넣으면 모델이 더 안정적인 weight를 유지하면서 질병과 관련된 일반 패턴을 배우도록 도와줍니다.

LLM fine-tuning에서도 모델이 특정 instruction template만 외우지 않게 하는 데 도움이 됩니다. 물론 weight decay만으로 모든 문제가 해결되지는 않습니다. 데이터 품질, learning rate, batch size, dropout, early stopping도 함께 봐야 합니다.

embedding 모델에서는 regularization이 embedding 공간을 너무 이상하게 찌그러뜨리지 않도록 도울 수 있습니다. 비슷한 의미의 문장들이 안정적으로 가까운 위치에 모이려면, 학습 데이터의 우연한 pair만 외우는 것보다 일반적인 의미 구조를 배워야 합니다.

### 헷갈리기 쉬운 포인트

- regularization은 모델을 무조건 작게 만드는 것이 아니라, 과하게 복잡한 해결책을 덜 선호하게 만드는 것입니다.
- L2 penalty와 weight decay는 실전에서 비슷하게 말할 때가 많지만, optimizer 구현에서는 차이가 있을 수 있습니다. 특히 AdamW에서는 weight decay를 loss penalty와 분리해서 적용합니다.
- 정규화가 강할수록 항상 좋은 것은 아닙니다. 너무 강하면 underfitting이 됩니다.
- L1은 weight를 0에 가깝게 만들 수 있고, L2는 큰 weight를 부드럽게 줄이는 경향이 있습니다.

오늘은 “학습 데이터에 잘 맞는 것”과 “새 데이터에 잘 일반화하는 것”의 차이를 중심으로 복습해볼게요.

### 1. training loss는 낮아지는데 validation loss가 올라간다면 어떤 현상을 의심해야 할까요? 왜 그런가요?

**정답**

이 경우에는 과적합, 즉 overfitting을 의심해야 합니다.

training loss는 낮아지는데 validation loss가 올라간다는 것은 모델이 학습 데이터는 점점 더 잘 맞히고 있지만, 처음 보는 데이터에는 점점 더 못 맞히고 있다는 뜻입니다.

즉, 모델이 진짜 규칙을 배운다기보다 학습 데이터의 세부 패턴, 우연한 noise, 특이한 예시까지 외우기 시작했을 가능성이 큽니다.

**설명**

training loss는 모델이 학습에 사용한 데이터에서 얼마나 틀렸는지를 나타냅니다. loss function은 모델의 예측과 정답 사이의 차이를 숫자로 나타낸 값입니다. 이 값이 낮아진다는 것은 학습 데이터에서는 예측이 좋아지고 있다는 뜻입니다.

하지만 머신러닝의 진짜 목표는 학습 데이터를 외우는 것이 아닙니다. 목표는 아직 보지 못한 새 데이터에서도 잘 예측하는 것입니다. 이것을 generalization, 즉 일반화라고 합니다.

validation loss는 학습에 직접 쓰지 않은 검증 데이터에서의 loss입니다. 그래서 validation loss는 모델이 새 데이터에도 잘 작동하는지 확인하는 신호로 쓰입니다.

만약 training loss는 계속 내려가는데 validation loss가 올라간다면, 모델은 학습 데이터에는 점점 더 특화되고 있지만 일반적인 규칙에서는 멀어지고 있을 수 있습니다. 쉽게 말하면 “원리를 이해한 학생”이 아니라 “연습 문제 답안지를 외운 학생”처럼 되는 것입니다.

이때 모델은 학습 데이터 안의 우연한 특징까지 중요하다고 착각할 수 있습니다. 예를 들어 고양이 사진 분류 모델이 고양이의 귀나 얼굴을 보는 것이 아니라, 학습 데이터에 자주 등장한 특정 배경이나 워터마크를 보고 고양이라고 판단할 수도 있습니다.

**예시**

아주 작은 예를 들어볼게요.

학습 데이터가 다음과 같다고 합시다.

- x = 1 → y = 2
- x = 2 → y = 4
- x = 3 → y = 6

사실 규칙은 단순하게 `y = 2x`입니다.

좋은 모델은 이 규칙을 배워서 x = 4가 들어오면 y = 8이라고 예측합니다.

그런데 과적합된 모델은 x = 1, 2, 3을 완벽히 맞히려고 너무 복잡한 곡선을 만들 수 있습니다. 학습 데이터에서는 loss가 거의 0에 가까워질 수 있지만, x = 4가 들어오면 갑자기 y = 100 같은 이상한 예측을 할 수도 있습니다.

즉, 이미 본 문제는 잘 맞히지만 새 문제에는 약한 상태입니다.

**실전 연결**

실전 ML/DL에서는 training loss만 보고 모델을 선택하면 위험합니다. 이미지 분류, 추천 시스템, LLM fine-tuning 모두에서 validation loss나 validation accuracy를 함께 봐야 합니다.

예를 들어 작은 데이터셋으로 큰 transformer 모델을 fine-tuning할 때 training loss가 빠르게 낮아질 수 있습니다. 하지만 validation loss가 올라간다면 모델이 데이터의 일반 패턴이 아니라 특정 문장, 특정 label 패턴, 특정 template을 외우고 있을 수 있습니다.

이럴 때는 early stopping, weight decay, dropout, data augmentation, 더 많은 데이터 확보 같은 방법으로 overfitting을 줄입니다.

### 2. bias가 큰 모델과 variance가 큰 모델은 각각 어떤 예측 행동을 보이나요?

**정답**

bias가 큰 모델은 너무 단순해서 실제 규칙을 제대로 못 배웁니다. 그래서 학습 데이터에서도 자주 틀리고, 새 데이터에서도 자주 틀립니다. 보통 underfitting과 연결됩니다.

variance가 큰 모델은 학습 데이터의 작은 변화나 noise에 너무 민감합니다. 학습 데이터는 매우 잘 맞히지만, 새 데이터에서는 예측이 크게 흔들릴 수 있습니다. 보통 overfitting과 연결됩니다.

**설명**

bias는 모델의 가정이 실제 규칙에서 얼마나 벗어나 있는지를 뜻합니다. 여기서 bias는 사회적 편향이라는 뜻이 아니라, 수학적으로 “모델이 구조적으로 한쪽으로 틀리는 정도”에 가깝습니다.

bias가 큰 모델은 문제를 너무 단순하게 봅니다. 예를 들어 실제 데이터는 곡선 형태인데, 모델이 무조건 직선 하나로만 설명하려고 하면 중요한 패턴을 놓칠 수 있습니다. 이 경우 training error도 높고 validation error도 높을 가능성이 큽니다.

variance는 학습 데이터가 조금 바뀌었을 때 모델의 예측이 얼마나 흔들리는지를 뜻합니다.

variance가 큰 모델은 너무 민감합니다. 학습 데이터의 작은 noise까지 따라가려고 합니다. 그래서 training data는 아주 잘 맞힐 수 있지만, 데이터가 조금만 달라져도 예측이 불안정해집니다.

Bias-Variance Tradeoff는 이 둘 사이의 균형 문제입니다.

모델이 너무 단순하면 bias가 커집니다. 반대로 모델이 너무 복잡하고 데이터의 세부사항까지 따라가면 variance가 커질 수 있습니다. 좋은 모델은 실제 규칙을 충분히 표현할 만큼 복잡하지만, 우연한 noise까지 외울 만큼 과하게 복잡하지 않아야 합니다.

**예시**

시험 점수를 예측하는 모델을 생각해봅시다.

공부 시간이 늘수록 점수가 오른다고 해볼게요.

- 1시간 공부 → 50점
- 2시간 공부 → 60점
- 3시간 공부 → 70점
- 4시간 공부 → 80점

대략 규칙은 “공부 시간이 1시간 늘면 점수가 10점 오른다”입니다.

bias가 큰 모델은 이렇게 말할 수 있습니다.

“누구든 항상 65점일 거야.”

이 모델은 안정적이긴 하지만 공부 시간이 늘어나는 규칙을 무시합니다. 1시간 공부한 사람에게도 65점, 4시간 공부한 사람에게도 65점이라고 하니 기본 패턴을 못 배운 것입니다.

variance가 큰 모델은 학습 데이터 4개를 완벽하게 맞히려고 너무 복잡한 곡선을 만들 수 있습니다.

그래서 1시간은 50점, 2시간은 60점, 3시간은 70점, 4시간은 80점을 정확히 맞히지만, 2.5시간 공부한 사람에게는 갑자기 95점이라고 예측할 수도 있습니다.

균형 잡힌 모델은 이렇게 배웁니다.

`점수 = 40 + 10 × 공부시간`

이 모델은 학습 데이터도 꽤 잘 맞히고, 새로운 공부 시간에도 자연스럽게 예측할 수 있습니다.

**실전 연결**

실전에서는 모델 성능이 나쁠 때 “bias 문제인지 variance 문제인지”를 구분하는 것이 중요합니다.

training loss와 validation loss가 둘 다 높다면 모델이 너무 단순하거나 학습이 부족한 bias 문제일 수 있습니다. 이때는 더 큰 모델, 더 좋은 feature, 더 긴 학습, pre-trained model 사용 등을 고려할 수 있습니다.

반대로 training loss는 낮은데 validation loss가 높다면 variance 문제일 가능성이 큽니다. 이때는 regularization, weight decay, dropout, data augmentation, early stopping, 데이터 추가 등을 고려합니다.

LLM에서도 같습니다. 작은 데이터셋으로 큰 모델을 fine-tuning할 때 모델이 특정 답변 형식만 외우면 variance 문제가 생길 수 있습니다. 반대로 모델이 너무 작거나 학습이 부족하면 질문의 기본 의미도 제대로 못 잡는 bias 문제가 생길 수 있습니다.

### 3. L1 penalty와 L2 penalty는 weight에 어떤 방식으로 벌점을 주며, 실전에서 어떤 차이를 만들 수 있나요?

**정답**

L1 penalty는 weight의 절댓값 합에 벌점을 줍니다.

예를 들어 weight가 3과 -4라면 L1 penalty는 `|3| + |-4| = 7`입니다.

L2 penalty는 weight의 제곱 합에 벌점을 줍니다.

예를 들어 weight가 3과 -4라면 L2 penalty는 `3² + (-4)² = 9 + 16 = 25`입니다.

실전에서 L1은 일부 weight를 0에 가깝게 만들어 feature를 선택하는 효과가 있고, L2는 큰 weight를 부드럽게 줄여 모델이 특정 feature에 과하게 의존하지 않도록 도와줍니다.

**설명**

정규화, 즉 regularization은 모델이 학습 데이터에 너무 과하게 맞춰지는 것을 막기 위한 방법입니다.

기본적으로 모델은 data loss를 줄이려고 학습합니다. data loss는 예측값과 정답 사이의 차이입니다. 그런데 data loss만 줄이라고 하면 모델이 학습 데이터를 억지로 맞히기 위해 weight를 너무 크게 만들거나, 너무 복잡한 규칙을 만들 수 있습니다.

그래서 정규화를 넣으면 학습 목표가 이렇게 바뀝니다.

`최소화할 값 = data loss + λ × penalty`

여기서 λ, 즉 lambda는 정규화의 세기입니다. lambda가 크면 penalty를 더 강하게 주고, lambda가 작으면 penalty의 영향이 약해집니다.

L1 penalty는 weight 절댓값의 합을 벌점으로 사용합니다. 절댓값을 쓰기 때문에 weight가 양수든 음수든 크면 벌점을 받습니다. L1은 많은 weight를 정확히 0에 가깝게 만들기 쉬운 성질이 있습니다. 그래서 필요 없는 feature를 꺼버리는 feature selection 효과가 있습니다.

L2 penalty는 weight 제곱의 합을 벌점으로 사용합니다. 제곱을 하기 때문에 큰 weight가 특히 강하게 벌점을 받습니다. 예를 들어 weight 10은 제곱하면 100이지만, weight 100은 제곱하면 10000이 됩니다. 그래서 L2는 너무 큰 weight를 강하게 억제합니다.

딥러닝에서는 L2와 비슷한 효과를 내는 weight decay를 자주 사용합니다. 특히 AdamW optimizer에서 weight decay는 매우 흔한 hyperparameter입니다.

**예시**

집값을 예측하는 모델을 생각해봅시다.

모델이 이렇게 예측한다고 해볼게요.

`예측 집값 = 10 × 방 개수 + 500 × 데이터 ID`

여기서 방 개수는 집값과 관련이 있을 수 있습니다. 하지만 데이터 ID는 원래 집값과 관련이 없어야 합니다. 그런데 학습 데이터에서 우연히 ID가 큰 집들이 비쌌다면 모델이 데이터 ID에 큰 weight 500을 줄 수 있습니다.

이 경우 학습 데이터는 잘 맞을 수 있지만, 새 데이터에서는 망가질 가능성이 큽니다.

L2 penalty를 넣으면 500처럼 큰 weight는 제곱 때문에 큰 벌점을 받습니다. 그래서 모델은 데이터 ID에 그렇게 크게 의존하지 않으려 합니다.

L1 penalty를 넣으면 아예 데이터 ID에 해당하는 weight가 0에 가까워질 수 있습니다. 그러면 모델은 “이 feature는 별로 필요 없구나”라고 판단한 것처럼 동작합니다.

**실전 연결**

실전 ML에서는 L1과 L2가 모델 복잡도 제어에 자주 사용됩니다.

L1은 feature가 많고 그중 일부만 중요할 때 유용할 수 있습니다. 예를 들어 수천 개의 feature 중 실제로 예측에 중요한 feature가 몇 개뿐이라면, L1은 불필요한 weight를 0에 가깝게 만들어 모델을 더 해석하기 쉽게 만들 수 있습니다.

L2 또는 weight decay는 딥러닝에서 특히 많이 쓰입니다. transformer, vision model, embedding model을 학습하거나 fine-tuning할 때 weight가 너무 커지는 것을 막아 모델이 더 안정적으로 일반화하도록 도와줍니다.

LLM fine-tuning에서도 weight decay는 모델이 작은 학습 데이터의 특정 문장이나 답변 스타일을 과하게 외우지 않도록 도와줄 수 있습니다. 다만 정규화가 너무 강하면 underfitting이 생길 수 있습니다. 즉, 모델이 필요한 규칙까지 충분히 못 배우게 될 수 있습니다.

그래서 실전에서는 validation loss를 보면서 regularization strength, learning rate, batch size, epoch 수를 함께 조절합니다.
