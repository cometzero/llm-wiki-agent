## 1. Streaming Tensor Processor (TSP) 소프트웨어 정의 하드웨어 [2]

Groq의 스트리밍 텐서 프로세서(TSP)는 소프트웨어 정의 하드웨어와 결정론적 실행을 통해 딥러닝 모델의 예측 불가능한 성능 문제를 해결한다.

### 1.1. 소프트웨어 정의 접근 방식 [8]

하드웨어-소프트웨어 공동 설계 재검토: 기존의 공동 설계 방식을 재검토하여 하드웨어-소프트웨어 인터페이스를 개선한다. [8]

정적-동적 인터페이스: 컴파일 시점(정적)과 실행 시점(동적)에 수행되는 작업을 명확히 구분하여 런타임 성능과 정확성을 예측 가능하게 한다. [9]

MLIR 인터페이스: 컴파일러가 아키텍처 상태를 파악하여 병렬 실행을 최적화할 수 있도록 한다. [12]

머신러닝 모델에 적합: TSP 하드웨어는 정적 분석과 결정론적 실행을 통해 머신러닝 모델에 최적화되어 있다. [11]

### 1.2. 결정론적 실행 및 마이크로아키텍처 [14]

결정론적 하드웨어 설계: 컴파일러와 런타임을 위한 효율적인 타겟을 구축하기 위해 결정론적 설계 철학을 따른다. [14]

메모리 일관성 모델: 메모리 참조의 재정렬을 허용하지 않아 예측 가능한 실행을 보장한다. [15]

비반응형 메커니즘 배제: 중재자, 크로스바, 캐시 등 예측 불가능성을 유발하는 구성 요소를 사용하지 않는다. [15]

컴파일러의 정확한 제어: 컴파일러가 모든 텐서의 온칩 위치를 정확히 파악하여 명령어 실행을 조율한다. [16]

스트리밍 프로듀서-컨슈머 모델: 레지스터 파일을 사용하여 칩을 통해 흐르는 각 텐서의 상태를 추적한다. [17]

복잡성 회피: 기존 CPU의 복잡성을 줄여 데이터 흐름을 단순화하고 예측 가능한 성능을 제공한다. [19]

예측 가능한 성능: 딥러닝 모델의 처리량 특성을 고정적이고 예측 가능한 실행 시간으로 제공한다. [20]

단일 레벨 SRAM: 대규모 스크래치패드 SRAM을 사용하여 명시적으로 텐서를 할당하고 데이터 흐름을 제어한다. [20]

계층적 메모리 회피: 캐시 메모리 계층 구조가 도입하는 복잡성과 비결정성을 피한다. [22]

시스템 레벨 복잡성 회피: 데이터 흐름을 단순화하고 예측 가능한 성능을 제공한다. [24]

라우팅 복잡성 감소: 적응형 라우팅을 통해 온칩 버퍼 지연 시간과 점유율을 줄인다. [27]

네트워크 직경 감소: 하이-라딕스 스위치와 낮은 직경의 네트워크 토폴로지를 사용하여 지연 시간을 줄인다. [28]

컴파일러 제어 트래픽: Groq C2C 네트워크에서 컴파일러가 트래픽 패턴을 제어하여 예측 가능성을 높인다. [26]

## 2. TSP 마이크로아키텍처 [31]

Groq TSP는 기능적으로 분할된 멀티코어 메시 아키텍처를 통해 소프트웨어 정의 하드웨어의 잠재력을 극대화하며, 각 기능 단위는 특정 연산에 최적화되어 있다.

### 2.1. 소프트웨어 정의 하드웨어의 의미 [31]

소프트웨어 정의 하드웨어: 하드웨어의 동작을 소프트웨어로 제어하여 유연성과 효율성을 극대화한다. [32]

### 2.2. 기능적으로 분할된 마이크로아키텍처 [34]

재구성된 멀티코어 메시: 기존의 5단계 파이프라인(IF, ID, EX, MEM, WB)을 기능적으로 분할하여 온칩 코어 네트워크를 재구성한다. [34]

기능 슬라이스: 명령어 제어 장치(ICU), 온칩 메모리(MEM), 벡터/행렬 연산(VXM), 행렬 연산(MXM), 데이터 재구성 및 I/O(SXM) 등으로 기능이 분할된다. [39]

데이터 및 명령어 흐름: 데이터는 수평적으로 "스트림"을 통해 흐르고, 명령어는 수직적으로 실행된다. [41]

Figure 1: 기능적으로 분할된 멀티코어 메시 아키텍처 [50]

### 2.3. TSP 데이터 흐름 [51]

칩 구조: 칩은 동서(East/West) 두 개의 반구로 나뉘며, 중앙에 VXM 유닛이 위치한다. [51]

VXM 유닛: 각 레인당 16개의 PE(프로세싱 엘리먼트)를 가지며, 총 5,120개의 벡터 ALU를 포함한다. [52]

MXM 유닛: 320개의 레인과 44개의 독립적인 메모리 뱅크/슬라이스를 가지며, 409,600개의 MAC(곱셈-누산) 유닛을 포함한다. [53]

명령어 제어 유닛(ICU): 명령어 흐름을 제어한다. [55]

칩-투-칩(C2C) 연결: PCIe Gen4 x4 링크를 통해 다른 칩과 연결된다. [55]

## 3. 소프트웨어 추상화 [57]

GroqChip은 SIMD, 스트리밍, 공간 아키텍처를 결합하여 대규모 병렬 연산과 효율적인 데이터 흐름을 가능하게 하며, 소프트웨어 제어 메모리와 컴파일러 기반 명령어 스케줄링을 통해 예측 가능한 성능을 제공한다.

### 3.1. GroqChip 아키텍처 [60]

GroqChip 1: 대규모 병렬 연산을 위한 핵심 빌딩 블록이다. [60]

메모리 유닛: 80TB/s의 대역폭을 가진 대규모 SRAM을 포함하며, 스트라이드에 둔감하다. [61]

행렬 유닛(MXM): 4개의 퓨즈드 닷 프로덕트 엔진을 가진 320x320 TruePoint™ 엔진을 포함한다. [61]

벡터 유닛(VXM): 5,120개의 벡터 ALU를 가진 프로그래밍 가능한 유닛이다. [61]

네트워킹: 480GB/s의 대역폭을 가지며, 다양한 네트워크 토폴로지로 확장 가능하다. [62]

명령어 제어: 다중 명령어 큐를 통해 명령어 병렬성을 높인다. [63]

### 3.2. GroqChip 빌딩 블록 [65]

SIMD 유닛: 다양한 유형의 특수 SIMD 유닛(MXM, VXM, SXM, MEM)으로 구성된다. [67]

MXM: 행렬-행렬 곱셈 연산. [67]

VXM: 벡터-벡터 연산. [67]

SXM: 온칩 데이터 재구성. [67]

MEM: SRAM 메모리. [67]

SIMD 유닛 배치: 칩 영역에 SIMD 유닛이 배치된다. [69]

동기화된 명령어 디스패치: 모든 SIMD 유닛에 걸쳐 동기화된 명령어 디스패치를 통해 실행을 제어한다. [70]

## 4. 소프트웨어 지원 ISA [72]

Groq의 ISA는 소프트웨어 제어 메모리 추상화와 컴파일러 기반 명령어 스케줄링을 통해 결정론적이고 예측 가능한 성능을 제공하며, 단순화된 데이터 흐름과 통신 메커니즘으로 효율성을 극대화한다.

### 4.1. 소프트웨어 제어 메모리 추상화 [74]

저수준 아키텍처 노출: 하드웨어 캐싱 없이 컴파일러가 모든 데이터 위치를 파악할 수 있도록 한다. [74]

플랫 메모리 계층: L1, L2, L3 캐시 없이 물리적 뱅크 세트로 직접 주소 지정되는 메모리를 소프트웨어에 노출한다. [75]

대용량 온칩 SRAM: 220MB의 온칩 SRAM 용량은 외부 DRAM으로의 데이터 유출 필요성을 줄여 예측 불가능성을 방지한다. [76]

스크래치패드 메모리: 외부 메모리 액세스를 숨길 수 있는 충분한 스크래치패드 메모리를 제공한다. [78]

### 4.2. 컴파일러 기반 명령어 스케줄링 [80]

사이클-정확한 명령어 스케줄링: 컴파일러가 기능 유닛 간의 명령어 스케줄링을 사이클 단위로 정확하게 수행한다. [80]

동기화된 실행: 모든 유닛이 록스텝으로 실행되며, 각 경로당 사이클당 하나의 명령어가 발행된다. [80]

VLIW 명령어: 144-와이드의 완전 파이프라인 VLIW(Very Long Instruction Word) 명령어로 볼 수 있다. [81]

낮은 하드웨어 오버헤드: 명령어 실행 관리를 위한 하드웨어 오버헤드가 3%에 불과하다. [81]

### 4.3. 단순한 인터커넥트 [83]

단방향 스트림 레지스터: 기능 유닛 간의 데이터 이동을 위한 단순하고 단방향 "스트림 레지스터"를 사용한다. [83]

예측 가능한 데이터 이동: 데이터 이동 시간을 시뮬레이션 없이 쉽게 계산할 수 있어 예측 가능성을 높인다. [84]

동서 방향 스트림 레지스터 경로: 동쪽 및 서쪽 방향으로 데이터가 흐르는 스트림 레지스터 경로로 구성된다. [85]

## 5. ISA 지원 및 데이터 유형 [86]

Groq TSP의 ISA는 다양한 기능 유닛에 대한 명시적이고 저수준의 제어를 제공하며, 광범위한 데이터 유형을 지원하여 딥러닝 및 HPC 워크로드에 최적화된 유연하고 결정론적인 연산을 가능하게 한다.

### 5.1. 명령어 세트 설명 [86]

ICU (Instruction Control Unit) 명령어:

NOP (No-operation): 지정된 사이클 수만큼 실행을 지연시킨다. [86]

IFETCH: 로컬 스트림 메모리에서 명령어를 가져오거나 디스패치한다. [86]

REPEAT: 이전 명령어를 지정된 횟수만큼 반복한다. [87]

SYNC: 대기 중인 배리어 알림을 기다린다. [90]

NOTIFY: 대기 중인 배리어를 해제하여 명령어 흐름을 재개한다. [90]

CONFIG: 저전력 모드를 구성한다. [90]

MEM (Memory) 명령어:

READ: 지정된 주소에서 스트림으로 벡터를 로드한다. [87]

STORE: 레지스터 내용을 주 메모리에 저장한다. [87]

STEP: 후속 주소 간의 스트라이드를 설정한다. [88]

ITERATIONS: 루프 주소 생성의 경계를 설정한다. [88]

GATHER: 맵 스트림이 가리키는 주소에서 읽어 스트림에 넣는다. [91]

SCATTER: 스트림의 내용을 맵 스트림이 가리키는 주소에 저장한다. [91]

VXM (Vector Matrix) 명령어:

POINT-WISE: 단항 또는 이항 점별 연산을 수행한다. [89]

TYPE CONVERSIONS: 고정 소수점 및 부동 소수점 유형 변환을 수행한다. [92]

ReLU: 정류 선형 단위 활성화 함수를 수행한다. [92]

TanH: 하이퍼볼릭 탄젠트 활성화 함수를 수행한다. [92]

Exp: 지수 연산을 수행한다. [92]

RSqrt: 역제곱근 연산을 수행한다. [92]

MXM (Matrix Multiply) 명령어:

LW (Load Weights): 스트림에서 가중치를 가중치 버퍼로 로드한다. [93]

IW (Install Weights): 스트림에서 가중치를 IW 버퍼로 설치한다. [93]

ABC (Activation Buffer Control): 활성화를 시작하고 조정한다. [94]

ACC (Accumulate): MXM 또는 SXM 결과에서 INT32 또는 FP32를 누산한다. [94]

SXM (Switch eXecution Module) 명령어:

SHIFT: 스트림을 N 레인만큼 위/아래로 이동시킨다. [94]

PERMUTE: 320개의 입력과 출력을 매핑하여 데이터를 재정렬한다. [95]

ROTATE: 모든 가능한 회전으로 입력 데이터를 출력 스트림으로 회전시킨다. [95]

TRANSPOSE: 16x16 요소를 전치하여 16개의 출력 스트림을 생성한다. [96]

C2C (Chip-to-Chip) 명령어:

DESKEW: 플레시오크로너스 링크의 스큐를 관리한다. [96]

SEND: 320바이트 벡터를 보낸다. [97]

RECEIVE: 320바이트 벡터를 수신하여 주 메모리에 배치한다. [97]

### 5.2. 데이터 유형 지원 [98]

MXM 유닛 지원 데이터 유형:

정수: INT8, UINT8, INT16, UINT16, INT32, UINT32 [98]

부동 소수점: FLOAT16 (반정밀도), FLOAT32 [98]

논리: BOOL8, BOOL16, BOOL32 [98]

특징: 320x320 퓨즈드 닷 프로덕트 또는 FLOAT16 누산을 지원한다. [98]

VXM 유닛 지원 데이터 유형:

모든 데이터 유형: INT32 데이터의 모든 유형을 지원하는 상위 집합이다. [100]

최고/최저 값: 각 데이터 유형에 대한 최고 및 최저 값을 정의한다. [101]

## 6. TSP 개요 및 기능 유닛 [104]

Groq TSP는 도메인별 명령어 가속기와 목적에 맞게 구축된 기능 유닛을 통해 딥러닝 연산을 최적화하며, 각 유닛은 특정 데이터 유형과 연산에 특화되어 효율적인 데이터 흐름과 병렬 처리를 가능하게 한다.

### 6.1. 기능 유닛 개요 [104]

도메인별 명령어 가속기: 목적에 맞게 구축된 명령어 세트를 가진 도메인별 가속기이다. [104]

ICU (Instruction Control Unit): SRAM에서 명령어를 가져와 제어 유닛으로 보낸다. [104]

NOP (No-Op): 1사이클 이상 대기한다. [105]

SYNC: ICU를 정지시키고 NOTIFY를 기다린다. [105]

NOTIFY: 144개의 온칩 ICU 중 하나를 "깨워" 다른 ICU와 록스텝으로 동기화한다. [106]

컴파일러의 실행 시간 추론: 컴파일러가 기능 유닛의 실행 시간을 추론할 수 있도록 한다. [107]

단일 연산 실행: 각 기능 유닛은 해당 연산만 실행한다. [107]

### 6.2. MXM (Matrix Multiply) 엔진 [109]

MXM 유닛: 행렬 곱셈 연산을 수행한다. [109]

구성: 각 반구에 2개의 MXM 유닛이 있으며, 각각 Int8 및 Float16을 지원한다. [109]

성능: 320B x 320B 닷 프로덕트를 20사이클 내에 실행하며, 32비트 누산을 지원한다. [110]

파이프라인: 완전 파이프라인 방식으로 N개의 독립적인 연산을 지원한다. [110]

### 6.3. VXM (Vector Matrix) 및 MEM (Memory) 기능 [112]

VXM 및 MEM 기능: 복잡하고 맞춤화된 기능을 지원한다. [112]

데이터 흐름: VXM 데이터 흐름은 여러 스트림을 통해 유연한 데이터 병렬 처리를 제공한다. [113]

MEM 대역폭: 높은 대역폭을 지원하며, 동시 메모리 액세스를 가능하게 한다. [113]

스트림 텐서: 스트림 텐서를 읽고 프로그래밍 가능한 패브릭에 전달하여 데이터 지역성을 지원한다. [114]

MEM 쿼드 그룹: 88개의 독립적인 MEM 슬라이스로 구성되며, 각 슬라이스는 8192개의 물리적 뱅크를 가진다. [119]

스트림 인터페이스: 단일 MEM 슬라이스에서 스트림을 읽고 쓸 수 있으며, 80TBps의 대역폭을 가진다. [120]

다차원 텐서 지원: 다차원 텐서 또는 다중 바이트 데이터 유형을 위해 MEM 슬라이스를 그룹화할 수 있다. [122]

Figure 2: VXM 및 MEM 데이터 흐름 [121]

### 6.4. SXM (Switch eXecution Module) [123]

SXM 모듈: 데이터 조작 및 변환을 위한 스위스 나이프 역할을 한다. [123]

분배기 (Distributor): 데이터를 분배하고 재배열한다. [123]

전치기 (Transposer): 데이터를 전치한다. [124]

시프터 (Shifter): 임의의 매핑으로 데이터를 이동, 회전, 전치한다. [124]

인트라-벡터 셔플링: 슈퍼레인 내에서 벡터 요소를 셔플링한다. [125]

데이터 스트림 변환: 재구성 및 패딩과 같은 데이터 스트림 변환을 수행한다. [125]

## 9. 글로벌 동기화 [146]

Groq 시스템은 하드웨어 정렬 카운터(HAC)와 소프트웨어 정렬 카운터(SAC)를 통해 다중 TSP 간의 결정론적 실행을 유지하며, ISA 지원을 통해 링크 지연 시간 추정 및 동기화된 통신을 가능하게 한다.

### 9.1. 결정론 유지 [149]

다중 TSP 간 결정론 확장: 단일 TSP는 결정론적이지만, C2C 링크는 비결정성을 유발할 수 있으므로 하드웨어 및 소프트웨어 지원이 필요하다. [149]

하드웨어 정렬 카운터 (HAC): 클럭 드리프트를 보상하기 위한 하드웨어 카운터이다. [150]

소프트웨어 정렬 카운터 (SAC): 동기식 통신을 위한 소프트웨어 카운터이다. [150]

링크 지연 시간 추정: 정확한 링크 지연 시간 추정을 위한 ISA 명령어가 추가되었다. [151]

초기 정렬 및 런타임 재동기화: 다중 TSP에 걸쳐 전역적으로 동기화된 클럭 없이도 결정론적 실행을 보장한다. [151]

### 9.2. ISA 지원 [153]

소프트웨어 정의 네트워킹을 위한 ISA 지원:

SYNC: 칩 전체의 모든 ICU를 정렬하여 록스텝 실행을 유지한다. [154]

NOTIFY: 소프트웨어 스케줄링을 사용하여 정지된 명령어 큐를 깨운다. [155]

DESKEW: HAC를 일시 중지하여 런타임 스큐를 결정론적으로 지연시킨다. [156]

TRANSMIT: C2C 링크를 통해 메시지를 전송한다. [156]

FEC (Forward Error Correction): 대부분의 전송 오류를 수정한다. [156]

분산 시스템에서 결정론 유지: 각 TSP는 독립적으로 실행되는 HAC를 유지한다. [158]

## 10. 소프트웨어 스케줄링 네트워크 [160]

Groq의 소프트웨어 스케줄링 네트워크는 하드웨어 중재 및 동적 라우팅을 배제하고 컴파일러 기반의 정적 스케줄링을 통해 예측 가능한 성능과 부하 분산을 달성하며, 텐서 기반 패킷 형식과 비최소 경로 라우팅을 통해 대역폭 활용도를 극대화한다.

### 10.1. 기존 스케일아웃 네트워크 [163]

기존 네트워크 특징:

홉별 하드웨어 중재 라우터: 각 홉에서 하드웨어 중재를 사용한다. [163]

하드웨어 기반 전역 적응형 라우팅: 하드웨어 기반의 전역 적응형 라우팅을 사용한다. [163]

백프레셔를 통한 혼잡 감지: 네트워크 혼잡을 백프레셔를 통해 감지한다. [164]

### 10.2. 소프트웨어 스케줄링 네트워크 (결정론적) [165]

TSP 네트워크 특징:

하드웨어 중재 없음: 동적 콘텐츠에 대한 하드웨어 중재가 없다. [165]

깊은 입력 큐 없음: 하드웨어 라우팅에 깊은 입력 큐가 필요하지 않다. [165]

부하 분산을 위한 스케줄링 없음: 하드웨어 부하 분산을 위한 스케줄링이 없다. [165]

정적 스케줄링: 정적으로 스케줄링되어 혼잡 감지가 필요 없다. [166]

트래픽 패턴 기반 결정론적 부하 분산: 트래픽 패턴을 기반으로 결정론적 부하 분산을 수행한다. [166]

### 10.3. 텐서, 패킷이 아닌 라우트 [167]

320바이트 패킷 형식: 텐서 인코딩을 위한 320바이트 패킷 형식을 사용한다. [167]

낮은 오버헤드: 헤더 및 테일 플릿에서 2.5%의 낮은 오버헤드를 가진다. [167]

흐름 제어 없음: 하드웨어 흐름 제어, IDLE, Sync, Start, End 정보가 없다. [168]

성능 향상: 특히 작은 메시지 크기에서 대역폭 성능을 향상시킨다. [168]

### 10.4. 결정론적 부하 분산 [170]

경로 다양성 및 비최소 경로 라우팅:

높은 경로 다양성: 고-라딕스 토폴로지에서 높은 경로 다양성을 제공한다. [172]

비최소 경로 라우팅: 두 노드 간의 대역폭 양을 증가시킨다. [172]

대칭 토폴로지: 토폴로지 에지/노드가 대칭적이며, 라우트도 대칭적이다. [173]

Figure 5: 비최소 경로 라우팅 [177]

Dragonfly 라우팅: 결정론적이지만 높은 경로 다양성을 가진다. [178]

경로 다양성 활용: 비최소 경로를 통해 경로 다양성을 활용한다. [178]

적응형 라우팅의 위험: 잘못된 적응형 라우팅 결정은 성능 저하를 유발할 수 있다. [179]

간접 적응형 라우팅: 팬텀 혼잡을 피하기 위한 간접 적응형 라우팅을 사용한다. [180]

## 11. RealScale™ 칩-투-칩(C2C) 링크 및 흐름 제어 [181]

Groq RealScale™ C2C 링크는 기존 RDMA와 달리 논리적으로 공유되는 전역 SRAM 액세스 모델을 제공하여, TSPs 간의 직접적인 통신과 효율적인 데이터 이동을 통해 분산 시스템의 복잡성을 줄이고 성능을 최적화한다.

### 11.1. RealScale™ C2C 링크 및 흐름 제어 [181]

단순화된 통신 모델: 논리적으로 공유되는 전역 SRAM 액세스를 제공한다. [181]

물리적 분산 DRAM: DRAM은 TSPs 간에 물리적으로 분산되어 있다. [181]

직접 C2C 링크: TSPs는 C2C 링크를 통해 DRAM에 직접 연결된다. [182]

기존 RDMA와의 비교: 기존 RDMA(Remote Direct Memory Access)와 달리 Groq RealScale™ C2C 통신은 단순화된 모델을 제공한다. [183]

## 12. 신뢰성 [187]

Groq 시스템은 TSP 내 예비 슈퍼레인, ECC 보호, 그리고 SDC 방지 메커니즘을 통해 높은 신뢰성과 데이터 무결성을 보장하며, 결정론적 설계 철학을 통해 검증 및 예외 처리를 단순화한다.

### 12.1. TSP 내 중복성 [188]

예비 슈퍼레인: 제조 수율을 높이기 위해 각 TSP 내에 "예비" 슈퍼레인을 포함한다. [188]

결함 허용: 단일 슈퍼레인의 하드웨어 결함을 허용하여 "모든 양품" 다이를 사용할 수 있게 한다. [189]

중복 노드 및 전원 공급 장치: 각 노드에 중복 노드와 전원 공급 장치를 제공한다. [190]

### 12.2. 결정론 설계 검증 단순화 [192]

가정-보증 추론: 기능 유닛 간의 입력(스트림 레지스터 파일) 및 출력(스트림 레지스터 파일)에 대한 가정을 명시하고 보증을 확인한다. [192]

상태 비저장 기능 유닛: 기능 유닛은 상태 비저장 및 부작용이 없도록 설계된다. [194]

결정론적 설계 철학: 하드웨어에 반응형 구성 요소가 없고, 메모리 또는 네트워크 트랜잭션의 재정렬이 없으며, 고정 지연 시간 기능 유닛을 통해 예측 가능한 명령어를 제공한다. [195]

컴파일러에 필요한 상태 노출: 컴파일러가 프로그램 정확성을 추론하는 데 필요한 아키텍처 가시 상태를 노출한다. [196]

하드웨어 일관성 메커니즘 없음: 칩 또는 시스템 전반에 걸쳐 하드웨어 일관성 메커니즘이 없다. [197]

### 12.3. 소프트웨어 스택 신뢰성 및 중복성 [199]

소프트웨어 정의 하드웨어 인터페이스:

정적-동적 인터페이스: 컴파일 시간 대 런타임. [199]

하드웨어-소프트웨어 인터페이스: 아키텍처 가시 상태 노출. [200]

예외 처리: 산술 동작(예: 오버플로)과 같은 예외 처리에 특별한 주의를 기울인다. [200]

병렬화 컴파일러 인터페이스: 오류 수정 및 감지. [201]

런타임 시스템: 하드웨어 및 온칩 하드웨어-소프트웨어 예외 처리 구조. [202]

### 12.4. 모든 곳에 ECC [204]

소프트 오류 증가: 90nm 트랜지스터 이후 소프트 오류(SEU)가 크게 증가했다. [204]

SRF (Stream Register File) 보호: 스트림 레지스터 파일(SRF)은 제어 및 데이터 경로를 보호한다. [205]

구성: 320바이트 스트림 레지스터 64개(동쪽 32개, 서쪽 32개)를 포함한다. [207]

SECDED: 각 슈퍼레인에 45개의 SRF 스테이션이 있으며, 모두 SECDED(단일 오류 수정 및 이중 오류 감지)로 보호된다. [207]

### 12.5. SDC (Silent Data Corruption) 방지 [209]

SDC 원인: 고에너지 입자로 인한 비트 플립, 제조 및 초기 수명 불량, SI/PI 노이즈 등이 SDC를 유발한다. [209]

SDC 감지 및 방지: 대규모 하이퍼스케일러는 SDC 이벤트를 감지하고 방지하기 위해 노력한다. [211]

### 12.6. 하드웨어 구조 보호 [213]

핵심 하드웨어 구조 보호: 제어 및 메모리 슬라이스, VXM/MXM/산술 슬라이스, SXM 데이터 이동 슬라이스, C2C 칩-투-칩 I/O 슬라이스, 데이터 경로 등을 보호한다. [213]

SRF 보호: 각 슈퍼레인에는 45개의 SRF 스테이션이 있으며, 모두 SECDED로 보호되어 단일 비트 오류를 수정하고 다중 비트 오류를 감지한다. [215]

## 13. 예외 및 오류 처리 [224]

Groq 시스템은 NaN/Inf, SDC, 산술 예외와 같은 오류를 사전에 계획하고 처리하며, 컴파일러가 산술 예외의 의미를 결정하고 런타임에 오류를 재시도할 수 있도록 하여 결정론적이고 신뢰할 수 있는 연산을 보장한다.

### 13.1. 예외 및 결정론 처리 [224]

오류 발생 원인: NaN(Not a Number) 및 Inf(Infinity) 발생, SRAM 또는 핵심 하드웨어 구조의 SDC/SEU(Single Event Upset) 등으로 오류가 발생할 수 있다. [224]

예외 처리 계획: 산술 예외(오버플로/언더플로)에 대한 처리 방식을 사전에 결정해야 한다. [225]

산술 예외 방지: ADD_SAT, ADD_MOD, SUB_SAT, SUB_MOD, MUL_SAT, MUL_MOD과 같은 포화/모듈로 연산을 통해 산술 예외를 방지한다. [225]

컴파일러의 역할: 컴파일러가 컴파일 시점에 산술 예외의 의미를 결정하도록 허용한다. [226]

런타임 오류 처리:

원샷 재시도: 오류가 일시적인 경우(해결됨) 추론을 재시도하거나, 영구적인 경우 대체 하드웨어 리소스를 설정한다. [226]

FRU (Field Replaceable Unit) 교체: 하드웨어 교체를 시작하고 MTTR(Mean Time To Repair) 타이머를 시작한다. [227]

## 14. 워크로드 평가 [228]

Groq TSP는 Cholesky 분해, BERT, GEMM, AllReduce와 같은 다양한 AI 및 HPC 워크로드에서 기존 GPU 대비 월등한 성능과 낮은 지연 시간을 제공하며, 특히 배치-1 추론에서 예측 가능한 처리량을 통해 사용자 경험을 크게 향상시킨다.

### 14.1. Cholesky 분해 [231]

Cholesky 분해: 대규모 선형 시스템 방정식을 푸는 데 중요한 기술이다. [231]

성능 비교: Groq TSP는 Nvidia P100 GPU 대비 Cholesky 분해에서 훨씬 빠른 실행 시간을 보여준다. [232]

확장성: 여러 TSP를 사용하여 문제 크기에 따라 선형적으로 성능이 향상된다. [233]

Figure 8: Cholesky 분해 성능 비교 [234]

### 14.2. BERT 자연어 처리 [235]

BERT 모델 가속화: BERT 모델의 지연 시간을 최소화하고 처리량을 최대화하는 것을 목표로 한다. [236]

성능 비교: Groq TSP는 Nvidia T4 및 A100 GPU 대비 BERT-BASE 모델에서 4.8배에서 6.1배 빠른 지연 시간을 제공한다. [237]

예측 가능한 처리량: 지연 시간 분산을 최소화하여 예측 가능한 처리량을 제공한다. [238]

Figure 9: BERT-BASE 모델 지연 시간 비교 [239]

### 14.3. 일반 행렬 곱셈 (GEMM) [240]

GEMM: 많은 ML 워크로드 및 HPC의 핵심 연산이다. [240]

온칩 메모리 대역폭: ALU 및 벡터 연산을 위한 온칩 메모리 대역폭이 성능을 결정한다. [241]

일관된 성능: 다양한 텐서 크기에서 일관된 성능을 제공한다. [241]

높은 활용도: 최신 모델 및 애플리케이션에서 높은 활용도를 보여준다. [242]

Figure 10: GEMM 활용도 비교 [243]

### 14.4. AllReduce 결과 비교 [244]

미세 통신: Read(vector)->Send(vector)는 250사이클 이내에 미세 통신을 가능하게 한다. [244]

성능 비교: 8개의 A100 GPU 시스템과 비교했을 때, Groq TSP는 대규모 텐서 크기에서 A100과 유사한 대역폭을 제공하며, 중간 크기 텐서에서 대역폭을 크게 향상시킨다. [245]

네트워크 대역폭: A100 시스템은 Groq TSP보다 약 100배 높은 채널 대역폭을 가진다. [246]

## 15. 요약 및 향후 계획 [248]

Groq의 TSP 아키텍처는 소프트웨어 정의 하드웨어와 결정론적 실행을 통해 딥러닝 및 HPC 워크로드에서 예측 가능하고 반복 가능한 저지연, 고처리량 성능을 제공하며, 이는 기존 마이크로아키텍처로는 불가능한 수준의 서비스 품질을 달성한다.

### 15.1. 현재까지의 성과 [251]

컴파일러 지원 모델: 컴퓨터 비전, 자연어 처리, 고성능 컴퓨팅, 텍스트-투-스피치 등 다양한 분야의 모델을 지원한다. [251]

Figure 12: 컴파일러 지원 모델 로드맵 [254]

### 15.2. 요약 및 시사점 [255]

저지연 및 고처리량 컴퓨팅: 컴퓨팅 집약적인 딥러닝에 필수적이다. [255]

예측 가능하고 반복 가능한 성능: 사용자 대면 애플리케이션에 중요하다. [255]

배치-1 추론: 응답성과 서비스 품질(QoS)을 제공하는 데 중요하며, 기존 마이크로아키텍처로는 불가능하다. [256]

소프트웨어 정의 하드웨어 및 결정론: 하드웨어와 소프트웨어 전반에 걸친 설계 철학을 포함한다. [257]

하드웨어 추상화: 하드웨어의 세부 사항을 추상화하는 것이 아니라 제어하는 것이다. [257]

다중 프로세서로 TSP 결정론 확장: 소프트웨어 스케줄링 네트워크를 통해 텐서를 명시적으로 스케줄링한다. [258]

록-프리 통신 모델: 대규모 시스템에서 록-프리 통신을 가능하게 한다. [259]

ISA 노출: 144개의 독립적인 명령어 유닛(ICU)과 아키텍처 가시 상태(GPR, SRAM, 명령어 버퍼 등)를 노출한다. [259]

소프트웨어 기반 예외 처리: 소프트웨어 기반 재시도 통신을 통해 예외 처리를 지원한다. [260]
