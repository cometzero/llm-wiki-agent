## 1. NVIDIA 텐서 코어의 진화 배경 [1]

NVIDIA 텐서 코어는 AI 및 딥러닝 분야에서 무어의 법칙을 뛰어넘는 성능 향상을 이끌어왔으며, 이는 AI 산업 발전에 핵심적인 역할을 한다.

### 1.1. AI 스케일링 법칙과 컴퓨팅 발전 [3]

AI 스케일링 법칙의 중요성 [3]

AI 스케일링 법칙은 AI 산업을 발전시키고 모델 기능의 성장을 촉진한다.

이는 단위 토큰 비용을 빠르게 절감하는 데 기여한다.

이러한 스케일링 법칙은 훈련 및 추론 최적화와 혁신에 의해 주도된다.

무어의 법칙을 초월하는 컴퓨팅 능력 발전도 중요한 역할을 한다.

컴퓨팅 스케일링의 변화 [5]

2000년대 후반 데나드 스케일링(Dennard Scaling)의 종말과 2010년대 후반 트랜지스터당 비용 감소의 둔화가 있었다.

그럼에도 불구하고 컴퓨팅 능력은 첨단 패키징, 3D 스태킹, 새로운 트랜지스터 유형, GPU와 같은 특수 아키텍처 덕분에 빠르게 향상되었다.

GPU 컴퓨팅 능력의 발전 [8]

AI 및 딥러닝 분야에서 GPU 컴퓨팅 능력은 무어의 법칙보다 빠르게 발전하여 "황의 법칙(Huang's Law)" 성능 향상을 매년 제공한다.

이러한 발전의 핵심 기술은 텐서 코어이다.

## 2. 성능 기본 원칙 [30]

컴퓨팅 리소스 확장에 따른 성능 향상을 이해하기 위해 암달의 법칙, 강한 스케일링, 약한 스케일링, 그리고 데이터 이동의 중요성을 파악해야 한다.

### 2.1. 암달의 법칙 [31]

정의 [32]

고정된 문제 크기에 대해 병렬화를 통해 얻을 수 있는 최대 속도를 나타낸다.

컴퓨팅 리소스를 확장하는 것은 병렬 부분의 실행 시간만 단축시키므로, 성능 향상은 직렬 부분에 의해 제한된다.

최대 성능 향상 공식 [34]

1 / (S + (1-S)/p)

여기서 S는 병렬 작업 실행 시간이고, p는 병렬화 가능한 작업의 속도 향상이다.

병렬 부분이 완벽하게 병렬화되는 이상적인 경우, 속도 향상 p는 처리 장치의 수가 될 수 있다.

### 2.2. 강한 스케일링 및 약한 스케일링 [38]

정의 [39]

강한 스케일링(Strong scaling): 고정된 크기의 문제를 해결하기 위해 컴퓨팅 리소스를 확장하는 것을 의미하며, 암달의 법칙이 속도 향상을 정량화한다.

약한 스케일링(Weak scaling): 더 큰 문제를 일정한 시간 내에 해결하기 위해 컴퓨팅 리소스를 확장하는 것을 의미한다.

예를 들어, 4배 더 많은 컴퓨팅 리소스를 사용하여 4배 더 큰 이미지를 동일한 시간 내에 처리하는 것이다.

성능 향상 차이 [44]

강한 스케일링은 모든 문제 크기에 대해 속도 향상을 제공한다.

약한 스케일링은 더 큰 문제를 해결하기 위해 더 많은 컴퓨팅 리소스를 사용할 때만 성능 향상을 보장한다.

### 2.3. 데이터 이동의 중요성 [47]

데이터 이동의 비효율성 [48]

런타임 및 스케일링 측면에서 계산은 저렴하고 데이터 이동은 비싸다.

현대 DRAM 셀은 수십 나노초 단위로 작동하는 반면, 트랜지스터는 서브 나노초 속도로 전환되므로 데이터 이동이 근본적으로 더 느리다.

메모리 병목 현상 [50]

2000년대 이후 계산 속도 향상이 둔화되었지만, 메모리 속도 향상은 더 느려져 메모리 병목 현상(memory wall)이 발생했다.

### 3.1. 텐서 코어 세대 개요 [52]

주요 NVIDIA GPU 아키텍처 [53]

Tesla V100 GPU (Volta)

A100 Tensor Core GPU (Ampere)

H100 Tensor Core GPU (Hopper)

Blackwell GPU

CUDA 프로그래밍 모델 복습 [54]

텐서 코어 이해를 돕기 위해 텐서 코어 이전 섹션을 포함한다.

주요 기능 및 변경 사항 [55]

각 하위 섹션에서 텐서 코어 이해에 관련된 주요 기능과 변경 사항을 간략하게 다룬다.

### 3.2. 텐서 코어 이전 (Pre-Tensor Core) [56]

PTX 프로그래밍 모델 [57]

정의: GPU 세대를 추상화하는 가상 명령어 세트이다. [58]

커널 함수: PTX 프로그램은 GPU 스레드(CUDA 코어에서 실행)에 의해 실행되는 커널 함수를 설명한다. [59]

스레드 구성: 스레드는 그리드(grid)로 구성되며, 그리드는 협력 스레드 배열(CTA)로 이루어진다. [61]

메모리 접근: PTX 스레드는 다양한 특성을 가진 여러 상태 공간(메모리 저장 영역)에서 데이터에 접근할 수 있다. [62]

스레드별 레지스터

CTA 내 스레드 간 공유 메모리

모든 스레드가 접근 가능한 전역 메모리

PTX 머신 모델 [66]

GPU 아키텍처: 스트리밍 멀티프로세서(SM) 배열을 중심으로 구축된다. [67]

SM 구성: SM은 스칼라 처리 코어, 멀티스레드 명령어 장치, 온칩 공유 메모리로 구성된다. [68]

스레드 관리: SM은 각 스레드를 스칼라 처리 코어(CUDA 코어)에 매핑하고, 멀티스레드 명령어 장치는 32개의 병렬 스레드 그룹인 워프(warp) 단위로 스레드를 관리한다. [69]

SIMT(Single-Instruction, Multiple Threads) 실행: 명령어 발행 시, 명령어 장치는 워프를 선택하고 워프의 스레드에 명령어를 발행한다. [70]

SIMT는 단일 명령어로 여러 처리 요소를 제어한다.

SIMD(Single-Instruction, Multiple Data)와 달리 SIMT는 벡터 너비 대신 단일 스레드 동작을 지정한다.

스트리밍 어셈블러 (SASS) [74]

정의: PTX가 가상화하는 아키텍처별 명령어 세트이다. [75]

문서화 부족: NVIDIA가 아키텍처 ISA 세부 정보를 경쟁사로부터 숨기기 때문에 SASS는 잘 문서화되어 있지 않다. [77]

### 3.3. Volta 아키텍처 [78]

텐서 코어 추가 이유 [79]

ML 워크로드 가속화 필요성: 딥러닝이 부상하면서 ML 워크로드에 하드웨어 가속이 필요하다는 인식이 생겼다. [80]

경쟁사의 움직임: 2015년 Google은 내부 ML 워크로드 가속을 위해 TPUv1을 배포했다. [81]

전력 비효율성: GPU는 명령어 발행 시 적은 에너지(~30pJ)를 소비하지만, HFMA와 같은 간단한 부동 소수점 연산은 훨씬 적은 에너지(1.5pJ)를 소비한다. [82]

이는 명령어에 필요한 전력이 부동 소수점 연산 자체에 필요한 전력보다 20배 더 많다는 것을 의미한다.

따라서 행렬 곱셈을 위한 많은 부동 소수점 연산은 전력 효율적이지 않다.

오버헤드 상쇄: 명령어 오버헤드를 상쇄하기 위해 명령어당 더 많은 계산을 수행할 수 있는 복잡한 명령어가 필요하다. [85]

HMMA 명령어 및 텐서 코어 도입: NVIDIA는 하프 정밀도 행렬 곱셈 및 누적(HMMA) 명령어를 설계하고, 이를 실행하기 위한 전용 하드웨어인 텐서 코어를 2017년 Volta 아키텍처의 Tesla V100 GPU에 도입했다. [86]

Volta 텐서 코어는 Volta 아키텍처 개발 막바지에 추가되었다.

MMA 명령어 개요 [88]

계산: 주어진 행렬에 대해 D = A * B + C를 계산한다. [89]

A는 M x K 행렬이다. [90]

B는 K x N 행렬이다. [91]

C와 D는 M x N 행렬이다. [92]

행렬 형태 표기: 행렬 형태는 mMnNkK 또는 MxNxK로 표기한다. [93]

계산 과정 [94]

로드: 공유 메모리에서 행렬 A, B, C를 스레드 레지스터로 로드하여 각 스레드가 행렬의 조각을 보유한다.

실행: MMA 명령어를 실행하여 스레드 레지스터에서 행렬을 읽고, 텐서 코어에서 계산을 수행하며, 결과를 스레드 레지스터에 저장한다.

저장: 스레드 레지스터의 결과를 공유 메모리로 다시 저장한다.

협력적 수행: 전체 계산은 여러 스레드에 의해 공동으로 수행되며, 각 단계에서 협력 스레드 간의 동기화가 필요하다.

1세대 텐서 코어 - 워프 스코프 MMA [99]

하드웨어 구성: Tesla V100 GPU의 SM은 8개의 텐서 코어를 포함하며, 두 개씩 그룹화된다. [100]

성능: 각 텐서 코어는 사이클당 4x4x4 행렬 곱셈에 해당하는 계산을 수행할 수 있으며, 이는 SM당 사이클당 1024 FLOPs에 해당한다. [101]

PTX 명령어 mma: NVIDIA는 하위 수준 HMMA 명령어를 대상으로 하는 PTX 명령어 mma를 설계했다. [102]

MMA 연산: Volta 아키텍처에서 MMA 명령어는 8x8x4 행렬 곱셈을 수행하며, 8개의 스레드로 구성된 쿼드페어(quadpair)가 입력 및 출력 행렬을 공동으로 보유하여 연산에 참여한다. [103]

T0은 스레드 0을 의미하며, [T0, T1, T2, T3]와 [T16, T17, T18, T19]는 스레드 그룹이고, 이 두 스레드 그룹이 쿼드페어를 형성한다.

데이터 유형: Volta 텐서 코어는 NVIDIA의 혼합 정밀도 훈련 기술에 맞춰 FP16 입력과 FP32 누적을 지원한다. [106]

이 기술은 모델 정확도를 잃지 않고 낮은 정밀도로 모델을 훈련할 수 있음을 보여주었다.

### 3.4. Turing 아키텍처 [111]

2세대 텐서 코어 [112]

Volta 텐서 코어의 향상된 버전으로, INT8 및 INT4 정밀도 지원을 추가했다.

새로운 MMA 지원 [113]

새로운 워프 수준 동기식 MMA를 지원한다.

딥러닝 적용 [114]

딥러닝 슈퍼 샘플링(DLSS)을 가능하게 하여 NVIDIA가 딥러닝을 게임 그래픽에 적용하기 시작했다.

### 3.5. Ampere 아키텍처 [116]

비동기 데이터 복사 (Asynchronous Data Copy) [117]

도입 배경: Volta에서는 스레드가 전역 메모리에서 레지스터로 데이터를 로드한 다음 공유 메모리에 저장해야 했다. [119]

MMA 명령어는 레지스터 사용량이 많아 데이터 로드 작업과 레지스터 파일을 공유해야 했다.

이로 인해 높은 레지스터 압력과 RF(Register File)로 데이터를 복사하는 데 메모리 대역폭 낭비가 발생했다. [120]

문제 완화: 비동기 데이터 복사는 전역 메모리(DRAM)에서 데이터를 가져와 공유 메모리(선택적 L1 접근 포함)에 직접 저장하여 MMA 명령어에 더 많은 레지스터를 확보한다. [121]

성능 향상: 데이터 로딩과 계산이 비동기적으로 발생할 수 있어 프로그래밍 모델 관점에서는 더 어렵지만, 더 높은 성능을 제공한다. [122]

구현: PTX 명령어 cp.async (스레드 수준 비동기 복사)로 구현된다. [123]

해당 SASS는 LDGSTS(전역에서 공유 메모리로의 비동기 복사)이다. [124]

정확한 동기화 메커니즘은 async-group 및 mbarrier 기반 완료 메커니즘이다. [125]

3세대 텐서 코어 - 워프 수준 동기식 MMA [126]

성능: Ampere는 SM당 4개의 텐서 코어를 가지며, 각 텐서 코어는 사이클당 512 FLOPs를 수행할 수 있어 SM당 사이클당 2048 Dense FLOPs를 달성하며 Volta의 성능을 두 배로 높였다. [127]

MMA 연산 참여 스레드 수: Volta가 8개의 스레드로 구성된 쿼드페어를 필요로 했던 반면, Ampere는 32개의 스레드로 구성된 전체 워프를 필요로 한다. [128]

MMA 명령어를 워프 단위로 처리하면 스레드 레이아웃이 단순화되고 Ampere의 RF 압력이 감소한다. [129]

예를 들어, 16x8x16 형태의 혼합 정밀도 부동 소수점 데이터에 대한 스레드 및 데이터 레이아웃은 다음과 같다. [130]

ldmatrix 명령어: Ampere에서 NVIDIA는 향상된 벡터화 로드 작업인 ldmatrix를 도입했다. [132]

ldmatrix는 mma와 마찬가지로 워프 단위로 작동하며, 워프의 스레드들이 공동으로 행렬을 로드한다. [133]

여러 로드 명령어를 발행하는 것에 비해 주소 생성 레지스터 사용을 줄여 레지스터 압력을 낮춘다. [134]

데이터 레이아웃 개선: ldmatrix는 텐서 코어의 데이터 레이아웃과 일치하는 레이아웃으로 데이터를 레지스터에 로드한다. [136]

Volta의 인터리브 패턴에 비해 더 간단한 스레드 및 데이터 레이아웃은 프로그래밍 편의성을 크게 향상시킨다.

BF16 지원: Ampere MMA는 하프 정밀도 데이터 유형의 사실상 표준이 된 BF16(Brain Floating Point Format)을 특징으로 한다. [139]

BF16은 FP32와 동일한 8비트 지수 범위를 제공하지만 7비트 가수부를 가지므로, 절반의 저장 비용으로 FP32 수준의 동적 범위를 허용한다. [140]

BF16은 또한 혼합 정밀도 훈련에서 손실 스케일링의 필요성을 없앤다. [141]

### 3.6. Hopper 아키텍처 [142]

스레드 블록 클러스터 (Thread Block Cluster) [143]

도입 배경: SM 수가 증가함에 따라 SM과 전체 GPU 간의 크기 불균형이 커졌다. [144]

새로운 계층: Hopper에서 NVIDIA는 CTA(SM에 매핑)와 그리드(전체 GPU에 매핑) 사이에 새로운 스레드 계층 수준인 스레드 블록 클러스터를 추가했다. [145]

이는 동일한 그래픽 처리 클러스터(GPC)에 물리적으로 위치한 SM 그룹에 매핑된다.

스레드 블록 클러스터는 협력 그리드 배열(CGA)이라고도 불리며, CUDA 문서에서는 클러스터로 지칭된다.

스케줄링 및 메모리: 스레드 블록 클러스터 내의 CTA는 동일한 GPC 내 SM에 공동 스케줄링되며, 기본적으로 SM당 하나의 CTA로 분산된다. [147]

이 SM들의 공유 메모리 파티션은 분산 공유 메모리(DSMEM)를 형성한다.

스레드는 전용 SM-to-SM 네트워크를 통해 낮은 지연 시간으로 다른 SM의 공유 메모리에 접근할 수 있다(L2 캐시를 거치지 않음). [149]

성능 향상: GPC 하드웨어 실행 단위를 프로그래밍 모델에 노출함으로써 프로그래머는 데이터 이동을 줄이고 데이터 지역성을 개선할 수 있다. [150]

텐서 메모리 가속기 (Tensor Memory Accelerator, TMA) [151]

도입 목적: 데이터 가져오기 효율성을 개선하기 위해 Hopper SM에 TMA를 추가했다. [152]

기능: TMA는 전역 메모리와 공유 메모리 간의 대량 비동기 데이터 전송을 가속화하는 전용 하드웨어 유닛이다. [153]

작동 방식: CTA의 단일 스레드가 TMA 복사 작업을 시작할 수 있다. [154]

TMA는 주소 생성을 처리하고 범위 외 처리와 같은 추가 이점을 제공하여 스레드가 다른 독립적인 작업을 실행할 수 있도록 해준다. [155]

PTX에서 해당 명령어는 cp.async.bulk이다. [156]

사용 권장 사항: 작은 요청의 경우 주소 생성 오버헤드 때문에 TMA 로드가 일반 비동기 데이터 복사보다 지연 시간이 길다. [157]

따라서 NVIDIA는 오버헤드를 상쇄하기 위해 대량 데이터 복사에 TMA를 사용할 것을 권장한다.

예를 들어, LLM 추론에서 TMA는 KV 캐시를 작은 청크로 로드하는 워크로드에는 적합하지 않지만, 각 청크가 16바이트의 배수일 때는 잘 작동한다. [159]

멀티캐스트 지원: TMA는 멀티캐스트 마스크로 지정된 스레드 블록 클러스터 내 여러 SM의 공유 메모리로 전역 메모리에서 데이터를 로드하는 멀티캐스트 모드를 지원한다. [161]

동일한 데이터를 여러 SM에 로드하기 위해 여러 전역 메모리 로드를 발행하는 대신, 멀티캐스트는 한 번의 로드로 이를 완료한다.

특히, 스레드 블록 클러스터 내 여러 CTA는 데이터의 일부를 해당 SMEM에 로드하고 DSMEM을 통해 데이터를 공유한다. [163]

이는 L2 캐시 트래픽을 줄이고 결과적으로 HBM 트래픽을 줄인다. [164]

4세대 텐서 코어 - 워프그룹 수준 비동기 MMA [166]

새로운 MMA 유형: Hopper에서 NVIDIA는 워프그룹 수준 MMA(wgmma)라는 새로운 유형의 MMA를 도입했다. [167]

워프그룹 단위 연산: wgmma는 워프그룹 단위로 작동하며, 4개의 워프로 구성된 워프그룹이 MMA 연산을 공동으로 수행한다. [168]

다양한 형태 지원: wgmma는 더 넓은 범위의 형태를 지원한다. [169]

예를 들어, 혼합 정밀도 MMA는 m64nNk16을 지원하며, 여기서 N은 8에서 256까지 8의 배수가 될 수 있다.

wgmma.mma_async는 새로운 SASS 세트인 GMMA로 변환된다. [170]

또 다른 예로, 하프 정밀도 wgmma 명령어는 HGMMA로 변환된다. [171]

공유 메모리 직접 로드: 워프그룹의 모든 스레드가 출력 행렬을 레지스터에 공동으로 보유하는 동안, Hopper 텐서 코어는 레지스터 대신 공유 메모리에서 피연산자를 직접 로드할 수 있어 레지스터 공간과 대역폭을 절약한다. [173]

특히, 피연산자 행렬 A는 레지스터 또는 공유 메모리에 있을 수 있으며, 피연산자 행렬 B는 공유 메모리를 통해서만 접근할 수 있다. [174]

데이터 유형: Hopper는 FP32 누적을 포함하는 8비트 부동 소수점 데이터 유형(E4M3 및 E5M2)을 도입했다. [177]

실제로는 누적 경로가 22비트 고정 소수점 형식(13비트 가수부와 부호 및 지수 비트)으로 구현되어, 진정한 32비트 누적에 비해 동적 범위가 제한된다. [178]

텐서 코어 정밀도 감소로 인해 훈련 정확도 제약을 방지하기 위해 N_c 누적마다 CUDA 코어에서 발생해야 한다. [179]

이 감소된 정밀도 누적은 효율성을 향상시키지만 정확도 손실을 초래한다. [181]

### 3.7. Blackwell 아키텍처 [192]

텐서 메모리 (Tensor Memory, TMEM) [194]

도입 배경: Hopper에서도 극심한 레지스터 압력이 지속되어 텐서 코어 연산에 특화된 새로운 메모리인 TMEM이 도입되었다. [194]

구성: 각 SM에는 128개의 행(레인)과 512개의 4바이트 셀 열이 있어 총 256KB이며, 이는 SM의 레지스터 파일 크기와 동일하다. [195]

제한된 접근 패턴: TMEM은 제한된 메모리 접근 패턴을 가진다. [196]

전체 TMEM에 접근하려면 워프그룹이 필요하며, 워프그룹 내 각 워프는 특정 레인 세트에만 접근할 수 있다.

메모리 접근 패턴을 제한함으로써 하드웨어 설계자는 접근 포트 수를 줄여 칩 공간을 절약할 수 있다.

이 설계는 에필로그(epilogue) 연산에도 워프그룹이 필요하다는 것을 의미한다.

명시적 관리: 공유 메모리와 달리 프로그래머는 TMEM의 할당, 할당 해제, 데이터 복사 등을 명시적으로 관리해야 한다. [200]

CTA 페어 (CTA Pair) [201]

정의: 스레드 블록 클러스터 내 두 CTA의 CTA 순위가 마지막 비트에서 다를 경우(예: 0과 1, 4와 5) CTA 페어를 형성한다. [202]

매핑: CTA 페어는 두 개의 SM으로 구성된 텍스처 처리 클러스터(TPC)에 매핑되며, 다른 TPC와 결합하여 GPC를 형성한다. [203]

피연산자 공유: Blackwell 텐서 코어 연산이 CTA 페어 단위로 수행될 때, 두 CTA는 입력 피연산자를 공유할 수 있다. [204]

이 공유는 SMEM 용량과 대역폭 요구 사항을 모두 줄인다. [205]

5세대 텐서 코어 MMA [206]

레지스터 사용 제거: 5세대 텐서 코어 MMA 명령어(tcgen05.mma in PTX)는 행렬을 보유하기 위해 레지스터를 사용하는 방식에서 완전히 벗어났다. [207]

이제 피연산자는 공유 메모리와 텐서 메모리에 상주한다. [208]

단일 스레드 의미론: tcgen05.mma는 단일 스레드 의미론을 가지며, 단일 스레드가 MMA 연산을 시작한다. [210]

이는 MMA 발행에서 워프의 역할을 제거한다. [211]

MMA.2SM 변형: 주목할 만한 MMA 변형은 MMA.2SM으로, 2개의 SM을 사용하여 MMA 연산을 공동으로 수행한다. [213]

MMA.2SM은 CTA-페어 수준의 세분성으로 실행되며, tcgen05.mma가 단일 스레드 의미론을 가지므로 CTA 페어의 리더 CTA에 있는 단일 스레드가 MMA.2SM을 시작한다. [214]

데이터 경로 조직 레이아웃 A: 레이아웃 A는 MMA.2SM이 1SM 버전(레이아웃 D)에 비해 M 차원을 두 배로 늘려 두 SM이 다른 행렬 A 및 D 타일을 로드함을 보여준다. [215]

또한 MMA.2SM은 행렬 B를 분할하여 로드되는 데이터 양을 절반으로 줄인다. [217]

행렬 B 공유: 행렬 B는 두 SM에 걸쳐 공유되므로, 타일 B0과 B1은 DSMEM을 통해 통신해야 한다. [218]

DSMEM과 SMEM 간의 대역폭 차이가 있지만, 더 작은 타일을 로드하므로 조정에 미치는 영향은 미미하다. [219]

Blackwell에서는 TPC 내 SM 간 통신 대역폭이 DSMEM보다 높아서 MMA.2SM이 더 나은 성능을 달성할 것으로 예상된다. [220]

컨볼루션 지원: 5세대 텐서 코어는 일반 행렬 곱셈 외에 컨볼루션도 수행할 수 있다. [221]

tcgen05.mma는 가중치 고정 패턴(weight stationary patterns)을 지원하며, 재사용을 위해 행렬 B를 캐시하는 컬렉터 버퍼를 사용한다. [222]

지원 데이터 유형: Blackwell은 MXFP8, MXFP6, MXFP4를 포함한 마이크로스케일링 부동 소수점 형식(MXFP)을 지원한다. [224]

Blackwell은 또한 MXFP4보다 더 정확하다고 알려진 NVIDIA 자체 NVFP4 형식을 지원한다. [225]

이는 더 작은 블록 크기, 다른 스케일링 팩터 데이터 형식, 그리고 2단계 양자화 방법 때문일 가능성이 높다.

FP8 및 FP6 처리: Blackwell에서 FP8과 FP6는 이론적 처리량이 동일하므로 텐서 코어 내에서 물리적 회로를 공유하는 것으로 보인다. [227]

대조적으로, CDNA4는 FP6 유닛이 FP4와 데이터 경로를 공유하기 때문에 FP8에 비해 2배의 FP6 처리량을 가진다. [228]

UDNA는 FP6 유닛을 FP8과 공유하도록 전환할 것으로 예상된다. [229]

### 3.8. 부록: 구조적 희소성 (Structured Sparsity) [230]

Ampere의 2:4 구조적 희소성 [231]

특징: Ampere는 2:4 구조적 희소성을 특징으로 하며, 이론적으로 텐서 코어 처리량을 두 배로 늘린다.

작동 방식: 가중치 행렬을 가지치기하여 4개의 요소마다 2개가 0이 되도록 한다.

메모리 절감: 이 형식에서는 0이 아닌 요소를 제거하여 행렬을 압축하고, 추가 메타데이터 인덱스 행렬이 그 위치를 기록하여 메모리 사용량과 대역폭을 약 절반으로 줄인다.

성능 향상 가능성 [234]

마이크로벤치마킹 논문에 따르면, Ampere의 구조적 희소성은 명령어 수준에서 대형 MMA 연산에 대해 2배의 속도 향상을 실현할 수 있다.

Hopper에서는 구조적 희소성 wgmma 명령어가 2배의 속도 향상을 달성하고 가중치 로드에 사용되는 메모리 대역폭을 최대 2배 절약할 수 있음을 보여준다.

실제 적용의 어려움 [236]

불행히도, 2:4 구조적 희소성 GEMM 커널은 Hopper에서 밀집된(dense) 커널에 비해 2배에 가까운 속도 향상을 달성하지 못한다.

이는 모델 정확도를 유지하면서 구조적 가지치기를 수행하는 어려움, 최적화되지 않은 cuSPARSELt 커널, 그리고 TDP(Thermal Design Power) 제한 때문이다.

대부분의 AI 연구소는 생산 추론을 위해 2:4 구조적 희소성을 무시하고 양자화 및 증류(distillation)에 집중한다.

Meta는 Llama에서 이를 실험하고 있지만, 많은 경우 막다른 길이다.

NVIDIA에 대한 권고 [240]

2:4 FP8 구조적 희소성 또는 4:8 FP4 구조적 희소성으로 성능 향상을 보이고 정확도 손실이 없는 폐쇄형 또는 오픈 모델이 부족하다.

구조적 가지치기에 전념하는 리소스도 부족하다.

NVIDIA는 키노트 및 마케팅 자료에서 젠슨(Jensen) 수학 구조적 희소성 FLOPs를 중단해야 한다.

SOTA 오픈 모델이 추론을 위해 구조적 가지치기를 활용할 수 있음을 지속적으로 보여주지 않는 한 말이다.

첫 번째 좋은 단계는 DeepSeek에 구조적 희소성을 적용하고, NVFP4와 같은 다른 기술(증류 및 양자화)과 함께 성능을 쌓을 수 있음을 보여주는 것이다.

Blackwell의 4:8 구조적 희소성 [243]

도입: 5세대 텐서 코어에서 NVIDIA는 NVFP4 데이터 유형에 대해 쌍별(pair-wise) 4:8 구조적 희소성을 도입했다.

작동 방식: 이 방식에서는 8개의 요소가 4개의 연속적인 쌍으로 그룹화되며, 이 중 정확히 2개의 쌍만 0이 아닌 값을 포함하고 나머지 2개는 0으로 가지치기된다.

도입 동기: NVFP4가 서브바이트(sub-byte) 데이터 유형이기 때문에 NVIDIA가 쌍별 4:8 패턴을 채택하도록 동기를 부여한 것으로 보인다.

제약 조건: 4:8 희소성이 이전 2:4 패턴보다 더 관대해 보일 수 있지만, 추가된 쌍별 요구 사항은 모델 정확도를 유지하면서 가지치기를 하려는 ML 엔지니어에게 실제로는 더 완화된 제약이 아니다.

### 3.9. 텐서 코어 크기 증가 [247]

텐서 코어 크기 확장 전략 [249]

NVIDIA는 세대를 거듭하며 텐서 코어의 수를 늘리기보다 텐서 코어의 크기를 더 적극적으로 확장했다.

이는 행렬 곱셈의 성능 특성에 더 적합하기 때문이다.

문제 크기를 확장할 때 행렬 곱셈 계산은 세제곱으로 증가하지만, 데이터 이동은 제곱으로 증가하여 산술 강도(arithmetic intensity)가 선형적으로 증가한다.

O(n) 산술 강도는 데이터 이동이 계산보다 비싸다는 사실과 결합되어 텐서 코어 크기 증가를 촉진했다.

양자화 효과의 비용 [254]

코어 크기와 코어 수 모두를 확장하는 것은 양자화 효과(quantization effects)의 비용을 수반한다.

많은 수의 코어는 타일 양자화 효과(tile quantization effect)로 인해 어려움을 겪는다.

큰 코어 크기는 웨이브 양자화 효과(wave quantization effect)를 초래한다.

웨이브 양자화 효과는 작업 단위 수가 작업자 수로 완전히 나누어지지 않을 때 발생하며, 최종의 더 작은 작업 배치를 처리할 때 활용률이 떨어진다.

텐서 코어 크기를 늘리는 것은 본질적으로 작업 단위 크기를 늘리는 것이므로, 작은 행렬에 대한 활용률이 낮아진다.

MMA 형태 증가의 동기 [259]

산술 강도의 선형적 증가는 MMA 형태 증가를 촉진한다.

더 큰 MMA 형태를 가지면 피연산자 공유의 세분성이 향상된다.

특히, 더 적은 수의 더 큰 타일을 시작하면 데이터 재사용이 증가하여 RF 및 SMEM의 메모리 공간과 대역폭을 절약할 수 있다.

Blackwell 이전 아키텍처에서는 MMA 연산을 공동으로 수행하기 위해 스레드 수를 늘리는 방향으로 이어졌다.

8개의 스레드로 구성된 쿼드페어(Volta)에서 32개의 스레드로 구성된 워프(Ampere), 그리고 128개의 스레드로 구성된 워프그룹(Hopper)으로 증가했다.

### 3.10. 메모리 크기 증가 [263]

공유 메모리 및 레지스터 파일 크기 변화 [265]

공유 메모리는 거의 모든 세대에서 증가한 반면, 레지스터 파일 크기는 일정하게 유지되었다.

이는 텐서 코어 처리량 증가에 더 깊은 스테이징 버퍼가 필요하기 때문이다.

스테이징 메모리의 필요성 [267]

텐서 코어가 전역 메모리보다 훨씬 빠르게 데이터를 소비하기 때문에, 메모리 로딩이 MMA 연산보다 앞서 실행될 수 있도록 데이터를 버퍼링하는 스테이징 메모리가 필요하다.

텐서 코어 처리량은 매 세대마다 두 배로 증가했지만, 전역 메모리 로드 지연 시간은 감소하지 않고 오히려 증가했다.

결과적으로 더 많은 데이터를 버퍼링하기 위해 스테이징 메모리 크기를 늘려야 했다.

NVIDIA는 텐서 코어의 스테이징 메모리로 공유 메모리를 선택했으며, 이는 공유 메모리가 증가하고 레지스터 파일 크기가 일정하게 유지된 이유를 설명한다.

Blackwell의 공유 메모리 [271]

Blackwell의 공유 메모리 크기는 Hopper에서 증가하지 않았다.

이는 tcgen05 MMA가 2개의 SM을 활용할 수 있으므로 각 SM의 공유 메모리는 피연산자의 절반만 로드하면 되기 때문이다.

따라서 Blackwell의 공유 메모리 크기는 사실상 두 배가 되었다.

TMEM 추가 및 이점 [274]

NVIDIA의 스테이징 메모리 선택은 피연산자 위치가 점차 레지스터에서 공유 메모리로 이동한 이유를 설명한다.

NVIDIA는 증가된 텐서 코어 처리량을 지원하기 위해 Blackwell에 TMEM을 추가했다.

TMEM은 텐서 코어에 더 가깝게 배치되어 전력 효율적이다.

또한, 별도의 메모리를 가지면 텐서 코어를 포화시키기 위한 총 메모리 대역폭이 증가한다.

모든 피연산자 중에서 행렬 D는 항상 TMEM에 유지된다.

행렬 D는 행렬 A와 B보다 더 자주 접근되므로, 이 설계로 TMEM의 전력 효율성을 활용할 수 있다.

예를 들어, 단순한 타일 행렬 곱셈에서 타일 D는 2Kt번 접근되는 반면(Kt번 읽기 및 Kt번 쓰기, Kt: K 차원 타일 수), 행렬 A 타일과 행렬 B 타일은 한 번만 접근된다.

### 3.11. MMA 명령어의 비동기성 [283]

MMA 명령어의 비동기적 진화 [287]

MMA 명령어는 겉보기에는 동기식에서 비동기식으로 갑자기 전환된 것처럼 보이지만, 실제로는 LDSM 명령어의 오버랩 필요성 때문에 SASS 수준에서 점진적으로 비동기화되었다.

SASS 수준의 MMA 연산 [289]

SASS 수준에서 MMA 연산은 공유 메모리에서 레지스터 파일로 행렬 타일을 로드하는 하나의 LDSM 명령어와 MMA를 수행하는 두 개의 HMMA 명령어를 실행하는 것을 포함한다.

실행 중 두 HMMA 명령어는 비동기적으로 발행되며, 하드웨어 인터록(interlock)으로 레지스터 사용을 차단한다.

하드웨어 인터록은 LDSM 명령어의 오버랩을 허용하지 않으므로, 하나의 LDSM과 두 개의 HMMA 명령어의 순차적 실행은 명령어 발행 파이프라인에 작은 버블(bubble)을 생성한다.

텐서 코어가 매우 빨라져 이 버블이 무시할 수 없는 성능 손실을 유발하게 되었고, 이는 MMA에 대한 비동기 완료 메커니즘의 필요성을 야기했다.

Hopper의 비동기 완료 메커니즘 [293]

Hopper는 wgmma에 대한 비동기 완료 메커니즘인 commit 및 fence를 지원한다.

HGMMA 명령어가 발행될 때 레지스터 사용을 보호하는 하드웨어 인터록이 없다.

대신 컴파일러는 다음 MMA를 위해 LDSM을 스케줄링하고, FENCE 명령어를 사용하여 다음 HGMMA가 대기하도록 한다.

Blackwell의 완전 비동기 MMA [296]

Blackwell에서는 MMA 연산이 완전히 비동기적이다.

텐서 메모리로 로드하는 명령어(tcgen05.ld, tcgen05.st, tcgen05.cp)는 모두 명시적으로 비동기적이다.

### 3.12. 데이터 유형 정밀도 감소 [299]

낮은 정밀도 데이터 유형 추가 [301]

NVIDIA는 텐서 코어의 각 세대마다 16비트에서 4비트에 이르는 낮은 정밀도 데이터 유형을 계속 추가하고 있다.

이는 딥러닝 워크로드가 낮은 정밀도에 매우 관대하기 때문이다.

특히 추론의 경우 훈련보다 더 낮은 정밀도를 사용할 수 있다.

낮은 정밀도는 전력 효율적이고, 실리콘 공간을 덜 차지하며, 더 높은 컴퓨팅 처리량을 달성한다.

최신 세대에서는 실리콘 면적 및 전력 예산 내에서 낮은 정밀도 데이터 유형을 우선시하기 위해 FP64 지원을 제거하는 경향도 보인다.

정수 데이터 유형 지원 변화 [306]

흥미롭게도 이러한 우선순위는 정수 데이터 유형 지원에도 영향을 미쳤다.

Hopper 이후 INT4 데이터 유형은 더 이상 사용되지 않으며, Blackwell Ultra에서는 INT8 컴퓨팅 처리량이 감소했다.

이는 낮은 정밀도 정수 데이터 유형의 인기가 지연되었기 때문이다.

Turing이 INT8과 INT4를 지원했지만, LLM 서비스에 INT4의 압축성을 활용할 수 있는 새로운 추론 양자화 방법이 등장하기까지 4년이 걸렸다.

그 무렵 NVIDIA는 이미 Hopper wgmma에서 INT4를 더 이상 사용하지 않게 되었다.
