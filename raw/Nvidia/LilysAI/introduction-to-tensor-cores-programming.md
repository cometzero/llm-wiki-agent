## 1. NVIDIA 텐서 코어의 이해 [1]

NVIDIA 텐서 코어는 AI 알고리즘 연산 비용의 90% 이상을 차지하는 행렬 곱셈에 특화된 가속 장치이다.

### 1.1. 텐서 코어의 역할 및 중요성 [4]

텐서 코어의 정의 [4]

NVIDIA GPU(Volta 마이크로아키텍처 이후)에 탑재된 행렬 곱셈 전용 가속 장치이다. [4]

AI 연산에서의 중요성 [5]

AI 알고리즘 연산 비용의 90% 이상이 행렬 곱셈에서 발생하므로, 전용 하드웨어의 존재는 매우 중요하다. [5]

정밀도 용어 이해의 필요성 [6]

NVIDIA 공식 문서에서 자주 언급되는 "하프 프리시전(half-precision)" 및 "싱글 프리시전(single-precision)"과 같은 용어의 의미를 이해해야 한다. [6]

### 1.2. 행렬과 컴퓨터 메모리 [8]

메모리 저장 방식 [9]

컴퓨터 메모리는 선형 주소 공간으로 표현되므로, 행렬을 2D 형태로 직접 저장할 수 없다. [9]

C/C++ 및 Python과 같은 언어는 2D 배열을 행 우선(row-major) 방식으로 저장한다. [11]

그림 1: 행렬 저장을 위한 행 우선 레이아웃

FORTRAN은 2D 배열을 열 우선(column-major) 방식으로 저장한다. [14]

요소 접근 방식 [15]

2D 인덱스를 선형화하여 요소에 접근한다. [15]

예를 들어, M x N 행렬 A에서 요소 (6, 8)의 선형화된 인덱스는 6 x N + 8이다. [16]

일반적으로 요소 (i, j)는 메모리 위치 i x N + j에 있다. [18]

### 1.3. 메모리 정밀도 [20]

기본 단위 [21]

비트(bit)는 가장 작고 기본적인 디지털 정보 단위이다. [21]

바이트(byte)는 8비트로 구성되며, 대부분의 컴퓨터 아키텍처에서 가장 일반적인 저장 단위이자 가장 작은 주소 지정 가능한 메모리 단위 중 하나이다. [22]

숫자 저장 방식 [23]

더블 프리시전(Double Precision) [24]

C/C++에서 double로 선언되며, 숫자를 저장하는 데 8바이트를 사용한다. [24]

싱글 프리시전(Single Precision) [26]

C/C++에서 float로 선언되며, 숫자를 저장하는 데 4바이트를 사용한다. [26]

메모리 공간을 덜 차지하지만, 정확도와 표현 가능한 값의 범위가 줄어든다. [27]

정밀도 비교 [29]

싱글 프리시전은 약 7자리의 십진수 정밀도를 제공하며, 약 1.4×10−45에서 3.4×1038까지의 숫자를 표현할 수 있다. [29]

더블 프리시전은 약 15-17자리의 십진수 정밀도를 제공하며, 약 4.9×10−324에서 1.8×10308까지의 숫자를 표현할 수 있다. [30]

그림 2: 싱글 프리시전 vs 더블 프리시전

하프 프리시전(Half-Precision) [32]

2바이트를 사용하는 부동 소수점 숫자이다. [32]

표준 C++에서는 기본적으로 지원되지 않지만, CUDA는 half 타입으로 하프 프리시전을 사용할 수 있는 옵션을 제공한다. [33]

텐서 코어는 하프 프리시전으로 작동한다. [34]

### 1.4. 텐서 코어 프로그래밍 [35]

텐서 코어의 연산 [36]

텐서 코어는 행렬 곱셈 및 누적 연산(D = A ⋅ B + C)을 수행한다. [36]

C를 0으로 초기화하면 순수한 행렬 곱셈을 수행할 수 있다. [37]

입력 및 출력 정밀도 [38]

텐서 코어는 일반적으로 하프 프리시전(FP16) 입력을 받아 싱글 프리시전(FP32) 출력을 생성하도록 설계되었다. [38]

행렬 차원 제한 [39]

텐서 코어는 특정 행렬 차원에 제한되며, 그림 3은 4x4 입력 및 출력의 예시를 보여준다. [39]

그림 3: 텐서 코어 곱셈 및 누적 (출처: NVIDIA)

임의 행렬 크기 처리 [41]

16x16 행렬 차원으로 작업하며, 임의의 행렬 크기는 16의 배수가 되도록 0으로 패딩한 후 여러 16x16 타일로 분할하여 행렬 곱셈을 수행한다. [41]

워프 레벨 작업 [43]

텐서 코어는 CUDA 코어와 달리 워프(warp) 레벨에서 작동한다. [43]

즉, 워프 내의 모든 스레드(32개 스레드)가 협력하여 하나의 16x16 행렬 곱셈 및 누적 연산을 수행한다. [44]

## 2. 텐서 코어를 활용한 행렬 곱셈 구현 [45]

텐서 코어를 활용한 행렬 곱셈은 타일링, 워프 기반 연산, 그리고 CUDA의 WMMA API를 통해 효율적으로 구현된다.

### 2.1. 텐서 코어 기반 행렬 곱셈 예시 [45]

32x32 행렬 곱셈 분할 [45]

텐서 코어가 16x16 행렬만 처리할 수 있으므로, 32x32 행렬 A, B, C는 각각 4개의 16x16 타일로 분할된다. [45]

2x2 그리드에 4개의 블록을 정의하며, 각 블록은 32개의 스레드(단일 워프)를 포함하고 출력 행렬 C의 한 타일을 계산한다. [46]

그림 4: 텐서 코어를 사용한 행렬 곱셈

타일 계산 단계 [49]

각 D 타일은 두 단계로 계산된다. [49]

1단계: 32개 스레드가 행렬 A와 B의 타일(0,0)을 텐서 코어에 로드하고 부분 행렬 곱셈을 수행한다. [50]

2단계: 동일한 32개 스레드가 행렬 A의 타일(0,1)과 행렬 B의 타일(1,0)을 로드하여 행렬 곱셈을 완료한다. [51]

그림 5: 텐서 코어를 사용한 타일링 행렬 곱셈

데이터 로딩 추상화 [54]

타일이 코어 자체에 로드되는 것은 아니지만, 프로그래머는 전역 메모리에서 텐서 코어로 데이터가 이동하는 방식에 대해 걱정할 필요가 없다. [54]

### 2.2. 텐서 코어 프로그래밍 코드 예시 [56]

타일 크기 및 블록 정의 [56]

GPU에 맞춰 타일 크기를 16x16으로 설정하고, 각 블록에 32개의 스레드를 사용하여 필요한 블록 수를 정의한다. [56]

커널 함수 및 워프 식별 [59]

커널 함수 내에서 현재 작업 중인 워프를 식별한다. [60]

텐서 코어는 워프 레벨에서 작동하며, 각 블록에 하나의 워프를 유지하여 단순성을 높인다. [61]

프래그먼트 메모리 할당 [63]

텐서 코어는 행렬의 일부를 나타내는 데이터 구조인 프래그먼트(fragments)를 사용한다. [64]

하드웨어 수준에서 프래그먼트는 워프 스레드의 레지스터에 로드되지만, CUDA는 수동 데이터 이동 없이 편리한 방법을 제공한다. [67]

프래그먼트 정의 시 다음을 지정해야 한다. [70]

행렬 A, B 또는 C인지 여부 [70]

WMMA_M, WMMA_N, WMMA_K를 사용한 프래그먼트 크기 [71]

데이터의 정밀도(half 또는 float) [72]

데이터의 메모리 레이아웃(행 우선 또는 열 우선) [73]

출력 행렬 D에는 누적기(accumulator)를 사용하는데, 이는 행렬 곱셈이 여러 단계로 수행되고 각 단계의 결과가 이전 단계 결과에 추가되기 때문이다. [76]

출력 프래그먼트 초기화 및 입력 행렬 분할 [77]

출력 행렬 프래그먼트를 0으로 초기화하고, 루프를 사용하여 입력 행렬을 여러 타일로 분할한다. [77]

타일 로드 및 행렬 곱셈 수행 [79]

워프 내의 모든 스레드가 협력하여 텐서 코어에서 계산할 타일을 로드한다. [79]

워프가 타일의 왼쪽 상단 요소를 가리키도록 설정하면, nvcuda::wmma::load_matrix_sync()를 사용하여 적절한 타일이 텐서 코어에 로드된다. [80]

타일이 로드되면 nvcuda::wmma::mma_sync()를 사용하여 행렬 곱셈을 한 줄로 수행할 수 있다. [82]

결과 저장 [84]

최종 결과가 출력 프래그먼트에 저장되면, 유사한 방식으로 전역 메모리에 다시 저장할 수 있다. [84]

CUDA는 텐서 코어와 편리하게 작업할 수 있는 방법을 제공하며, 이는 NVIDIA 성공의 큰 이유 중 하나이다. [85]

### 2.3. GFLOPS의 중요성 [87]

성능 분석 지표 [88]

실행 시간도 유효한 분석 지표이지만, 초당 수행되는 연산 수 또는 GFLOPS(Giga Floating-Point Operations per Second)를 살펴보는 것이 더 나은 옵션이다. [88]

GFLOPS 계산 [90]

M x K 행렬과 K x N 행렬을 곱할 때, 각 출력 행렬 요소는 약 K개의 곱셈과 K개의 덧셈, 즉 2K개의 연산을 필요로 한다. [90]

총 M x N개의 출력 요소가 있으므로, 총 연산 수는 2 x M x N x K이다. [91]

이 값을 행렬 곱셈 수행 시간으로 나누면 구현된 알고리즘의 FLOPS(GFLOPS로 변환 가능)를 얻을 수 있다. [92]
