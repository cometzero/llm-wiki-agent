## 1. AI 추론 지연 시간 단축을 위한 추측 디코딩 소개 [1]

추측 디코딩은 LLM 텍스트 생성의 고질적인 지연 시간 문제를 해결하기 위해 여러 토큰을 동시에 예측하고 검증하여 AI 추론 속도를 높이는 기술이다.

### 1.1. 추측 디코딩의 개념 [9]

정의 및 작동 방식 [10]

추측 디코딩은 타겟 모델과 경량 드래프트 메커니즘을 결합한 추론 최적화 기술이다. [10]

드래프트 메커니즘이 다음 토큰들을 빠르게 제안하면, 타겟 모델은 이를 단일 포워드 패스로 검증하고 예측과 일치하는 가장 긴 접두사를 수락한다. [11]

이 기술은 표준 자기회귀 디코딩(패스당 1개 토큰 생성)과 달리 여러 토큰을 한 번에 생성하여 정확도에 영향을 주지 않으면서 지연 시간을 단축하고 처리량을 높인다. [12]

LLM의 한계 극복 [13]

LLM은 AI 하드웨어의 한계를 넘어서는 경우가 많아 사용자 경험을 최적화하기 어렵다. [13]

추측 디코딩은 작업의 일부를 덜 자원 집약적인 모델에 오프로드하여 이 문제를 해결한다. [14]

작동 원리 비유 [15]

추측 디코딩은 실험실의 수석 과학자가 경험이 적지만 효율적인 조수에게 일상적인 실험을 맡기는 방식과 유사하다. [15]

경량 조수 모델이 여러 가능한 연속을 제안하면, 대규모 모델이 이를 일괄적으로 검증한다. [17]

궁극적인 이점은 순차적 단계 수를 줄여 메모리 대역폭 병목 현상을 완화하는 것이다. [18]

검증 메커니즘은 기본 모델이 생성할 수 있는 결과와 다른 모든 결과를 폐기하므로, 출력 품질을 유지하면서 가속화가 이루어진다. [19]

## 2. 추측 디코딩의 기본 원리: 드래프트-타겟 및 EAGLE-3 [20]

추측 디코딩은 드래프트-타겟 접근 방식과 EAGLE-3와 같은 고급 기술을 통해 토큰 생성의 효율성을 높인다.

### 2.1. 드래프트-타겟 접근 방식 [25]

개념 [26]

드래프트-타겟 접근 방식은 추측 디코딩의 고전적인 구현으로, 두 개의 모델 시스템으로 작동한다. [26]

주 모델은 출력을 가속화하려는 대규모 고품질 타겟 모델이다. [27]

이와 함께 작동하는 모델은 훨씬 작고 빠른 드래프트 모델로, 종종 타겟 모델의 증류되거나 단순화된 버전이다. [28]

작동 방식 비유 [29]

실험실 과학자 비유로 돌아가면, 타겟 모델은 정확성을 보장하는 꼼꼼한 과학자이고, 드래프트 모델은 과학자가 검증할 가능성을 제안하는 빠른 조수이다. [29]

다음 그림은 드래프트 모델이 4개의 드래프트 토큰을 빠르게 생성하고, 타겟 모델이 2개를 검증하고 유지하며 추가로 1개의 토큰을 자체적으로 생성하는 과정을 보여준다. [30]

그림 1. 추측 디코딩의 드래프트-타겟 접근 방식은 두 모델 시스템으로 작동한다.

단계별 과정 [32]

드래프트 생성 [33]

더 작고 효율적인 메커니즘이 후보 토큰 시퀀스(일반적으로 3~12개 토큰)를 생성한다. [34]

일반적으로 이는 동일한 데이터 분포에서 훈련된 별도의 소규모 모델 형태를 취한다. [35]

타겟 모델의 출력은 일반적으로 드래프트 모델 훈련의 정답 역할을 한다. [36]

병렬 검증 [37]

타겟 모델은 단일 포워드 패스에서 입력 시퀀스와 모든 드래프트 토큰을 동시에 처리하여 각 위치에 대한 확률 분포를 계산한다. [38]

이 병렬 처리는 순차적 생성 중 타겟 모델의 계산 능력이 충분히 활용되지 않는 것을 방지하여 핵심적인 효율성 향상을 가져온다. [39]

KV 캐시 덕분에 원래 접두사에 대한 값은 이미 계산되어 저장되었으므로, 이 검증 패스 동안 새로운 추측 토큰만 계산 비용이 발생한다. [40]

검증된 토큰은 다음 생성 단계의 새로운 접두사를 형성하도록 선택된다. [41]

거부 샘플링 [42]

거부 샘플링은 타겟 모델에서 확률 분포가 생성된 후 발생하는 의사 결정 단계이다. [43]

거부 샘플링의 핵심은 수락 로직이다. [44]

다음 그림과 같이 이 로직은 드래프트 모델의 제안된 확률 P(Draft)를 타겟 모델의 실제 확률 P(Target)와 비교한다. [45]

그림 2. 수락 로직은 병렬 검증 중 거부 샘플링의 핵심 측면이다.

처음 두 토큰인 "Brown"과 "Fox"의 경우 P(Target)이 P(Draft)보다 높으므로 수락된다. [46]

그러나 "Hopped"의 경우 P(Target)이 P(Draft)보다 현저히 낮아 신뢰할 수 없는 예측임을 나타낸다. [47]

"Hopped"와 같은 토큰이 수락 로직에 의해 거부되면, 해당 토큰과 드래프트의 모든 후속 토큰은 폐기된다. [48]

그런 다음 프로세스는 마지막으로 수락된 토큰인 "Fox"부터 표준 자기회귀 생성으로 되돌아가 수정된 토큰을 생성한다. [49]

드래프트 토큰이 타겟 모델이 생성했을 내용과 일치할 때만 수락된다. [51]

이 엄격한 토큰별 검증은 최종 출력이 타겟 모델이 생성했을 내용과 동일함을 보장하여 속도 향상이 정확도 손실 없이 이루어지도록 한다. [52]

총 생성량 대비 수락된 토큰 수는 수락률이다. [53]

수락률이 높을수록 속도 향상이 더 크며, 최악의 경우 모든 드래프트 토큰이 거부되면 단일 타겟 모델 토큰만 생성된다. [54]

### 2.2. EAGLE 접근 방식 [55]

개념 [56]

EAGLE(Extrapolation Algorithm for Greater Language-Model Efficiency)은 타겟 모델의 출력 헤드 바로 앞의 숨겨진 상태에서 외삽하여 피처 수준에서 작동하는 추측 디코딩 방법이다. [56]

별도의 드래프트 모델에 의존하여 토큰을 제안하는 드래프트-타겟 접근 방식과 달리, EAGLE은 타겟 모델의 숨겨진 상태에서 피처를 수집하는 경량 자기회귀 예측 헤드를 사용한다. [57]

이는 두 번째 모델을 훈련하고 실행하는 오버헤드를 제거하면서도 타겟 모델이 단일 포워드 패스당 여러 토큰 후보를 검증할 수 있도록 한다. [58]

EAGLE-3의 특징 [59]

EAGLE-3는 타겟 모델의 저수준, 중간 수준, 고수준 임베딩을 직접 드래프팅 헤드로 가져오는 다층 융합 피처 표현을 도입하여 이 기반을 구축한다. [59]

또한 컨텍스트 인식 동적 드래프트 트리(EAGLE-2에서 상속)를 사용하여 여러 연결된 가설을 제안한다. [60]

이러한 후보 토큰은 병렬 트리 어텐션을 사용하여 타겟 모델에 의해 검증되어 유효하지 않은 분기를 효과적으로 가지치기하고 수락률과 처리량을 모두 향상시킨다. [61]

다음 그림은 이러한 흐름을 보여준다. [62]

그림 3. EAGLE-3 드래프팅 메커니즘은 타겟 모델에서 후보 토큰 트리를 생성한다.

EAGLE 헤드 [64]

드래프트-타겟 접근 방식처럼 별도의 소규모 모델을 사용하는 대신, EAGLE-3는 타겟 모델의 내부 레이어에 경량 드래프팅 구성 요소를 "EAGLE 헤드"로 부착한다. [65]

EAGLE 헤드는 일반적으로 경량 트랜스포머 디코더 레이어와 최종 선형 레이어로 구성된다. [65]

이는 본질적으로 주 모델을 구성하는 빌딩 블록의 축소된 버전이다. [66]

이 EAGLE 헤드는 단일 시퀀스뿐만 아니라 전체 후보 토큰 트리를 생성할 수 있다. [67]

이 프로세스는 또한 인스턴스 적응형으로, 헤드가 트리를 구축하면서 자체 신뢰도를 평가하고 신뢰도가 임계값 아래로 떨어지면 드래프팅을 중지한다. [68]

이를 통해 EAGLE 헤드는 여러 생성 경로를 효율적으로 탐색하여 예측 가능한 텍스트의 더 긴 분기와 복잡한 부분에 대한 더 짧은 분기를 생성하며, 이 모든 것이 타겟 모델의 단일 포워드 패스 실행 비용으로 이루어진다. [69]

### 2.3. DeepSeek-R1의 다중 토큰 예측(MTP) [70]

개념 [71]

EAGLE과 유사하게, 다중 토큰 예측(MTP)은 DeepSeek의 여러 반복에서 사용되는 추측 기술로, 모델이 다음 토큰 하나만이 아니라 여러 미래 토큰을 한 번에 예측하도록 학습한다. [71]

MTP는 각 헤드가 토큰 드래프터 역할을 하는 다중 헤드 방식을 사용한다. [72]

모델에 부착된 첫 번째 헤드는 첫 번째 드래프트 토큰을 추측하고, 다른 헤드는 그 다음 토큰을, 또 다른 헤드는 세 번째 토큰을 추측하는 식이다. [73]

주 모델은 이러한 추측을 순서대로 확인하고 일치하는 가장 긴 접두사를 유지한다. [74]

이 방법은 별도의 드래프팅 모델의 필요성을 자연스럽게 제거한다. [75]

EAGLE과의 차이점 [76]

본질적으로 이 기술은 EAGLE 스타일의 추측 디코딩과 유사하며, 둘 다 검증을 위해 여러 토큰을 제안한다. [76]

그러나 제안이 형성되는 방식에서 차이가 있다. MTP는 특수화된 다중 토큰 예측 헤드를 사용하는 반면, EAGLE은 내부 피처 상태를 외삽하여 후보를 구성하는 단일 헤드를 사용한다. [77]

## 4. 추측 디코딩이 추론 지연 시간에 미치는 영향 [107]

추측 디코딩은 표준 자기회귀 생성의 고정된 순차적 비용으로 인한 핵심 지연 시간 병목 현상을 해결한다.

### 4.1. 지연 시간 단축 원리 [108]

표준 자기회귀 생성의 지연 시간 [108]

표준 자기회귀 생성의 핵심 지연 시간 병목 현상은 각 단계의 고정된 순차적 비용이다. [108]

단일 포워드 패스(가중치 로드 및 토큰 계산)에 200밀리초가 걸린다면, 3개의 토큰을 생성하는 데는 항상 600밀리초(3개의 순차적 단계 * 200밀리초)가 걸린다. [109]

사용자는 이 지연을 개별적인 누적 대기 시간으로 경험한다. [110]

추측 디코딩을 통한 지연 시간 단축 [111]

추측 디코딩은 이러한 여러 대기 시간을 하나로 통합할 수 있다. [111]

빠른 드래프트 메커니즘을 사용하여 두 개의 후보 토큰을 추측한 다음 단일 250밀리초 포워드 패스에서 모두 검증함으로써, 모델은 600밀리초 대신 250밀리초 만에 3개의 토큰(두 개의 추측 + 하나의 기본 모델 생성)을 생성할 수 있다. [112]

## 5. 추측 디코딩 시작하기 [119]

추측 디코딩은 LLM 추론을 가속화하기 위한 근본적인 전략이 되고 있다.

### 5.1. 추측 디코딩의 중요성 및 미래 [120]

핵심 전략으로서의 추측 디코딩 [120]

드래프트-타겟 생성 및 병렬 검증의 기본부터 EAGLE-3와 같은 고급 방법에 이르기까지, 이러한 접근 방식은 순차적 토큰 생성 중 유휴 컴퓨팅이라는 핵심 과제를 해결한다. [121]

추측 디코딩은 LLM 추론을 가속화하기 위한 근본적인 전략이 되고 있다. [120]

확장성 및 효율성 [122]

작업량이 증가하고 더 빠른 응답 시간과 더 나은 시스템 효율성에 대한 요구가 증가함에 따라, 추측 디코딩과 같은 기술은 점점 더 중요한 역할을 할 것이다. [122]

이러한 방법을 NVIDIA TensorRT-LLM, SGLANG 및 vLLM과 같은 프레임워크와 결합하면 개발자가 실제 환경에서 더 성능이 좋고, 더 실용적이며, 더 비용 효율적인 모델을 배포할 수 있다. [123]
