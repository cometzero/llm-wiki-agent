## 1. GPU 소개 [1]

GPU는 높은 지연 시간을 가지지만, 압도적인 처리량을 통해 딥러닝과 같이 병렬 연산이 많은 작업에서 뛰어난 성능을 발휘한다.

### 1.1. GPU의 성능 특성 [4]

GPU의 강력한 연산 능력 [4]

최신 NVIDIA RTX 4090 GPU는 이론적으로 1.3테라플롭/s의 FP64 연산을 수행할 수 있다. [5]

이는 2006년까지 사용된 7천만 달러 규모의 슈퍼컴퓨터 ASCI Red와 비슷한 성능이다. [5]

RTX 4090은 저정밀도 연산에 최적화되어 있어, 실제로는 ASCI Red보다 훨씬 뛰어나다. [6]

2000년 TOP500에서 1위를 차지한 ASCI Red 슈퍼컴퓨터 [9]

CPU와 GPU의 성능 비교: 지연 시간 vs. 처리량 [10]

GPU는 근본적으로 처리량(throughput)에 최적화된 장치이며, 지연 시간(latency)에 최적화되어 있지 않다. [10]

대부분의 지표에서 CPU가 GPU보다 훨씬 낮은 지연 시간(더 빠름)을 가진다. [15]

스레드 간 통신 지연 시간도 CPU가 훨씬 빠르다. [16]

CPU는 59ns 만에 스레드 간 통신을 완료할 수 있지만, GPU는 스트리밍 멀티프로세서(SM) 간 직접 통신 메커니즘이 없어 이 지표가 정의되지 않는다. [18]

GPU의 강점: 높은 병렬 연산 능력 [19]

GPU는 높은 지연 시간과 블록 간 통신 부족에도 불구하고, CPU에 비해 연산에 훨씬 더 많은 칩 다이 영역을 할애한다. [20]

이는 직렬 통신이 적고 연산량이 많은 작업에서 GPU가 탁월한 성능을 발휘하게 한다. [21]

GPU와 CPU의 비유는 다음과 같다. [22]

GPU는 스쿨버스와 같아서, 만차일 때 A 지점에서 B 지점으로 이동하면 '인원-마일/시간' 지표에서 뛰어난 성능을 보인다. [23]

CPU는 스포츠카와 같아서, A 지점에서 B 지점으로 훨씬 빠르게 이동할 수 있지만 '인원-마일/시간' 지표에서는 스쿨버스를 따라갈 수 없다. [24]

스쿨버스가 전통적으로 '빠르다'고 생각되지 않지만, 올바르게 활용하면 가장 빠른 경주용 자동차도 따라올 수 없는 '인원-마일/시간' 지표를 제공할 수 있다. [25]

### 1.2. GPU와 딥러닝 [26]

딥러닝 혁신과 GPU의 역할 [27]

2012년 토론토 대학 팀은 ImageNet 챌린지에서 기록을 경신했다. [27]

이전에는 대부분의 컴퓨터 비전 커뮤니티가 수작업으로 설계된 특징 추출기와 전통적인 머신러닝 알고리즘을 사용했다. [28]

Alex K, Ilya S, Geoff H는 충분한 데이터와 연산 능력이 주어지면 인공 신경망이 수작업 방식보다 훨씬 뛰어난 특징을 학습할 수 있음을 보여주었다. [30]

AlexNet 논문의 혁신은 알고리즘적이라기보다는 Alex K의 GPU 프로그래밍 전문 지식 덕분이라고 할 수 있다. [32]

이 돌파구는 최근 딥러닝 발전의 폭발적인 성장을 이끌었으며, ImageNet 데이터셋 전체를 처리할 만큼 충분히 큰 신경망을 훈련시킬 계산 능력과 GPGPU(범용 GPU) 코드가 핵심이었다. [33]

Alex Krizhevsky의 2011년 오리지널 CUDA 코드는 여전히 Google Code에 보관되어 있다. [37]

딥러닝 워크로드에 이상적인 GPU 특성 [40]

딥러닝은 GPU의 대규모 병렬 처리 능력에 매우 적합한 특성을 가진다. [40]

특히, 토론토 대학 팀이 훈련시킨 컨볼루션 신경망은 대량의 고도로 병렬적인 연산(행렬 곱셈)을 포함했다. [41]

2012년 이후 인공 신경망은 더 큰 GPU 클러스터에서 더 많은 데이터를 처리하며 거의 모든 문제에서 기록을 경신했다. [42]

CNN, RNN, 트랜스포머, SSM 등 다양한 신경망 아키텍처가 등장했지만, 딥러닝의 핵심 요소인 대량의 행렬 곱셈은 크게 변하지 않았다. [43]

GPU 외 딥러닝 가속기 및 미래 전망 [46]

GPU가 딥러닝 워크로드를 가속화하는 유일한 방법은 아니며, 향후 몇 년간 다른 접근 방식들과 경쟁할 것이다. [46]

주요 경쟁자로는 TPUs (Google), Dojo/AP car computer (Tesla), WSE (Cerebras), Grayskull (Tenstorrent), IPUs (Graphcore), 그리고 아날로그 멤리스터 기반 기술 (Rain) 등이 있다. [47]

저자는 장기적인 관점에서 딥러닝 추론을 위한 GPU(및 폰 노이만 아키텍처 기반의 모든 것)에 대해 회의적이다. [48]

생물학적 신경망과 인공 신경망이 추상적인 수준에서 크게 다르지 않다고 믿는 입장이다. [49]

만약 생물학적 뉴런이 발화할 때마다 시냅스에 도달한 활동 전위가 수천 개의 뉴런 떨어진 곳으로 이동하여 '가중치'를 찾아야 한다면, 우리의 뇌는 엄청나게 비효율적일 것이다. [50]

그러나 이것이 현대 GPU가 하는 일과 본질적으로 같으며, 연산 자체보다 메모리 이동에 많은 에너지를 소비한다. [52]

32비트 DRAM 읽기 에너지 소비는 32비트 곱셈의 약 200배이다! [61]

하드웨어에 가중치가 구현된 아날로그 방식은 개발 및 확장에 시간이 걸리겠지만, 디지털 방식보다 많은 내적(dot-product) 연산에 더 적합할 것이다. [53]

매우 작은 기계식 스프링으로 딥러닝 가속기를 만드는 사고 실험을 할 수 있다. [54]

스프링의 거동을 지배하는 훅의 법칙(F=kx)은 인공 뉴런의 입력(y=wx)과 같은 형태를 가진다. [55]

압축/인장 스프링을 다른 강성(가중치)으로 플레이트(뉴런)에 연결하고, 플레이트가 음의 방향으로 변위되는 것을 막아 ReLU 비선형성을 구현할 수 있다. [56]

이를 확장하면 신경망 추론을 위한 놀랍도록 에너지 효율적인 메커니즘을 만들 수 있다. [57]

입력 플레이트를 조절하고 출력 플레이트의 위치를 측정하기만 하면 되며, 유일한 에너지 손실은 내부 스프링 응력으로 인한 최소한의 열 발생뿐이다. [58]

이는 실용적이지 않을 수 있지만, 뉴런이라는 아이디어가 얼마나 우아하고 보편적인지를 보여준다. [59]

GPU가 인공 일반 지능을 위한 계산 기판 탐구의 최종 단계일 가능성은 매우 낮다. [60]

## 2. GPU 메모리 [63]

GPU 메모리는 계층 구조로 나뉘며, 각 계층은 용량과 지연 시간 사이의 균형을 이룬다.

### 2.1. GPU 메모리 유형 [64]

글로벌 메모리 (Global Memory, GMEM) [64]

GPU에서 가장 큰 메모리 유형으로, DRAM(Dynamic Random Access Memory)으로 구현되며 칩 외부에 저장된다. [64]

NVIDIA Kepler 아키텍처 GPU에 표시된 DRAM 오프칩 모듈 [65]

DRAM의 각 비트는 전하를 저장하는 커패시터와 읽기/쓰기 접근을 제어하는 트랜지스터로 저장된다. [66]

커패시터는 시간이 지남에 따라 전하가 누설되므로, DRAM 셀은 지속적인 새로고침(일반적으로 각 행에 대해 ~20Hz)이 필요하다. [68]

"워드 라인"에 평행한 두 개의 인접한 DRAM 저장 셀의 단면 전자 현미경 사진 [69]

DRAM 읽기 과정 [70]

워드 라인은 DRAM 그리드의 어떤 행을 인덱싱할지 선택하고, 비트 라인은 열 선택을 허용하며 실제 1 또는 0을 읽기 작업을 완료하기 위해 행 버퍼로 전달한다. [70]

읽기 수행 시, 행 버퍼는 처음에 알려진 중립 값(~0.5V)으로 사전 충전되어 워드 라인 활성화 후 전하가 손상되지 않도록 한다. [71]

다음으로 워드 라인이 활성화되어 해당 행의 모든 비트를 행 버퍼로 가져온다. [72]

각 비트 라인은 행 버퍼의 센스 증폭기에 연결되어 비트 커패시터에 연결된 작은 전위차를 완전한 디지털 1 또는 0으로 변환한다. [73]

이 증폭된 값은 비트를 커패시터에 다시 쓰는 데(방금 방전되었으므로) 사용되며, 이 값을 메모리 컨트롤러로 전달한다. [73]

DRAM 접근 효율성 [74]

워드 라인을 활성화하면 해당 행의 모든 비트가 센스 증폭기로 들어오므로, 비트를 순차적으로 읽는 것이 다른 행의 비트를 읽는 것보다 훨씬 효율적이다. [74]

다른 행에 접근해야 할 경우, 메모리 컨트롤러는 행 버퍼를 중립 전위로 사전 충전하고 새로운 워드 라인을 활성화하는 시간이 많이 소요되는 단계를 수행해야 한다. [75]

이러한 이유로 DRAM의 진정한 '랜덤 접근'은 메모리 처리량의 심각한 병목 현상을 초래할 수 있다. [76]

DRAM 로드에 관련된 단계를 보여주는 다이어그램 [77]

메모리 정렬(Memory Alignment) [79]

DRAM에서 데이터를 접근하기 위해 여러 행을 읽어야 하는 것은 바람직하지 않다. [80]

논리적 메모리 배치가 물리적 메모리 뱅크와 어떻게 정렬되는지에 따라, 정렬되지 않은 레이아웃은 과도한 캐시 라인 트랜잭션/행 버퍼 로드를 유발할 수 있다. [81]

CUDA 커널에서 글로벌 메모리 접근을 최적화할 때 행 버퍼에 대해 직접 생각할 필요는 없지만, 각 로드에서 가능한 한 적은 캐시 라인을 건드려야 한다. [82]

RTX 3090의 경우, 이는 글로벌 메모리에서 가능한 한 적은 128바이트 정렬 로드를 수행하는 것을 의미한다. [83]

정렬되지 않은 메모리 접근 [84]

SRAM (Static Random Access Memory) [85]

SRAM은 GPU의 다른 모든 메모리 저장소가 구성되는 메모리 유형이다. [85]

일반적으로 교차 결합 인버터 회로의 4개 트랜지스터와 읽기/쓰기 게이트 역할을 하는 2개 트랜지스터를 포함하여 총 6개 트랜지스터로 구성된다. [86]

인버터 회로는 안정적인 양안정 회로로 설계되어 1 또는 0 값을 가질 수 있으며, 트랜지스터에 전원이 공급되는 한 영구적으로 저장된다. [87]

따라서 SRAM은 DRAM처럼 지속적인 새로고침이 필요 없지만, 전원이 차단되면 정보가 손실되는 휘발성 메모리이다. [88]

SRAM의 장단점 [89]

DRAM에 비해 메모리 접근 지연 시간이 훨씬 짧다. [89]

단점은 동등한 DRAM 셀(트랜지스터 1개와 커패시터 1개)보다 훨씬 큰 다이 면적(트랜지스터 6개)을 가지며, 온-상태 전력 소모가 더 높다는 것이다. [90]

FinFET SRAM 셀의 주사 전자 현미경 이미지 [93]

공유 메모리 (Shared Memory) [94]

NVIDIA GPU의 프로그래머 관리 SRAM은 32개의 온칩 SRAM 뱅크로 나뉜다. [94]

다른 뱅크에 대한 공유 메모리 접근은 비트가 무작위로 또는 순차적으로 접근될 때 처리량 저하가 없지만, 각 뱅크는 클럭 사이클당 1바이트를 제공하는 제한이 있다. [95]

따라서 각 스레드가 순차적인 공유 메모리 주소에 접근하여 접근이 직렬화되는 것을 방지하는 것이 가장 효율적이다. [96]

이러한 지연 시간 페널티는 동일한 메모리 풀에 접근하려는 스레드 간의 자원 경합으로 인해 발생하며, 동일한 풀 내 메모리 주소의 순서 때문이 아니다. [97]

아래 예시에서 왼쪽과 오른쪽 접근 패턴은 뱅크 충돌이 없지만, 가운데 패턴은 여러 스레드가 동시에 동일한 SRAM 뱅크에 접근하여 접근이 두 배 느려진다. [99]

공유 메모리 접근 사례. 왼쪽/오른쪽은 좋고, 가운데는 충돌이 있다. [98]

### 2.2. 메모리 계층 구조 [103]

메모리 계층의 원리 [104]

GPU의 메모리는 계층 구조로 파편화되어 있으며, 각 레벨은 용량을 위해 지연 시간과 처리량을 절충한다. [104]

이러한 지연 시간과 메모리 크기 간의 절충 경향은 프로세서에서 흔하며, 이는 더 큰 메모리 뱅크가 더 복잡한 인덱싱 회로와 더 긴 신호 경로 길이를 필요로 하기 때문이다. [105]

GPU 메모리 계층별 특징 [106]

글로벌 메모리 (GMEM) [106]

GPU에서 가장 크고 느린 메모리이며, 칩 외부에 존재한다. [106]

이 DRAM 뱅크는 모든 스트리밍 멀티프로세서의 모든 스레드에서 접근할 수 있도록 설계되었다. [107]

L2 캐시 [108]

GMEM 바로 아래 단계에 있으며, GPU가 관리하고 스트리밍 멀티프로세서와 GMEM 접근 사이의 중개자 역할을 한다. [109]

Ampere GPU에서는 L2가 두 개의 분리된 물리적 메모리 저장소로 구성되어 있으며, 일부 SM에서 더 먼 L2 파티션으로의 지연 시간은 글로벌 메모리 접근과 크게 다르지 않다. [110]

L2는 자주 접근되는 GMEM 캐시 라인을 SM에 더 가깝게 유지하고, 스레드 레지스터에서 넘쳐나는 데이터를 가로챈다. [111]

L1 캐시 / 공유 메모리 (Shared Memory) [112]

SM에 위치하며, L1과 공유 메모리는 실제로 동일한 물리적 메모리이다. [112]

프로그래머는 L1을 줄이고 공유 메모리를 늘리거나 그 반대로 설정할 수 있다. [113]

공유 메모리는 전적으로 프로그래머가 관리하는 반면, L1은 L2와 유사하게 하드웨어가 캐시 히트 가능성이 가장 높다고 판단하는 데이터를 저장한다. [114]

공유 메모리 사용은 고성능 GPU 커널을 작성하는 데 매우 중요하다. [115]

공유 메모리는 블록 내의 모든 스레드에서 접근할 수 있으므로, 합산 감소(sum-reduction)와 같은 비교적 복잡한 직렬 연산을 지원할 수 있다. [116]

또한, 스트라이드된 글로벌 메모리 로드를 통합하는 데 유용하며, 이는 스레드 레지스터로 직접 수행될 경우 매우 느린 비통합 접근을 필요로 할 수 있다. [117]

공유 메모리 접근 지연 시간은 L2 또는 GMEM 접근보다 훨씬 좋지만, 용량은 L2보다 한 자릿수 작고 GMEM보다 세 자릿수 작다. [118]

따라서 높은 점유율을 유지하면서 공유 메모리 할당을 관리하는 것은 다소 까다로울 수 있다. [119]

공유 메모리를 과도하게 사용하면 워프 스케줄러가 SM을 완전히 점유하지 못하게 하여 전체 커널 성능을 저하시킨다. [120]

스레드 레지스터 (Thread Registers) [121]

프로그래머가 관리하며 각 스레드에 할당된다. [122]

공유 메모리보다 훨씬 빠르며, 일반적으로 산술 명령을 실행할 때 로드되는 메모리 셀이다. [123]

RTX 3090에서 스레드는 255개 이상의 레지스터를 사용할 수 없으며, 이를 초과하면 '로컬 메모리'로 넘쳐흐른다. [124]

'로컬 메모리'는 다소 오해의 소지가 있는 이름으로, 스레드가 글로벌 메모리에서 활용할 수 있는 주소 공간을 의미한다. [124]

이는 성능에 부정적인 영향을 미칠 수 있으므로 피해야 한다. [125]

글로벌 메모리 지연 시간의 물리적 원인 [128]

저자는 전자가 온칩에서 오프칩 DRAM 모듈로 이동하는 데 걸리는 시간이 글로벌 메모리 지연 시간의 얼마나 많은 부분을 차지하는지 궁금해했다. [128]

신호 경로 길이에 대한 매우 관대한 추정치를 가정하더라도, 물리적 이동 시간은 메모리 접근 지연 시간의 큰 요인이 아니라고 생각한다. [129]

더 큰 요인은 트랜지스터 게이트 커패시턴스, 유한한 메모리 버스 폭, 클럭 속도, 각 엔드포인트 사이의 노드 수 등이라고 추정한다. [130]

구리 내 전자의 속도는 약 16cm/ns이고, 경로 길이를 25cm로 가정하면 신호 전파 지연은 약 1.6ns이다. [131]

## 3. GPU 연산 [134]

GPU는 CUDA 프로그래밍 모델을 통해 병렬 연산을 효율적으로 수행하며, 특히 딥러닝 워크로드를 가속화하는 텐서 코어를 포함한다.

### 3.1. CUDA 프로그래밍 추상화 [135]

CUDA의 기본 구성 요소 [135]

동일한 글로벌 메모리 공간을 사용하는 모든 연산은 커널(kernel) 내에 캡슐화된다. [136]

커널 내에는 '블록(blocks)'의 '그리드(grids)'가 존재하며, 각 블록은 최대 1024개의 스레드로 구성된다. [137]

각 블록은 동일한 스트리밍 멀티프로세서(SM)에서 실행되며, 동일한 블록 내의 모든 스레드는 동일한 공유 메모리에 접근할 수 있다. [138]

블록은 다른 블록과 완전히 독립적으로 실행되므로, 직렬 종속성이 있는 모든 연산은 동일한 블록 내에서 완료되어야 한다. [139]

하드웨어가 블록 내의 스레드를 실제로 실행할 때, 32개씩 '워프(warp)' 단위로 실행된다. [140]

워프 실행은 SIMD(Single-Instance Multiple-Data) 모델을 따르며, 이는 워프 내의 모든 스레드가 동시에 동일한 명령을 받지만 각 스레드는 다른 데이터에 대해 작동한다는 의미이다. [141]

CUDA 프로그래밍 모델 [143]

GPU의 제로-코스트 태스크 스위칭 [144]

SM은 실행 과정 동안 모든 관련 스레드 메모리를 유지하여 제로-코스트 태스크 스위칭을 가능하게 한다. [144]

반면 CPU는 스레드나 프로세스를 전환할 때 오버헤드가 발생하는데, 이는 CPU가 스레드 상태를 더 느린 메모리 캐시에 저장하여 나중에 작업을 재개할 수 있도록 하기 때문이다. [145]

작업 재개 시, 이러한 상태 변수들은 더 느린 메모리 캐시에서 더 빠른 레지스터 파일로 다시 가져와야 한다. [146]

그러나 GPU에서는 워프 변수들이 실행이 다른 워프로 전환될 때 모두 레지스터 파일에 유지된다. [147]

이로 인해 어떤 워프든 다시 전환되어 중단했던 지점부터 바로 작업을 재개할 수 있다. [148]

워프는 종종 많은 수의 레지스터를 사용하고 메모리 종속성으로 인해 '정지(stall)'될 수 있다. [149]

발행된 워프의 모든 레지스터 파일의 누적 크기가 SM의 물리적 레지스터 공간을 초과하면 '레지스터 스필링(register spilling)'이 발생할 수 있다. [150]

이 경우 GPU는 로컬 변수를 L2 캐시 또는 글로벌 메모리에 저장하는 방식으로 전환된다. [151]

핵심은 GPU가 메모리 지연 시간을 숨기기 위해 다른 워크로드를 매우 빠르게 전환하도록 설계되었다는 것이다. [152]

충분한 워프가 있다면 메모리 로딩과 연산이 겹칠 수 있다. [153]

프로그래머는 이 개념(점유율)을 이해하고 GPU의 연산 실행 장치가 연산 장치에 충분한 데이터를 공급하도록 해야 한다. [154]

### 3.2. NVIDIA Ampere 아키텍처 [155]

Ampere 아키텍처 GA102 칩의 특징 [155]

NVIDIA의 하드웨어 아키텍처는 지난 10년간 크게 발전했으며, 최신 Hopper 아키텍처에서도 많은 새로운 기능이 추가되고 있다. [155]

RTX 3090은 'Ampere' 계열에 속한다. [156]

Ampere 아키텍처 기반 GA102 칩은 628mm^2의 다이 면적에 283억 개의 트랜지스터를 포함한다. [157]

주요 연산 자원 [158]

10,752개의 CUDA 코어 [158]

레이 트레이싱 코어 (실시간 그래픽 레이 트레이싱용이므로 크게 중요하지 않다.) [159]

336개의 텐서 코어 [160]

스트리밍 멀티프로세서 (SM) 구조 [161]

GPU 커널의 실제 실행은 84개의 개별 '스트리밍 멀티프로세서'에서 발생한다. [161]

각 SM은 128개의 CUDA 코어와 4개의 텐서 코어를 가진다. [162]

32개의 스레드가 하나의 워프를 구성하고 128개의 CUDA 코어가 있으므로, 각 SM은 128개의 스레드 명령을 동시에 실행할 수 있다. [163]

각 SM은 4개의 세그먼트로 구성되며, 각 세그먼트는 다음을 포함한다. [164]

Ampere 스트리밍 멀티프로세서 아키텍처 [165]

L0 명령어 캐시: 프로세서가 실행할 가능성이 있는 명령어의 로컬 복사본을 저장한다. [166]

워프 스케줄러: SIMT(Single Instance Multi Thread) 방식으로 워프 실행을 관리한다. [167]

디스패치 유닛: 실제 명령어를 실행 유닛(FP32/텐서 코어 등)으로 보낸다. [168]

65.536 KB 레지스터 파일: 스레드별 변수 및 프로그램 상태를 저장한다. [169]

32개의 FP32 ALU: FP32 연산(덧셈/곱셈/융합 곱셈-누적)을 수행한다. [170]

32개의 INT32 ALU: INT32 연산을 수행한다. [171]

8개의 FP64 ALU: 배정밀도 연산을 수행한다. [172]

8개의 로드/스토어 유닛: 공유, 글로벌, 상수, 로컬 주소 공간에 대한 메모리 접근을 처리한다. [173]

### 3.3. SIMT 실행 모델 및 텐서 코어 [180]

SIMT (Single Instance Multi-Thread) 실행 모델 [180]

NVIDIA GPU가 따르는 명령어 실행 모델은 SIMT이다. [180]

이 모델에서 매 클럭 사이클마다 다음이 발생한다. [181]

워프 스케줄러는 정지되지 않은 워프를 선택하고, 해당 워프에 대해 하나 또는 두 개의 명령어를 디스패치 유닛으로 보낸다. [182]

디스패치 유닛은 관련 실행 유닛으로 명령어를 보낸다. [183]

워프 발산(warp divergence, 워프 내 스레드가 다른 코드 실행 경로를 따르는 경우)이 없다고 가정하면, 유닛은 클럭 사이클당 32개의 명령어를 보내며, 각 명령어는 다른 스레드/데이터 포인트에 매핑된다. [183]

동일한 워프에 대해 다른 실행 유닛에 매핑되는 독립적인 명령어가 있을 때만 클럭 사이클당 여러 명령어를 보낼 수 있다. [184]

예를 들어, 스레드 프로그램의 한 부분이 FP32 명령어를 필요로 하고 다른 데이터 독립적인 부분이 텐서 코어를 사용하는 경우에 발생할 수 있다. [185]

워프 발산 처리의 발전 [186]

Volta 이전에는 SM의 각 워프에 하나의 프로그램 카운터와 스택만 할당되었다. [186]

워프 발산이 발생하면, 각 분기된 경로는 전체적으로 직렬로 실행되어야 했다. [187]

활성 마스크(해당 경로에 대해 활성 상태인 스레드의 비트마스크)가 스레드가 명령어를 실행할지 여부를 제어했다. [188]

Volta 이전 워프 발산 처리 [189]

Volta 도입과 함께 각 스레드는 자체 프로그램 카운터와 호출 스택을 추적하게 되었고, 이는 분기된 경로의 실행을 인터리빙(interleaving)할 수 있음을 의미했다. [190]

Volta 이후 워프 발산 처리 [191]

Volta 이후 워프 발산 처리 [192]

이 접근 방식은 더 큰 명령어 수준 병렬성을 허용하고 워프 발산으로 인한 성능 저하를 어느 정도 줄인다. [193]

워프 스케줄러는 여전히 SIMT 모델을 따르며 클럭 사이클당 하나의 명령어만 발행할 수 있다는 점에 유의해야 한다. [194]

두 개의 다른 분기에 있는 스레드는 동일한 클럭 사이클에 명령어를 받을 수 없지만, 워프 스케줄러는 분기된 경로 사이를 더 동적으로 전환할 수 있다. [195]

텐서 코어 (Tensor Cores) [196]

Volta는 텐서 코어라는 새로운 범주의 실행 유닛을 도입한 첫 번째 아키텍처이다. [197]

이 하드웨어는 딥러닝 워크로드를 위한 행렬 곱셈을 가속화하도록 설계되었으며, 매우 빠르다. [198]

각 텐서 코어는 단일 클럭 사이클(~RTX 3090의 경우 0.75ns)에 전체 16x16 행렬 곱셈-누적(MMA) 연산을 실행할 수 있다. [199]

텐서 코어 연산 [200]

이 연산은 워프 전체에 걸쳐 수행되며, 32개의 모든 스레드가 입력 행렬을 텐서 코어로 로드하는 데 참여해야 하므로 CUDA의 스레드/워프 추상화를 어느 정도 깨뜨린다. [201]

## 4. 주요 시사점 [204]

GPU 추론 성능을 최적화하려면 메모리 지연 시간을 최소화하고, 공유 메모리 및 레지스터를 효율적으로 사용하며, 글로벌 메모리 접근을 통합하여 수천 개의 코어에 데이터를 지속적으로 공급해야 한다.

메모리 지연 시간의 중요성 [208]

현대 GPU에서 메모리 지연 시간은 매우 치명적이다. [208]

글로벌 메모리 접근이 얼마나 느린지 시각화하면 놀랍다. [209]

글로벌 메모리 접근을 가능한 한 최소화해야 한다. [210]

효율적인 메모리 사용과 연산 오버랩 [213]

메모리 지연 시간이 길지만, 공유 메모리/레지스터의 효율적인 사용과 통합된 글로벌 메모리 접근은 높은 메모리 처리량을 가능하게 한다. [213]

이는 칩 내 수천 개의 코어에 데이터를 지속적으로 공급할 수 있게 한다. [214]

건강한 메모리 사용 관행과 메모리 접근과 연산을 효과적으로 오버랩하는 커널은 높은 전반적인 하드웨어 활용도를 달성하는 데 큰 도움이 될 것이다. [215]
