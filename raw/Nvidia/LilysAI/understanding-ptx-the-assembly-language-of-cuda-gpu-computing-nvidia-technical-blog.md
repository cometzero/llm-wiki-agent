## 1. CUDA 플랫폼에서 PTX의 역할 [1]

PTX는 CUDA GPU 컴퓨팅 플랫폼의 어셈블리 언어로, 고수준 언어를 GPU 바이너리 코드로 변환하는 중간 단계 역할을 한다.

### 1.1. 명령어 세트 아키텍처(ISA)의 이해 [8]

ISA의 정의 [9]

ISA는 프로세서가 실행할 수 있는 명령어, 형식, 동작 및 이진 인코딩에 대한 사양이다. [9]

모든 프로세서는 ISA를 가지며, 예를 들어 x86_64와 ARM64는 CPU ISA이다. [10]

NVIDIA GPU의 ISA는 세대 또는 제품 라인에 따라 다를 수 있다. [13]

가상 머신 ISA의 정의 [15]

가상 머신 ISA는 가상 프로세서가 지원하는 명령어, 형식 및 동작에 대한 사양이다. [15]

이는 추상적인 프로세서의 ISA이며, 실제 물리적 프로세서에서 실행하는 데 필요한 이진 인코딩을 지정하지 않을 수 있다. [16]

### 1.2. CUDA 플랫폼에서 PTX의 역할 [18]

CUDA 컴파일 과정 [19]

CUDA 파일이 NVIDIA CUDA 컴파일러(NVCC)로 컴파일될 때, 소스 코드는 GPU 코드와 CPU 코드로 분리된다. [37]

GPU 코드는 GPU 컴파일러로, CPU 코드는 호스트 컴파일러로 전송된다. [38]

호스트 컴파일러는 NVCC의 일부가 아니며, NVCC는 명령줄에서 전달되거나 시스템의 기본 컴파일러를 호출한다. [39]

그림 1. 소스 코드에서 실행 파일까지의 상위 수준 컴파일러 흐름 예시

PTX 생성 및 활용 [42]

GPU 컴파일러는 GPU에서 실행될 함수와 커널에 대해 CUDA 플랫폼의 어셈블리 언어인 PTX를 생성한다. [42]

이 PTX 어셈블리는 ptxas라는 어셈블러를 통해 GPU용 실행 가능한 바이너리 코드인 CUBIN으로 변환된다. [43]

GPU 코드 컴파일은 고수준 언어(C++)를 PTX로 컴파일하는 1단계와 PTX를 CUBIN으로 컴파일하는 2단계로 구성된다. [45]

PTX는 LLVM IR과 유사하게, 프로그램의 PTX 표현이 광범위한 NVIDIA GPU에서 컴파일될 수 있도록 한다. [53]

PTX는 애플리케이션 런타임에 JIT(Just-In-Time) 컴파일될 수 있으며, 실행 파일에 GPU 바이너리(CUBIN)와 PTX 코드를 모두 포함할 수 있다. [54]

PTX를 실행 파일에 포함하면 CUDA가 애플리케이션 런타임에 PTX를 적절한 CUBIN으로 JIT 컴파일할 수 있다. [56]

PTX를 통한 미래 호환성 확보 [58]

PTX를 애플리케이션에 포함하면 고수준 언어에서 PTX로의 1단계 컴파일은 애플리케이션 컴파일 시점에 수행된다. [58]

PTX에서 CUBIN으로의 2단계 컴파일은 애플리케이션 런타임까지 지연될 수 있다. [59]

이를 통해 애플리케이션은 빌드된 시점 이후에 출시된 GPU를 포함하여 더 넓은 범위의 GPU에서 실행될 수 있다. [60]

## 2. PTX를 통한 GPU 코드 호환성 및 이점 [100]

PTX는 다양한 GPU 아키텍처 간의 코드 호환성을 제공하며, 미래 GPU에서도 애플리케이션을 실행할 수 있도록 한다.

### 2.1. 컴퓨트 기능 및 NVIDIA GPU 하드웨어 ISA [100]

컴퓨트 기능(CC) 번호 [101]

모든 NVIDIA GPU는 컴퓨트 기능(CC) 번호로 알려진 버전 식별자를 가진다. [101]

각 컴퓨트 기능은 주 버전과 부 버전 번호를 가지며, 예를 들어 컴퓨트 기능 8.6은 주 버전 8, 부 버전 6이다. [102]

GPU ISA와 CUBIN 버전 [104]

NVIDIA GPU는 특정 ISA를 가지며, 다른 세대의 GPU는 다른 ISA를 가진다. [104]

이러한 ISA는 GPU의 컴퓨트 기능에 해당하는 버전 번호로 식별된다. [106]

바이너리(CUBIN)는 특정 컴퓨트 기능에 맞춰 컴파일되며, 모든 CUBIN 버전은 sm_XY 형식이다. [107]

PTX 버전 [111]

PTX는 가상 머신 ISA이며, ptxas 어셈블러는 PTX 프로그램을 GPU 바이너리(CUBIN)로 컴파일한다. [112]

새로운 GPU 하드웨어 세대와 함께 GPU 기능이 추가되면서 PTX 가상 머신도 확장되어 새로운 명령어 세트를 지원한다. [116]

PTX 버전 번호는 가상 아키텍처에서 사용 가능한 명령어 세트를 나타내며, CUBIN 버전과 마찬가지로 GPU 컴퓨트 기능에 해당한다. [120]

예를 들어, NVIDIA Ampere 세대 GA100 GPU의 컴퓨트 기능은 8.0이며, compute_80 버전의 PTX는 GA100이 지원하는 모든 명령어를 포함한다. [123]

### 2.2. GPU 코드 호환성 [124]

바이너리 호환성 [126]

NVIDIA GPU는 주 컴퓨트 기능 버전 내에서 부 버전이 같거나 높으면 바이너리 호환이 가능하다. [127]

예를 들어, sm_86용으로 컴파일된 CUBIN은 sm_8x (x ≥ 6)에서 로드 및 실행될 수 있다. [128]

그러나 sm_86 CUBIN은 컴퓨트 기능 8.0 장치에서는 로드되지 않는데, 이는 부 버전이 낮기 때문이다. [130]

NVIDIA GPU는 주 컴퓨트 기능 버전 간에는 바이너리 호환이 되지 않는다. [131]

PTX JIT 호환성 [133]

실행 파일에 PTX를 포함하면 단일 바이너리 파일 내에서 다른 컴퓨트 기능의 GPU 간 호환성을 제공한다. [134]

애플리케이션 또는 라이브러리에 PTX 코드가 저장되면, 로드되는 GPU에 맞춰 JIT 컴파일될 수 있다. [137]

예를 들어, compute_70을 대상으로 하는 PTX는 컴퓨트 기능 7.0 이상(8.x, 9.x, 10.x, 12.x 포함)의 모든 GPU에서 JIT 컴파일될 수 있다. [138]

PTX는 PTX 버전보다 낮은 컴퓨트 기능에서는 JIT 컴파일될 수 없다. [139]

### 2.3. Fatbin의 활용 [141]

Fatbin의 구성 [142]

CUDA 애플리케이션 또는 라이브러리는 fatbin이라는 컨테이너를 가지며, 이는 여러 CUBIN과 PTX 버전의 GPU 코드를 포함할 수 있다. [142]

예를 들어, 그림 2의 실행 파일에 있는 fatbin은 compute_70용 PTX와 sm_70, sm_80, sm_86용 CUBIN을 포함한다. [144]

sm_86 CUBIN은 컴퓨트 기능 8.9 GPU에서도 로드될 수 있다. [145]

PTX는 애플리케이션 시작 시 또는 GPU에서 코드가 처음 사용될 때 드라이버에 의해 컴파일된다. [150]

JIT 컴파일 시점 제어에 대한 자세한 내용은 CUDA 프로그래밍 가이드의 Lazy Loading 섹션을 참조해야 한다. [151]

### 2.4. PTX의 이점 [152]

미래 GPU 아키텍처 호환성 [153]

PTX를 중간 코드 형식으로 사용함으로써, CUDA 플랫폼은 아직 개발되지 않은 GPU에서도 실행될 수 있는 애플리케이션 바이너리를 구축할 수 있도록 한다. [153]

2018년에 NVIDIA Turing 아키텍처(CC 7.5)용으로 컴파일된 애플리케이션은 2025년 NVIDIA Blackwell(CC 12.0) GPU 및 미래에 출시될 GPU에서도 실행될 수 있다. [154]

실행 파일 또는 라이브러리에 GPU 코드의 PTX 표현을 포함함으로써, CUDA 드라이버는 애플리케이션이 컴파일될 때 구상되지 않았던 아키텍처에 대해 런타임에 PTX 코드를 JIT 컴파일할 수 있다. [155]

바이너리 버전의 애플리케이션 또는 라이브러리를 배포하는 개발자의 경우, 이는 바이너리를 업데이트할 필요 없이 미래 GPU 아키텍처에서 애플리케이션 또는 라이브러리를 실행할 수 있도록 한다. [156]

다양한 언어 지원 [157]

PTX는 CUDA GPU 컴퓨팅 플랫폼의 어셈블리 언어 역할을 함으로써, 모든 언어의 컴파일러가 PTX를 대상으로 할 수 있는 표현을 제공한다. [157]

예를 들어, 도메인 특정 언어(DSL) 컴파일러는 PTX 코드를 생성할 수 있으며, 이 코드는 NVIDIA GPU에서 실행될 수 있다. [158]

OpenAI Triton은 PTX를 생성하는 DSL의 예시이다. [159]

### 2.5. PTX 직접 작성 [161]

PTX 직접 작성의 가능성 [162]

PTX 가상 머신 ISA는 NVIDIA에 의해 문서화되어 있으며, PTX 코드를 직접 작성하는 것이 가능하다. [162]

그러나 다른 어셈블리 언어와 마찬가지로, 대규모 소프트웨어 프로젝트에는 적합하지 않다. [164]

고수준 언어는 어셈블리 또는 가상 어셈블리 언어를 직접 다루는 것보다 더 나은 개발자 생산성을 제공한다. [165]

PTX 직접 작성의 이점 및 주의사항 [166]

PTX를 직접 작성하는 것은 CPU 어셈블리 코드를 직접 작성하는 것과 유사하게, 프로세서가 코드를 실행하는 방식에 대한 통찰력을 가진 전문가가 최종 실행 파일의 명령어를 세밀하게 제어할 수 있도록 한다. [166]

이를 통해 성능 향상을 찾을 수 있지만, 대부분의 개발자에게는 일반적으로 필요하거나 권장되지 않는다. [167]

그러나 일부 개발자는 수십억 번 이상 실행될 내부 루프 코드에 대해 PTX를 직접 작성하여 코드를 최적화하는 것을 선택한다. [168]

PTX 활용 도구 [171]

CUDA 툴킷에 포함된 libcu++는 PTX 명령어에 직접 매핑되는 함수를 제공하는 cuda::ptx 네임스페이스를 제공한다. [171]

cuda::ptx 네임스페이스에 대한 자세한 내용은 libcu++ 문서를 참조해야 한다. [173]

또한, NVIDIA는 C++ 코드 내에서 PTX를 직접 인라인하는 방법에 대한 문서를 제공한다. [174]

### 2.6. 요약 [175]

PTX의 핵심 역할 [176]

PTX는 CUDA GPU 컴퓨팅 플랫폼의 어셈블리 언어로 간주될 수 있는 가상 머신 ISA이다. [176]

PTX는 CUDA GPU 컴퓨팅 플랫폼의 필수적인 부분이며, 고수준 언어는 PTX로 컴파일된 후, PTX는 컴파일 시점 또는 런타임에 바이너리 코드로 컴파일된다. [177]

PTX의 주요 이점 [179]

바이너리에 PTX 코드를 포함함으로써, 애플리케이션과 라이브러리는 단일 바이너리 내에서 세대 간 호환성을 달성할 수 있다. [179]

또한, 다른 프로그래밍 또는 도메인 특정 언어용 컴파일러는 PTX로 컴파일한 다음 ptxas 또는 JIT 컴파일을 사용하여 NVIDIA GPU에서 실행 가능한 바이너리 코드를 생성할 수 있다. [180]

개발자를 위한 권장 사항 [181]

개발자는 애플리케이션 또는 라이브러리에 PTX를 포함하여 GPU 코드의 호환성을 극대화해야 한다. [181]
