## 1. 텐서 코어 데이터 공급 문제: NVIDIA와 AMD의 접근 방식 [1]

AI 모델에서 텐서 코어의 높은 활용도를 유지하기 위해 NVIDIA는 TMEM을, AMD는 대규모 레지스터 파일을 도입하여 데이터 공급 문제를 해결한다.

### 1.1. 텐서 코어의 중요성 및 데이터 공급의 필요성 [3]

AI 모델에서 텐서 코어의 지배적 역할 [3]

H100에서 현대 AI 모델 실행 시, 컴퓨팅의 약 94%가 텐서 코어에서 발생한다. [3]

매트릭스 곱셈이 워크로드의 대부분을 차지하므로, 하드웨어는 매트릭스 곱셈을 빠르게 처리하도록 설계된다. [4]

텐서 코어의 지속적인 데이터 공급 필요성 [6]

전체 시스템 속도를 높이려면 텐서 코어에 데이터를 지속적으로 공급하는 것이 중요하다. [6]

적절한 비동기 패턴 없이는 H100조차 활용률이 약 63%에 불과하다. [7]

텐서 코어 파이프라인은 중단 없이 데이터를 공급받아야 하며, 지연은 곧 사이클 낭비로 이어진다. [8]

### 1.2. NVIDIA와 AMD의 상이한 해결책 [9]

NVIDIA의 TMEM 도입 [10]

SM(스트리밍 멀티프로세서)당 256KB의 전용 스크래치패드인 TMEM을 도입했다. [10]

이는 레지스터 파일과 별개로 작동한다. [10]

AMD의 대규모 레지스터 파일 활용 [11]

VGPR(Vector General Purpose Register)과 AGPR(Accumulator General Purpose Register)을 통해 대규모 레지스터 파일을 강화했다. [11]

두 접근 방식의 성능 및 소프트웨어 복잡성 [12]

두 접근 방식 모두 이론적으로는 거의 최고 성능에 도달할 수 있다. [12]

하지만 소프트웨어 복잡성 측면에서는 큰 차이가 있다. [13]

각 방식의 성능을 극대화하는 방법을 탐구하는 것이 중요하다. [14]

## 2. NVIDIA의 TMEM 기반 접근 방식 [15]

NVIDIA는 텐서 코어 프로그래밍을 발전시키면서 데이터 이동과 컴퓨팅을 분리하고, TMEM을 도입하여 레지스터 부담을 줄이고 비동기 파이프라인을 강화했다.

### 2.1. NVIDIA 텐서 코어 프로그래밍의 진화 [15]

세대별 발전 과정 [16]

Volta (2017): WMMA (Warp-level, 동기식) [17]

Ampere/Hopper: WGMMA (Warpgroup-level, 비동기식) [18]

Blackwell: tcgen05 (Warpgroup-level, 전용 TMEM 스크래치패드) [19]

데이터 이동과 컴퓨팅의 분리 [20]

각 세대는 데이터 이동과 컴퓨팅의 분리를 더욱 강화했다. [20]

tcgen05는 이러한 분리의 논리적 결론이다. [20]

Hopper 이후의 새로운 TMA 유닛과 기존 LDGSTS 인트린식 비교

### 2.2. TMEM의 역할과 이점 [22]

TMEM의 정의 및 필요성 [23]

TMEM은 SM당 256KB의 온칩 스크래치패드로, 레지스터 파일과 완전히 분리되어 있다. [23]

이전에는 텐서 피연산자가 레지스터에 저장되었으나, 레지스터는 비용이 많이 든다. [24]

Hopper에서 WGMMA를 실행하는 워프그룹은 행렬 타일을 저장하는 데 레지스터 파일의 40-60%를 사용할 수 있다. [26]

이로 인해 주소 계산, 루프 카운터, 비동기 처리를 위한 공간이 부족해진다. [27]

TMEM의 문제 해결 능력 [28]

TMEM은 행렬 피연산자를 위한 전용 공간을 제공하여 이 문제를 해결한다. [28]

이를 통해 레지스터 파일은 실제 계산을 위해 확보된다. [28]

주요 명령어 및 비동기 특성 [29]

tcgen05.cp: 공유 메모리에서 TMEM으로 직접 복사한다 (레지스터를 완전히 우회한다). [30]

tcgen05.mma: TMEM에서 A 및 B 피연산자를 직접 읽어 행렬 곱셈을 수행한다. [31]

비동기적 특성으로 인해 스레드는 작업을 발행하고 즉시 다음 작업으로 이동한다. [32]

결과가 필요할 때 명시적인 커밋을 통해 파이프라인을 비운다. [32]

### 2.3. 워프그룹: 128개 스레드의 협력 [33]

워프그룹의 정의 [34]

Blackwell 텐서 연산은 워프그룹 연산으로, 128개 스레드(4개 워프)가 하나의 행렬 곱셈을 협력적으로 실행한다. [34]

TMEM 접근 방식 [35]

각 워프는 TMEM의 자체 "레인 슬라이스"에 접근한다. [35]

피연산자 로딩을 위한 워프 간 통신은 필요 없다. [36]

내재된 동기화 및 주소 지정 단순화 [37]

워프그룹은 단위로 실행되므로, 그룹 내에서 명시적인 장벽 없이 내재된 동기화가 이루어진다. [37]

각 워프가 TMEM의 어느 부분을 소유하는지 정확히 알기 때문에 주소 지정이 단순화된다. [38]

## 3. AMD의 대규모 레지스터 파일 기반 접근 방식 [39]

AMD는 전용 텐서 메모리 대신 대규모 레지스터 파일을 활용하여 유연성을 확보했지만, 소프트웨어 복잡성이 증가하는 결과를 초래했다.

### 3.1. AMD의 대규모 레지스터 파일 투자 [39]

전용 텐서 메모리 대신 레지스터 파일 확장 [40]

AMD는 전용 텐서 메모리를 추가하는 대신, 거대한 레지스터 파일을 추가하는 데 투자했다. [40]

MFMA (Matrix Fused Multiply-Add) 기본 연산 [41]

핵심 기본 연산은 MFMA로, 웨이브프론트 수준(NVIDIA의 32개 스레드 대비 64개 스레드)에서 작동한다. [41]

MFMA는 16x16, 32x32 등 다양한 형태로 제공되며, 각각 다른 레지스터 소비량과 처리량을 가진다. [42]

AMD의 MFMA 시각화

### 3.2. VGPR + AGPR: 2단계 레지스터 설계 [44]

CDNA3/4 (MI300X, MI355X)의 SIMD 구성 [46]

각 SIMD는 256개의 VGPR(모든 용도의 표준 레지스터)을 가진다. [47]

각 SIMD는 256개의 AGPR(MFMA 누산기용 특수 레지스터)을 가진다. [48]

대규모 레지스터 파일의 목적 [49]

SIMD당 총 512개의 레지스터는 텐서 피연산자 저장을 위한 AMD의 해결책이다. [49]

모든 것을 담을 수 있을 만큼 레지스터 파일을 거대하게 만든다. [49]

AGPR의 제약 및 소프트웨어 복잡성 [50]

AGPR은 제한적이며, 벡터 ALU 연산에 직접 사용할 수 없다. [50]

VGPR과 AGPR 간의 데이터 이동에는 명시적인 accvgpr_read 및 accvgpr_write 명령어가 필요하다. [52]

이는 NVIDIA에는 없는 스케줄링 문제를 야기한다. [53]

### 3.3. 레지스터 사용의 장점과 단점 [54]

레지스터의 주요 장점 [55]

유연성: 레지스터는 행렬 타일, 중간 값, 주소 등 모든 것을 파티셔닝이나 특별한 처리 없이 저장할 수 있다. [56]

낮은 지연 시간: 레지스터 접근은 스크래치패드나 공유 메모리보다 빠르다. [57]

하드웨어 단순성: 두 개의 분리된 온칩 메모리 시스템을 유지하고 조정하는 대신, 하나의 통합 레지스터 파일에 의존하므로 하드웨어 설계가 더 단순하다. [58]

소프트웨어 복잡성 증가 [59]

이러한 장점들은 규모가 커질수록 소프트웨어 복잡성을 증가시킨다. [59]

## 4. 아키텍처별 스케줄링 패턴 및 메모리 레이아웃의 차이 [60]

NVIDIA와 AMD는 아키텍처 차이로 인해 실제 커널 설계에서 스케줄링 패턴과 메모리 레이아웃에서 큰 차이를 보이며, 이는 최적화 전략의 비호환성을 야기한다.

### 4.1. AMD에서 웨이브 특수화가 실패하는 이유 [60]

NVIDIA의 웨이브 특수화 성공 사례 [63]

입증된 패턴: NVIDIA에서 웨이브 특수화는 입증된 패턴이다. [63]

생산자-소비자 분리: 생산자 웨이브는 메모리 연산을, 소비자 웨이브는 컴퓨팅을 처리한다. [64]

하드웨어 모델과의 적합성: 이러한 분리는 NVIDIA의 하드웨어 모델과 잘 맞는다. [66]

성능 극대화 요인: [67]

TMA는 생산자 측 로드를 비동기적으로 실행하여 메모리 이동이 실행을 지연시키지 않는다. [68]

워프그룹은 WGMMA를 발행하고 즉시 다른 작업으로 전환할 수 있다. [69]

mbarrier는 빠르고 하드웨어 지원되는 생산자-소비자 동기화를 제공하여 과도한 오버헤드 없이 파이프라인을 가득 채운다. [70]

AMD에서 웨이브 특수화의 한계 [71]

TMA 부재: AMD에는 TMA와 동등한 기능이 없어, 생산자 웨이브는 레지스터와 ALU 사이클을 소비하는 직접 버퍼 로드에 의존한다. [72]

비동기 MMA 경로 부재: MFMA는 완료될 때까지 블록되므로, 작업을 발행하고 다른 작업으로 이동할 수 없다. [73]

정적 레지스터 할당: 생산자 웨이브는 컴퓨팅에 사용될 수 있는 레지스터를 점유하여 전체 점유율과 효율성을 감소시킨다. [74]

HipKittens 논문의 증명 [75]

HipKittens 논문은 NVIDIA에서 사용되는 웨이브 특수화가 AMD에 잘 적용되지 않음을 명시적으로 문서화했다. [75]

AMD의 하드웨어 제약에 더 잘 맞는 다른 실행 전략을 채택하는 것이 해결책이다. [77]

### 4.2. 메모리 레이아웃 및 스위즐링의 복잡성 [79]

NVIDIA의 단일, 범용 레이아웃 [80]

16x16 코어 행렬: NVIDIA는 단일하고 범용적인 16x16 코어 행렬 레이아웃을 설계했다. [80]

규칙적인 패턴: 64x64, 128x128과 같은 더 큰 타일은 여러 16x16 블록으로 구성된다. [81]

장점: [82]

단일 XOR 기반 스위즐을 통해 예측 가능한 뱅크 충돌 회피가 가능하다. [82]

128x128 MMA는 특정 배열의 16개 16x16 MMA와 동일하다. [83]

AMD의 형태별 레이아웃 [84]

MFMA 형태별 상이한 레지스터 레이아웃: AMD의 레지스터 레이아웃은 각 MFMA 형태에 따라 다르다. [85]

다양한 매핑: 행렬 좌표에서 레지스터 인덱스로의 매핑은 형태, 데이터 유형, 심지어 피연산자 역할(A, B, 누산기)에 따라 달라진다. [86]

복잡성 증가: [87]

각 형태는 자체 뱅크 충돌 전략이 필요하다. [87]

커널 중간에 MFMA 형태를 변경하려면 데이터 재포맷이 필요하다. [87]

여러 레이아웃 규칙을 동시에 고려해야 하므로 커널 복잡성이 높아진다. [87]

HipKittens 라이브러리의 노력 [88]

HipKittens 라이브러리는 AMD 특정 스위즐 패턴을 도출하는 데 상당한 노력을 기울였다. [88]

논문에 따르면, "신중한 스위즐링 없이는 공유 메모리 뱅크 충돌로 인해 유효 대역폭이 4-8배 감소한다." [89]

### 4.3. 결론: 아키텍처 철학에 따른 소프트웨어 최적화 [90]

텐서 코어 데이터 공급의 중요성 [90]

텐서 코어는 현대 AI 하드웨어에서 계속 지배적이지만, 데이터 공급이 진정한 과제이다. [90]

NVIDIA와 AMD의 상반된 아키텍처 선택 [91]

NVIDIA는 TMEM을 통해 텐서 피연산자를 외부화하여 소프트웨어를 단순화하고 비동기 파이프라인을 가능하게 했다. [91]

AMD는 모든 것을 대규모 레지스터 파일에 넣어 유연성을 유지했지만, 스케줄링 및 레이아웃 복잡성이 증가했다. [91]

최적화 전략의 비호환성 [92]

결과적으로 최적화 전략은 이식성이 없다. [92]
