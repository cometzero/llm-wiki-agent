## 1. CUDA 프로그래밍 모델 개요 [1]

CUDA 프로그래밍 모델은 GPU 아키텍처를 추상화하여 애플리케이션과 GPU 하드웨어 간의 다리 역할을 한다. [4]

### 1.1. 호스트와 디바이스의 개념 [6]

호스트(Host) [7]

시스템에 있는 CPU를 의미한다. [7]

CPU와 연결된 시스템 메모리를 호스트 메모리라고 한다. [8]

디바이스(Device) [9]

GPU를 의미하며, GPU 메모리는 디바이스 메모리라고 한다. [9]

### 1.2. CUDA 프로그램 실행 3단계 [10]

호스트-디바이스 데이터 전송 [11]

입력 데이터를 호스트 메모리에서 디바이스 메모리로 복사한다. [11]

GPU 프로그램 실행 [12]

GPU 프로그램을 로드하고 실행하며, 성능 향상을 위해 데이터를 온칩(on-chip)에 캐싱한다. [12]

디바이스-호스트 결과 전송 [13]

결과를 디바이스 메모리에서 호스트 메모리로 복사한다. [13]

## 2. CUDA 커널 및 스레드 계층 구조 [14]

CUDA 커널은 GPU에서 실행되는 함수이며, 병렬 처리를 위해 스레드와 블록 계층 구조를 사용한다. [15]

### 2.1. CUDA 커널의 특징 [15]

GPU에서 실행되는 함수 [15]

CUDA 커널은 GPU에서 실행되는 함수이다. [15]

애플리케이션의 병렬 부분은 일반 C/C++ 함수와 달리 K개의 CUDA 스레드에 의해 K번 병렬로 실행된다. [16]

그림 1. 커널은 GPU에서 실행되는 함수이다.

__global__ 선언 지정자 [18]

모든 CUDA 커널은 __global__ 선언 지정자로 시작한다. [18]

프로그래머는 내장 변수를 사용하여 각 스레드에 고유한 전역 ID를 제공한다. [18]

### 2.2. 스레드 및 블록 계층 구조 [19]

CUDA 블록과 그리드 [20]

스레드 그룹을 CUDA 블록이라고 한다. [20]

CUDA 블록들은 그리드로 그룹화된다. [20]

커널은 스레드 블록들의 그리드로 실행된다. [20]

그림 2. CUDA 커널은 블록으로 세분화된다.

스트리밍 멀티프로세서(SM)와 블록 실행 [21]

각 CUDA 블록은 하나의 스트리밍 멀티프로세서(SM)에 의해 실행되며, GPU 내 다른 SM으로 마이그레이션될 수 없다. [21]

하나의 SM은 CUDA 블록이 필요로 하는 리소스에 따라 여러 개의 동시 CUDA 블록을 실행할 수 있다. [22]

각 커널은 하나의 디바이스에서 실행되며, CUDA는 한 번에 여러 커널을 디바이스에서 실행하는 것을 지원한다. [23]

그림 3. GPU에서의 커널 실행.

3D 내장 변수 [26]

CUDA는 스레드와 블록에 대한 3D 내장 변수를 정의한다. [26]

스레드는 내장 3D 변수 threadIdx를 사용하여 인덱싱된다. [27]

3차원 인덱싱은 벡터, 행렬, 볼륨의 요소를 인덱싱하는 자연스러운 방법을 제공하여 CUDA 프로그래밍을 용이하게 한다. [28]

블록도 내장 3D 변수 blockIdx를 사용하여 인덱싱된다. [29]

### 2.3. CUDA 스레드 및 블록 관련 중요 사항 [30]

블록당 스레드 수 제한 [31]

CUDA 아키텍처는 블록당 스레드 수를 1024개로 제한한다. [31]

blockDim 변수 [32]

스레드 블록의 차원은 내장 blockDim 변수를 통해 커널 내에서 접근할 수 있다. [32]

__syncthreads 함수 [33]

블록 내 모든 스레드는 내장 함수 __syncthreads를 사용하여 동기화될 수 있다. [33]

__syncthreads를 사용하면 블록 내 모든 스레드가 다음 단계로 진행하기 전에 기다려야 한다. [33]

## 3. 메모리 계층 구조 [39]

CUDA 지원 GPU는 그림 4와 같은 메모리 계층 구조를 가진다. [40]

그림 4. GPU의 메모리 계층 구조.

### 3.1. GPU 아키텍처가 노출하는 메모리 종류 [42]

레지스터(Registers) [43]

각 스레드에 비공개이며, 다른 스레드에서는 볼 수 없다. [43]

컴파일러가 레지스터 활용을 결정한다. [43]

L1/공유 메모리(Shared Memory, SMEM) [44]

모든 SM은 L1 캐시 및 공유 메모리로 사용될 수 있는 빠르고 온칩 스크래치패드 메모리를 가진다. [44]

CUDA 블록 내 모든 스레드는 공유 메모리를 공유할 수 있으며, 주어진 SM에서 실행되는 모든 CUDA 블록은 SM이 제공하는 물리적 메모리 리소스를 공유할 수 있다. [44]

읽기 전용 메모리(Read-only memory) [45]

각 SM은 명령어 캐시, 상수 메모리, 텍스처 메모리 및 RO 캐시를 가지며, 이는 커널 코드에 대해 읽기 전용이다. [45]

L2 캐시(L2 cache) [46]

모든 SM이 공유하는 캐시로, 모든 CUDA 블록의 모든 스레드가 이 메모리에 접근할 수 있다. [46]

NVIDIA A100 GPU는 L2 캐시 크기를 V100 GPU의 6MB에서 40MB로 늘렸다. [46]

전역 메모리(Global memory) [47]

GPU의 프레임 버퍼 크기이자 GPU에 있는 DRAM이다. [47]

### 3.2. 메모리 최적화 [48]

NVIDIA CUDA 컴파일러는 메모리 리소스 최적화를 잘 수행한다. [48]

숙련된 CUDA 개발자는 필요에 따라 이 메모리 계층 구조를 효율적으로 사용하여 CUDA 프로그램을 최적화할 수 있다. [48]

## 4. 컴퓨트 기능 (Compute Capability) [49]

GPU의 컴퓨트 기능은 GPU 하드웨어에서 지원되는 일반 사양 및 사용 가능한 기능을 결정한다. [50]

### 4.1. 컴퓨트 기능의 역할 [50]

하드웨어 기능 결정 [50]

GPU의 컴퓨트 기능은 GPU 하드웨어에서 지원되는 일반 사양 및 사용 가능한 기능을 결정한다. [50]

런타임 시 활용 [51]

이 버전 번호는 애플리케이션이 런타임 시 현재 GPU에서 어떤 하드웨어 기능이나 명령어를 사용할 수 있는지 결정하는 데 사용될 수 있다. [51]

### 4.2. 버전 번호 체계 [52]

X.Y 형식 [52]

모든 GPU는 X.Y 형식의 버전 번호를 가지며, X는 주 개정 번호, Y는 부 개정 번호를 나타낸다. [52]

부 개정 번호 [53]

부 개정 번호는 아키텍처에 대한 점진적인 개선을 의미하며, 새로운 기능이 포함될 수 있다. [53]

### 4.3. 컴퓨트 기능 정보 확인 [54]

CUDA 샘플 코드 deviceQuery [54]

CUDA 지원 디바이스의 컴퓨트 기능에 대한 자세한 정보는 CUDA 샘플 코드 deviceQuery를 참조한다. [54]

시스템 내 CUDA 디바이스 속성 열거 [55]

이 샘플은 시스템에 있는 CUDA 디바이스의 속성을 열거한다. [55]

## 5. 요약 [56]

CUDA 프로그래밍 모델은 호스트와 디바이스가 각자의 메모리 공간을 가지고 비동기적으로 작동하는 이기종 환경을 제공한다. [57]

### 5.1. CUDA 프로그래밍 모델의 주요 특징 [57]

이기종 환경 [57]

CUDA 프로그래밍 모델은 호스트 코드가 CPU에서 C/C++ 프로그램을 실행하고, 커널은 물리적으로 분리된 GPU 디바이스에서 실행되는 이기종 환경을 제공한다. [57]

독립적인 메모리 공간 [58]

호스트와 디바이스는 각각 호스트 메모리와 디바이스 메모리라는 자체적인 메모리 공간을 유지한다고 가정한다. [58]

데이터 전송 [59]

CUDA 코드는 PCIe 버스를 통해 호스트와 디바이스 메모리 간의 데이터 전송을 제공한다. [59]

### 5.2. 프로그래밍 유연성 및 최적화 [60]

내장 변수 및 다차원 인덱싱 [60]

CUDA는 많은 내장 변수를 노출하고 프로그래밍을 용이하게 하기 위해 다차원 인덱싱의 유연성을 제공한다. [60]

다양한 메모리 관리 [61]

CUDA는 레지스터, 공유 메모리 및 L1 캐시, L2 캐시, 전역 메모리를 포함한 다양한 메모리를 관리한다. [61]

고급 개발자의 최적화 [62]

고급 개발자는 이러한 메모리 중 일부를 효율적으로 사용하여 CUDA 프로그램을 최적화할 수 있다. [62]
