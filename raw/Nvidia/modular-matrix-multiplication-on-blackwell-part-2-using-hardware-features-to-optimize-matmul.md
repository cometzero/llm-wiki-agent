## 1. 행렬 곱셈 최적화를 위한 하드웨어 기능 활용 [1]

Blackwell GPU에서 행렬 곱셈 성능을 최적화하기 위해 공유 메모리, TMA 로드/저장, tcgen05.mma, stmatrix 등의 하드웨어 기능을 활용하고 뱅크 충돌을 해결하는 스위즐링 기법을 적용하여 나이브 커널 대비 58배 성능 향상을 달성한다.

### 1.1. 공유 메모리를 활용한 중복 로드 감소 [26]

메모리 접근 시각화 및 문제점 파악 [17]

4줄 행렬 곱셈 커널에서 각 스레드는 하나의 출력값을 계산하기 위해 완전한 행과 열을 로드한다. [23]

4개의 스레드를 고려할 때, 각 행과 열에 대한 로드가 두 번 반복되어 중복 로드가 발생한다. [24]

이는 느린 전역 메모리 접근을 줄여야 함을 시사한다. [25]

4줄 행렬 곱셈의 스레드별 메모리 접근

루프 타일링을 통한 전역 메모리 접근 감소 [27]

루프 타일링은 작은 행렬 타일을 더 빠른 메모리 캐시(공유 메모리)에 로드하여 프로세서가 느린 주 메모리에 계속 접근하지 않고도 해당 데이터 블록에 대한 모든 필요한 계산을 수행할 수 있도록 하는 일반적인 기술이다. [27]

하나의 타일 작업이 끝나면 다음 타일을 로드한다. [30]

공유 메모리를 캐시로 사용 [31]

Blackwell SM은 228KB의 공유 메모리를 제공하므로, 여러 스레드 간에 데이터를 공유하고 블록 전체에 걸쳐 타일링을 수행할 수 있다. [31]

행렬을 A는 BMxBK, B는 BNxBK 타일로 분할하며, 여기서 BMxBNxBK는 64x64x64이다. [34]

첫 번째 K/BK 루프 반복에서 행렬 A에서 BMxBK 크기의 타일과 행렬 B에서 BNxBK 크기의 타일을 로드한다. [37]

이는 두 개의 64x64 타일, 즉 8192개의 2바이트 요소를 의미하며, 각 블록당 약 16KB의 메모리가 필요하여 사용 가능한 228KB 공유 메모리보다 훨씬 적다. [38]

이 타일에 대해 행렬 곱셈-누적(MMA) 연산을 수행하고 결과를 중간 값으로 저장한다. [40]

루프 타일링을 사용한 행렬 곱셈-누적

두 번째 반복에서는 다음 두 청크를 공유 메모리에 로드하고, 이 MMA의 결과를 이전 반복의 결과에 추가한다. [42]

K/BK 반복(이 경우 256회)이 완료되면 최종 출력 타일을 얻게 되며, 이 최종 결과는 전역 메모리에 한 번만 기록된다. [43]

### 1.2. 커널 2: TMA 및 텐서 코어 활용 [47]

커널 2의 개요 [48]

커널 2는 타일링과 텐서 코어를 모두 사용하여 최적화된 고급 커널이다. [49]

커널은 kernel_setup(), load_tiles_ab(), issue_mma_axb(), transfer_c_tile_to_registers(), write_c_tile_to_global_memory() 순서로 동작한다. [53]

공유 메모리로 타일 로드 (TMA 사용) [58]

TMA (Tensor Memory Accelerator) [59]

NVIDIA Hopper 아키텍처에 도입된 TMA는 GPU의 전역 메모리(GMEM)와 공유 메모리(SMEM) 간에 데이터를 비동기적으로 전송하는 특수 하드웨어 유닛이다. [59]

TMA 사용 방법 [60]

TMA를 사용하려면 먼저 호스트에서 텐서 타일을 생성하여 커널에 전달해야 한다. [60]

텐서 맵은 입력 텐서의 모양, 스트라이드, 전역 메모리 주소를 인코딩하는 128B 데이터 청크이다. [61]

Mojo API를 사용하여 TMA 타일을 쉽게 생성할 수 있다. [62]

커널 내 TMA 객체 사용 [65]

하나의 스레드(elect_one_thread)가 비동기 복사를 시작하고 메모리 배리어(tma_mbar)를 사용하여 복사가 완료되었는지 확인한다. [68]

a_tma_op.async_copy는 타일의 공유 메모리 주소를 제공하는 LayoutTensor, 전송된 데이터 양을 추적하는 메모리 배리어, 입력에서 현재 타일의 좌표를 인수로 받는다. [70]

TMA 배리어의 필요성 [74]

TMA 작업은 비동기적이므로, 타일이 공유 메모리에 완전히 상주할 때까지 MMA가 진행되지 않도록 하는 방법이 필요하다. [75]

이를 위해 메모리 배리어(mbar)를 사용하여 타일이 공유 메모리로 복사될 때까지 스레드가 대기하도록 한다. [76]

각 스레드는 자체 배리어 단계(tma_phase=0)로 초기화되며, 메모리 배리어도 내부 단계 값을 0으로 초기화한다. [77]

스레드의 단계가 배리어의 단계와 일치하면 스레드는 배리어를 잠금 해제할 수 없으며 통과할 수 없다. [78]

두 단계가 다를 때만 스레드가 진행할 수 있다. [79]

TMA 배리어로 스레드 차단 그림

TMA 전송 전에 tma_mbar[0].expect_bytes(expected_bytes)를 사용하여 TMA로부터 예상되는 바이트 수를 배리어에 초기화한다. [84]

expected_bytes는 전송되는 두 타일의 총 바이트 수이다. [85]

TMA는 전송된 바이트 수를 배리어에 지속적으로 업데이트하며, 전송된 바이트 수가 총 바이트 수에 도달하면 배리어의 단계가 전환되어 스레드가 진행할 수 있다. [88]

TMA 배리어 단계 전환

tma_phase ^= 1을 통해 각 스레드의 tma_phase를 수동으로 전환하여 다음 반복에서 TMA가 해당 반복의 타일을 공유 메모리로 전송할 때까지 스레드가 차단되도록 한다. [90]

TMA 배리어 단계 수동 전환

코어 행렬 (Core Matrices) [101]

텐서 코어는 요소를 이해하는 것이 아니라 행렬을 이해한다. [104]

텐서 코어는 행렬을 8x16B 타일 그룹으로만 볼 수 있으며, 이는 8x8 요소의 코어 행렬에 해당한다. [105]

텐서 코어 행렬

tcgen05.mma는 레이아웃(행 우선 또는 열 우선) 및 스위즐링 모드에 따라 공유 메모리에서 8가지 정식 코어 행렬 레이아웃을 지원한다. [107]

현재 커널은 A와 B 모두 K-major를 사용하며, 이는 코어 행렬의 각 열(8x1)이 공유 메모리에서 연속적이어야 하는 레이아웃에 해당한다. [108]

TMA는 한 번에 8개의 코어 행렬 열을 복사하며, 이 작업은 타일의 64개 요소 너비를 채우기 위해 8번 반복된다. [109]

8개의 코어 행렬 열을 8번 복사

MMA 명령어 발행 [112]

Blackwell 5세대 텐서 코어의 개선 사항 [113]

단일 SM에 대한 tcgen05.mma의 최대 모양이 Hopper의 64x256x16에서 128x256x16으로 증가하여 처리량이 거의 두 배가 되었다. [114]

최대 256x256x16의 2SM tcgen05.mma가 도입되었다. [115]

텐서 메모리(Tensor Memory)라는 새로운 종류의 메모리를 도입하여 레지스터 압력을 줄였다. [116]

텐서 메모리(TMEM) [117]

TMEM은 tcgen05 MMA 명령어의 입력 또는 출력을 저장하는 데 특화된 256K 온칩 메모리 공간이다. [120]

총 65,536개의 요소(128개 레인, 512개 열)가 있으며, 각 요소는 4바이트로 총 256KB이다. [121]

할당은 열 단위로 이루어지며, 최소 할당 단위는 32개 열(16KB)이다. [123]

텐서 메모리(TMEM)

이전 NVIDIA 세대는 행렬 곱셈 결과를 저장하기 위해 범용 레지스터를 사용해야 했지만, 이는 레지스터 공간 부족과 MMA가 랩 수준 작업일 때 발생하는 대기 문제 등의 단점이 있었다. [124]

TMEM은 ALU가 사용하는 레지스터와 텐서 코어가 필요로 하는 레지스터 간의 문제를 분리하여 이러한 문제를 해결한다. [127]

tcgen05.mma 및 텐서 메모리 사용 [128]

tcgen05.mma 명령어는 비동기적으로 실행되며, TMA 작업과 유사하게 단일 스레드에 의해 시작되고 메모리 배리어에 의해 보호된다. [131]

mma_arrive는 tcgen05.commit을 래핑하여 메모리 배리어에 신호를 보내고 MMA 명령어와 즉시 연결한다. [132]

num_k_mmas MMA 명령어를 발행하는 이유는 BMxBNxBK 타일링만으로는 실제 하드웨어 명령어의 크기 제한을 충족할 수 없기 때문이다. [133]

tcgen05.mma 명령어는 K 차원이 32B(BF16/FP16의 경우 16개 요소)여야 하므로, BK=64인 경우 MMA는 4번의 반복이 필요하다. [135]

BK=64일 때 MMA에 4번의 반복이 필요함

MMA 함수는 tcgen05.mma 명령어를 호출하여 tmem_addr 주소의 텐서 메모리에 결과를 누적한다. [140]

텐서 메모리 할당은 단일 워프에 의해 발행되어야 하며, 할당된 TMEM 주소를 얻기 위해 공유 메모리를 거쳐야 한다. [144]

디스크립터 (Descriptors) [147]

tcgen05.mma의 입력 및 구성은 디스크립터에 인코딩된다. [147]

명령어 디스크립터 (idesc): 명령어 모양, 데이터 유형, 행렬 레이아웃 등을 인코딩하며, 계산 전반에 걸쳐 일정하게 유지되므로 반복 중에는 변경되지 않는다. [148]

공유 메모리 디스크립터 (adesc 및 bdesc): 행렬 A와 B의 공유 메모리 레이아웃 및 접근 패턴에 대한 정보를 인코딩하며, 행렬의 다른 K-슬라이스를 이동함에 따라 공유 메모리 주소가 변경되므로 num_k_mma 반복에 걸쳐 변경된다. [149]

MMA 배리어 [151]

MMA가 완료되면 MMA 배리어에 도착하며, 이는 TMA 배리어와 동일하게 작동하여 MMA 작업이 완료될 때까지 모든 스레드를 차단한다. [151]

이를 통해 현재 타일에 대한 모든 MMA 작업이 완료될 때까지 어떤 스레드도 TMA 작업을 시작하는 다음 반복으로 진행하지 않는다. [153]

TMEM → 레지스터 전송 [154]

텐서 메모리에서 데이터를 이동하는 유일한 방법은 데이터를 먼저 레지스터로 이동하는 것이다. [159]

이는 tcgen05_ld 작업을 통해 수행할 수 있다. [159]

텐서 메모리에 데이터가 저장되는 방식을 보면, 텐서 메모리는 64x64 C_tile을 보유한다. [163]

NVIDIA의 Parallel Thread Execution ISA 버전 9.0의 그림 215에 따르면 레이아웃 구성 및 접근 패턴은 다음과 같다. [164]

텐서 메모리의 레이아웃 구성 및 접근 패턴

메모리에 접근하기 위해, 시작된 블록의 각 워프는 16개 레인을 읽어야 하며, 전체 워프 그룹(4개 워프)은 64개 레인을 읽는다. [166]

datapaths 및 bits 매개변수는 이 로드 패턴을 지정하며, tcgen05_ld는 각 레인 세트를 로드하기 위해 내부적으로 tcgen05.ld.16x256b 명령어를 디스패치한다. [167]

이는 각 반복에서 스레드가 256비트, 즉 8개 요소(FP32로 결과를 누적하여 정확도를 유지하므로 각 요소는 텐서 메모리에 4바이트 공간에 저장됨)를 텐서 메모리의 열을 가로질러 BN/8회 반복하여 로드한다는 의미이다. [168]

BN//8 = 8번 반복하면 각 스레드는 레지스터 배열에 타일의 32개 요소를 보유하게 된다. [170]

이 작업이 완료되면 모든 데이터가 레지스터로 성공적으로 전송되었음을 알 수 있으며, 할당된 텐서 메모리를 해제한다. [171]

레지스터 → GMEM 전송 [174]

레지스터에서 전역 메모리로 데이터를 이동하는 write_c_tile_to_global_memory 단계가 필요하다. [178]

행렬은 4096x4096이며, 각 블록은 이 출력의 64x64 타일을 담당한다. [180]

block_idx.y = 2, block_idx.x = 2인 경우, 이는 3행 3열의 세 번째 타일을 출력하는 것을 담당한다. [181]

그런 다음 각 워프에 대해 추가로 타일링한다. [186]

워프 0의 타일에 초점을 맞추면, c_gmem_warp_tile은 첫 번째 16행 64열(16xBN)을 나타내며, 누적 값이 저장된 워프 0에 이 16x64 타일을 매핑해야 한다. [190]

tcgen05.ld.16x256 PTX 명령어에 대한 요소의 레인(스레드) 매핑은 다음과 같다. [192]

tcgen05.ld.16x256 PTX 명령어에 대한 요소의 스레드 매핑

Mojo는 vectorize 및 distribute 함수를 제공하여 각 스레드에 필요한 레이아웃을 제공한다. [198]

vectorize[1, 2]()는 각 스레드가 2개의 연속적인 요소를 저장하므로 16x64 타일을 16x32의 2값 벡터 타일로 볼 수 있도록 한다. [201]

16x64 타일을 16x32의 2값 벡터 타일로 볼 수 있음

distribute[Layout.row_major(8, 4)]는 16x32 벡터를 8x4 스레드에 반복적으로 분배한다. [203]

예를 들어, 스레드 0은 모든 서브 행렬에서 (0, 0) 위치의 벡터를 얻고, 스레드 6은 (1, 3) 위치의 벡터를 얻는다. [204]

각 서브 행렬은 NVIDIA의 그림 185 레이아웃과 동일하게 매핑된다. [206]

서브 행렬 매핑

이는 2x8 서브 행렬을 생성하며, 각 서브 행렬은 8x4의 2값 벡터를 저장한다. [208]

distribute는 각 스레드에 필요한 포켓 뷰를 제공한다. [209]

distribute 연산을 NVIDIA의 매핑과 비교

이 매핑을 통해 전역 메모리로의 출력은 루프를 통해 간단하게 수행된다. [211]

num_vecs_n, num_vecs_m=(8,2)를 예로 들면, 각 워프에 걸쳐 한 번에 하나의 서브 행렬을 출력하며, 먼저 M 차원을 따라 두 번, 그 다음 N 차원을 따라 여덟 번 출력한다. [214]

CTA 수준에서 CTA의 타일을 전역 메모리의 C 행렬에 매핑할 수 있다. [220]

설정 코드는 동적 공유 메모리 할당(external_memory)에서 기본 주소를 가져온 다음, 아래 그림과 같이 오프셋을 증가시킨다. [227]

## 2. 커널 3: 스위즐링을 통한 뱅크 충돌 해결 [232]

스위즐링은 공유 메모리 뱅크 충돌을 해결하여 성능을 크게 향상시키는 기술이다.

### 2.1. 공유 메모리 뱅크 및 뱅크 충돌 [244]

공유 메모리 뱅크 [244]

공유 메모리는 32개의 연속적인 4B 너비 뱅크로 구성된다. [245]

32개의 연속적인 4B 너비 뱅크로 구성된 공유 메모리 레이아웃

각 뱅크는 사이클당 하나의 요청을 처리할 수 있으며, 여러 스레드가 공유 메모리 내의 다른 뱅크에 접근하는 경우 동시에 처리될 수 있다. [247]

동일한 사이클에서 다른 뱅크를 서비스하는 여러 스레드

뱅크 충돌 (Bank Conflicts) [250]

두 요청이 동일한 뱅크에 접근하는 경우, 예를 들어 두 스레드가 다른 주소로 뱅크 0에 접근하려 하면, 이는 2사이클이 소요된다. [251]

두 스레드가 동일한 뱅크에 접근하여 뱅크 충돌 발생

워프 내의 스레드가 동일한 뱅크에 매핑된 다른 주소에 접근하려고 하면, 하드웨어는 실행을 여러 사이클로 분할해야 한다. [259]

이러한 실행 지연을 뱅크 충돌이라고 하며, 이는 성능에 좋지 않다. [260]

128B 정식 레이아웃(타일이 BMxBK이고 BK=64)에 이를 적용하면, 첫 번째 코어 행렬의 8개 행이 모두 동일한 뱅크 0-3에 매핑된다. [261]

8방향 뱅크 충돌

이는 코어 행렬당 8방향 뱅크 충돌을 발생시키고 각 행에 대한 쓰기가 순차적으로 발생하게 한다. [263]

뱅크 충돌로 인한 지연 없이 필요한 데이터를 읽는 기술이 필요하다. [265]

### 2.2. 스위즐링 (Swizzling) [266]

스위즐링의 개념 [267]

스위즐링은 뱅크 충돌을 해결하는 기술로, 비트wise XOR(^)을 사용하여 인덱스를 교환하여 데이터가 동일한 뱅크에 상주하지 않도록 한다. [268]

예를 들어, 16개 뱅크가 있다고 가정할 때, 각 행에 대해 다른 XOR 패턴을 적용하여 동일한 인덱스(1-16)의 요소가 다른 뱅크에 매핑되도록 한다. [269]

이는 스레드가 동일한 인덱스로 다른 행의 요소에 접근할 때 뱅크 충돌이 발생하지 않도록 한다. [278]

128바이트 스위즐링 [280]

<3, 4, 3>의 128B 스위즐 패턴은 다음과 같다. [281]

첫 번째 3은 코어 행렬의 행 수인 2^3 = 8에 해당한다. [282]

4는 코어 행렬의 너비인 2^4 = 16B(8개 요소 x 2B)에 매핑된다. [283]

마지막 3은 2^3 = 8로, 8개의 16B 청크가 전체 32개 뱅크(128B)에 걸쳐 있음을 의미한다. [284]

이러한 값을 통해 스위즐 함수는 코어 행렬의 뱅크 충돌을 해결하기 위한 올바른 XOR 패턴을 제공한다. [285]

이 패턴은 Mojo로 작성될 수 있으며 일반적인 패턴에 대해 일반화될 수 있다. [286]

시각적으로는 다음과 같다. [287]

128바이트 스위즐링 패턴

각 8개 요소(16B = 8*2B)는 XOR 피연산자에서 3개의 LSB를 0으로 설정하여 그룹화된다. [289]

XOR 계산은 이전에 보여준 것처럼 각 행 내의 그룹을 교환한다. [290]

결과적으로 모든 8개 요소는 다른 뱅크에 존재한다. [291]

128바이트 스위즐링된 공유 메모리 타일

스위즐링 없이 인접한 두 코어 행렬이 32개 뱅크에 어떻게 스위즐링되는지 살펴보면 다음과 같다. [294]

스위즐링 없는 메모리 접근

스위즐링을 적용하면 다음과 같이 된다. [296]

스위즐링을 사용한 메모리 접근

코어 행렬의 너비가 16바이트이므로, 동일한 코어 행렬의 두 요소가 동일한 뱅크에 들어가지 않아 128바이트 스위즐링으로 뱅크 충돌이 발생하지 않는다. [298]

스위즐링은 매우 유용하며, 모든 고성능 GPU 커널에서 사용된다. [299]

### 2.3. 업데이트된 커널 및 성능 [300]

업데이트된 커널 [301]

스위즐링 지원은 라이브러리의 레이아웃 텐서와 명령어 자체를 통해 제공되므로 커널의 코드 변경은 최소화된다. [301]

TMA와 tcgen05.mma에 어떤 스위즐 모드를 채택할지 알려주는 것만이 필요한 코드 변경 사항이다. [302]

LayoutTensor는 스위즐링을 이해하므로, 스위즐 작업의 세부 사항을 레이아웃 텐서 API 뒤에 숨기고 코드를 변경하지 않고 유지할 수 있다. [305]

성능 [306]

이러한 최적화를 통해 B200에서 288.3 TFLOPs를 달성하며, 이는 87%의 성능 향상이다. [307]

공유 메모리 뱅크 충돌의 영향으로 성능이 절반으로 줄어들었지만, 뱅크 충돌을 해결함으로써 cuBLAS 성능의 16.4%에 도달하며 격차를 빠르게 줄이고 있다. [308]

## 3. 커널 4: 공유 메모리에 출력 패킹 및 TMA 저장 사용 [311]

### 3.1. 공유 메모리에 출력 패킹 [316]

TMA 저장을 위한 출력 데이터 패킹 [317]

TMA 저장을 활용하려면 출력 데이터를 공유 메모리에 패킹해야 한다. [317]

이는 텐서 메모리에서 출력을 레지스터로 로드하기 전에 레지스터를 공유 메모리로 복사하여 수행한다. [318]

전역 메모리의 출력이 BF16이므로, 레지스터를 공유 메모리로 복사하기 전에 FP32에서 BF16으로 캐스팅해야 한다. [319]

출력 결과는 특정 레이아웃(16x256비트 로드)으로 레지스터에 의해 조각화되므로, 레지스터를 공유 메모리로 복사할 때 이를 처리해야 한다. [320]

NVIDIA는 이 단계를 용이하게 하기 위해 stmatrix 명령어를 제공한다. [321]

stmatrix 명령어는 정확히 16x256비트 레이아웃으로 분산된 8x16B 코어 행렬을 공유 메모리에 저장하며, 사용자가 각 행에 대한 공유 메모리 주소를 지정할 수 있는 유연성을 제공한다. [322]

TMEM에서 로드된 데이터는 FP32이고, 공유 메모리에 저장할 때 BF16으로 캐스팅되므로 256비트(32B)와 행당 16B 사이에 불일치가 발생한다. [323]

stmatrix 명령어는 명령어당 최대 4개의 코어 행렬(2x2)을 저장한다. [325]

결과적으로 16x64(BN=64) 워프 타일의 패킹은 stmatrix의 4번의 반복이 필요하다. [326]

stmatrix의 4번의 반복

TMA 저장 (TMA Store) [329]

데이터가 공유 메모리에 스위즐링되고 패킹되면, TMA 저장 작업을 시작하여 데이터를 전역 메모리로 비동기적으로 복사할 수 있다. [330]

TMA가 비동기 저장을 발행하기 전에, fence_async_view_proxy를 통해 메모리를 펜스(fence)하여 공유 메모리의 이전 패킹이 TMA 저장에 표시되도록 해야 한다. [331]

TMA 저장을 발행한 후, commit_group()을 사용하여 저장을 커밋한다. [335]

wait_group[N]()은 N개의 저장 그룹만 비행 중일 때까지 기다린다. [337]

예를 들어, 3개의 커밋된 그룹이 있는 경우 wait_group[2]()는 첫 번째 그룹이 완료되고 마지막 두 그룹이 비행 중임을 보장한다. [338]

위 코드에서 wait_group[2]()는 모든 TMA 저장이 완료될 때까지 기다린다. [339]

커밋 그룹별로 기다리는 기능은 파이프라인을 구축하고 나중에 최적화에서 다른 작업을 효율적으로 오버랩할 수 있게 한다. [340]

TMA 저장과 TMA 로드 사이에는 또 다른 차이점이 있는데, 여러 스레드가 TMA 저장을 병렬로 발행할 수 있다는 점이다. [341]

TMA_BN은 스위즐링 모드에 따라 달라진다(예: 128B 스위즐링 및 BF16의 경우 TMA_BN=64). [344]

타일 차원 BN이 더 크면, 차원을 TMA_BN으로 나누고 여러 TMA 저장을 시작해야 한다. [346]

예를 들어, BN=128은 아래 그림과 같이 두 개의 저장에 매핑되며, 병렬 처리를 최대화하기 위해 두 스레드에 의해 시작된다. [347]

병렬 처리를 최대화하기 위해 두 스레드로 두 TMA 저장 매핑
